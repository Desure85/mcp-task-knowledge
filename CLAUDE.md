# CLAUDE.md — правила для Claude Code в этом репозитории

@AGENTS.md

Проектный файл **дополняет** глобальный `~/.claude/CLAUDE.md`, а не заменяет его: Claude Code читает оба.

## Обязательно для web-ui

Перед любой правкой `web-ui/` прочитай `DESIGN.md` в корне — это единый стилевой гайд для людей и всех
агентов: токены, две оси темы, каталог примитивов, контракт страницы и состояний, запреты и процесс.
Визуальные решения владельца фиксируются там, а не в переписке.

- Собирай интерфейс из `web-ui/components/ui` и семантических токенов. Зашитые цвета, `window.confirm`,
  нативные `button`/`input`/`select`/`textarea` вне `components/ui` и свои модалки без `Dialog` запрещены
  (`DESIGN.md` §7).
- Новый примитив — сначала в `web-ui/components/ui` и на странице `/design` во всех шести вариантах темы,
  потом страница. Сгенерированные блоки `DESIGN.md` обновляет `npm run design:doc`.
- Стражи: `web-ui/lib/design-guards.test.ts`, `web-ui/lib/no-hardcoded-colors.test.ts`,
  `web-ui/lib/design-doc.test.ts`. Запись в allowlist — только с причиной и задачей-владельцем.

## Приоритет правил

Правила проекта (`AGENTS.md`, `DESIGN.md`) выше внешних скиллов и плагинов. Скилл `frontend-design` можно
использовать как дополнение к `DESIGN.md` — для идей и полировки, — но он не отменяет токены, примитивы,
плотность и контракт страницы.
