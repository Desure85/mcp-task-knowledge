An index failure is logged and sets `meta.dirty` instead of failing the mutation. The index rebuilds from files in batches of 2000 (after file-level migrations, after a backup restore, or on demand) and a 100k-task + 100k-doc corpus builds in ~34 s with a flat heap. ### Fixed

- Bridge schema fidelity (MU-09): the stdio bridge no longer rebuilds JSON Schema into Zod. `ProxyPassthrough` forwards `tools/list`, `tools/call`, `resources/list`, `resources/templates/list`, `resources/read`, `prompts/list` and `prompts/get` to the core and returns its result unchanged, so nested `required`, `enum`, `minimum`/`maximum`, `description`, `default`, `format` and `pattern` reach clients exactly as the core publishes them; the bridge advertises the core's `listChanged` flags and relays `notifications/*list_changed` downstream. Measured on a private core and bridge: 128/128 tools with zero schema differences (previously 13 `required` paths were wrong and every constraint counter was zero), `tasks_bulk_create` with a single `title` succeeds through the bridge, an invalid `priority` returns the core's `Invalid enum value` text, and `resources/templates/list` is 14/14 instead of 0. Tests: `tests/proxy-schema-parity.test.ts` (8) plus the existing `tests/thin-proxy-shim.test.ts` (12).
- Test-infra leak (Q-017, P-20261106-2): suites could leave `node dist/index.js` processes behind, and the survivors held the fixed test ports (4002/4003) so the next run failed (`chaos-shutdown` SIGINT test 6/6, then the pre-push hook blocked pushes). Client helpers now close the transport when `client.connect()` throws (`__tests__/{project_purge_filters,resources_and_tools_resources,search_tools_lazy_init}`, the e2e harness, `mcp-prompts`, `elicitation`), every spawn goes through `tests/support/server-process.ts` (`getFreePort`, `spawnTrackedServer`, `terminateServer` with SIGTERM→SIGKILL escalation and a live-child registry), the fixed port counters (4000/4400/4600/4700/4800/4950/4970/5050) are replaced with OS-assigned ports, `waitForExit` arms its listener before signalling, and a vitest global teardown (`tests/support/orphan-guard.ts`) fails the run listing the PID and ports of any server that survived it (a baseline snapshot keeps a manually started dev server from false-positiving). Verified: mutation (one unclosed spawn) turns the guard red with `pid=... ports=...`; three full runs and `sh .husky/pre-push` leave 0 orphans; `e2e:full` 122 green; the original leak condition (100 busy loops, `__tests__` connect timeouts) no longer leaves a single process

- `/devcycle` single-writer lock: two ticks can no longer both win. `fs.writeFile(..., {flag:'wx'})` created `lock.json` empty and filled it afterwards, so a contender that hit that window read a lock with no owner, called it stale, deleted the live one and got `ok: true` too — measured 7 double-acquire rounds out of 70 under CPU pressure (up to 5 processes believing they held the lock). The lock is now created atomically with its content (private temp file + `fs.link`), a fresh unparsable lock counts as held for a 5 s grace instead of stale, reclaim runs under an exclusive `lock.json.reclaim` guard so two reclaimers cannot both delete and create, and `release()` deletes only a lock that still carries its own owner token. A cross-process regression test reproduces the "file exists, content missing" window deterministically (red on the previous code, green 30 runs in a row)
- CI base images: `docker-build-base` no longer skips proxy toolchain builds blindly on push. The job logs in to GHCR and verifies the tag with `docker buildx imagetools inspect` first: a published tag is still skipped (green, no build), a missing tag (`not found`/404) is built and published in that run, and any other failure (auth, network, 5xx) fails the job with an `::error::` naming the cause and pointing at `workflow_dispatch`. This closes the trap where `mcp-node:24-bullseye` was never published and six base jobs failed with "not found" on every push (runs 42070606130 → 42083930937)
- Тесты и pre-push: убраны три источника ложных падений. `tests/devcycle-state.test.ts` больше не зависит от скорости старта двух дочерних процессов: второй тик запускается только после того, как на диске появился читаемый `lock.json`, а окно удержания поднято до 8 с; `tests/search-perf.test.ts` меряет тёплую медиану и проверяет стоимость на документ (относительная метрика не зависит от загрузки машины), абсолютные потолки 4 с / 12 с остаются сетью для 10–20-кратной деградации; e2e-наборы через `tests/support/dist-guard.ts` падают сразу с сообщением «dist устарел» (и собирают `dist` сами, если его нет), а `.husky/pre-push` вызывает `npm run build` перед vitest — иначе устаревший `dist` давал 47 красных e2e-файлов.
- Relay: a taken LAN relay port no longer crashes the server. `RelayManager.start()` logs a warning and disables the optional relay (`relay_status` reports `enabled: false`) instead of leaving an unhandled `EADDRINUSE` that killed the process; `RELAY_PORT` selects the port (default `41235`, documented in the configuration reference) and the relay e2e tests take OS-assigned ports instead of the fixed one. ### Security

- P-20261105-1 dependencies: `npm audit --omit=dev` on 38a774d reported 14 findings (2 critical, 9 high, 3 moderate); `npm audit fix` without `--force` and with no major upgrades closes 12 of them — markdown-it 14.3.3 with linkify-it 5.0.2 (ReDoS and quadratic-scan DoS), js-yaml 3.15.2 (prototype pollution and quadratic merge-key DoS), picomatch 2.3.2 (ReDoS), protobufjs 7.6.6 with @protobufjs/utf8 1.1.2 (code injection and prototype injection), ajv 8.20.0/6.15.0 with fast-uri 3.1.9 (ReDoS and host confusion), and the express chain (body-parser 2.4.0, qs 6.17.1, proxy-addr 2.0.8, path-to-regexp 8.4.2). Two high findings remain by design: `zod` (fix requires the zod 4 major, owner decision P-20261105-2) and `@modelcontextprotocol/sdk` (fix ships only in 1.32.x, which does not type-check against zod 3 — 199 `registerTool` call sites fail with TS2589 and tsc runs out of memory; see TR-39)
- P-20261105-2a `@modelcontextprotocol/sdk` 1.17.4 → 1.32.2 (`^1.32.0`): closes every SDK advisory — cross-client response leak via shared server/transport reuse (GHSA-345p-7cg4-v4c7), missing DNS-rebinding protection, UriTemplate ReDoS, an OAuth client sending credentials to an authorization server chosen by the MCP server, unbounded request bodies and JSON-RPC batch length, bearer tokens issued for another service, and cross-origin redirects that re-sent headers and bodies. Remaining finding: `zod` < 4.6.6 (major upgrade, P-20261105-2b)
- P-20261105-2b `zod` 3.25.76 → 4.6.7 (`^4.6.7`): the last high finding from `npm audit --omit=dev` is closed. All imports stay on `zod/v3` — the v3 API compatibility layer shipped inside zod 4 — so no schema is rewritten and the tool contract is unchanged: the live `tools/list` payload (126 tools, names, descriptions, inputSchema, annotations) is byte-identical before and after, and so are the validation messages for type, required-field, min, enum and max violations. `npm ls zod` shows one copy in the production tree and only `zod` changes in the lock.
