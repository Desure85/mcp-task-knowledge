UX/UI audit — October 2026

audit project mcp updated 2026-10-30 30 findings owner dm

Verdict

The admin is usable for one technical user and not yet usable for a team. Two P0 blockers sit in Knowledge, and a P1 layer of state, identity and accessibility problems runs through every screen. Nothing found here is architectural: the server is sound, the UI shell is not.

This document records what was measured, what was inferred, and the smallest set of changes that would clear both P0s without a rewrite.

Findings

The audit records 30 findings across four screens. Six are listed here; twelve more need a decision this month.

  • P0Clicking a document in Knowledge crashes to a white screen. The document id is read before the route resolves, so the pane renders from undefined (T-2041).
  • P0Search inside Knowledge crashes on a query with no match, where the result array is empty and the same component dereferences its first item (T-2047).
  • P1Error and empty states are mixed: eight screens draw the same blank pane for “no results” and “request failed”, so a user cannot tell a retry from a dead end.
  • P1The realtime badge never leaves “Connecting…” and is indistinguishable from a working connection (T-2029).
  • P113 form fields have no visible label; the label text exists only as a placeholder and disappears on focus.
  • P16 text styles fall under 4.5:1 contrast, all of them in secondary metadata that carries meaning on its own.

Accessibility measurements

Measurements were taken with the browser accessibility tree, not from the design file. Four defects recur:

  • 13 inputs without a programmatic or visible label.
  • 2 focus rings clipped by the sticky toolbar as the page scrolls.
  • 6 text styles under 4.5:1, measured against the surface they sit on.
  • No skip link on any of the four screens, so keyboard users traverse the full navigation on every route.

Tasks vs YouTrack

The 30 findings map onto three tracked tasks: UI-13 covers the shell, UI-22 the knowledge pane, F-29 the state contract. Both P0s are already filed as T-2041 and T-2047. Four findings have no ticket yet and are listed in the appendix of the source file.

Proposals

The cheapest fixes are not visual, and they are ordered by how much they remove:

  • A state contract. Every data view declares loading, empty, error and ready, and the shell owns the rendering. This removes the largest single class of defects.
  • A shared token set. One scale for colour, type, spacing and rules, referenced by name. It removes the six failing contrasts and the drift between screens.
  • One page shell. Top bar, navigation, page header and focus order written once, so a fix lands on every screen at the same time.
