UX/UI audit — October 2026

type audit project mcp updated 2026-10-30 30 findings owner dm ui ux accessibility

Verdict

The admin is usable for one technical user who already knows the data model. It is not yet usable for a team: two P0 blockers sit in Knowledge, and a P1 layer of state, identity and accessibility problems runs through every screen. Nothing here needs a redesign; it needs a contract.

Findings

Two defects stop daily work today, and both are in the Knowledge screen. Both reproduce on the production build with a cold cache.

  • P0 — clicking a document crashes the pane. Opening any row from the list blanks the canvas. No error is shown and there is no way back except a reload.
  • P0 — search inside Knowledge crashes on a miss. A query with zero results throws instead of rendering the empty state, so a typo ends the session.

Underneath those, a layer of P1 problems makes the UI unpredictable even when nothing throws.

  • P1 — error and empty states are mixed. One slot renders “nothing found” and “request failed” with the same copy and the same weight.
  • P1 — the realtime badge never leaves “Connecting…”. The WS handshake sends the JWT in the query string, the server rejects it, and the client retries forever.
  • P1 — 13 unlabelled fields. Board filters, the prompts editor and memory search have no programmatic label, only a placeholder.
  • P1 — 6 text styles under 4.5:1. Muted meta text on tinted rows fails contrast in both themes.

Accessibility measurements

Measured on the production build at 1440×900 and 390×844. Contrast failures are all in the 11 to 12 px meta layer, between 3.1:1 and 4.2:1. Tab order reaches every control, but the focus ring is drawn under the board’s sticky header on 4 of 9 columns, which reads as “focus lost”. The skip link exists on 2 of 7 screens. No screen scrolls horizontally at 390 px once the board is given its own scroller.

Tasks vs YouTrack

The audit produced 30 findings. 22 are already tracked as UI-13, UI-22 and F-29. The remaining 8 are documented here with reproduction steps because they cross three modules and no single ticket owns them, which is exactly the failure mode this screen is meant to surface.

Proposals

Three changes remove most of the P1 layer without touching the visual language.

  • One state contract. Loading, empty, error and offline are four defined renderings per data block, written once and reused.
  • One token set. Board, knowledge and prompts read the same colour and type tokens, so a contrast fix lands everywhere at once.
  • One page shell. The same header, the same focus behaviour and the same skip link on every screen, instead of seven near-copies.
