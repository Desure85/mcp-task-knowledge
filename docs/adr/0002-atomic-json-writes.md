# ADR-002: Atomic JSON writes — tmp + rename

- **Статус:** Accepted (2026-08-29, Q-013)
- **Область:** src/fs.ts (writeJson)

## Контекст

Все данные сервера — файлы (tasks/knowledge). Прямая запись через
`fs.writeFile` при ENOSPC или крэше посреди записи оставляет повреждённый
JSON — потеря данных.

## Решение

`writeJson` пишет во временный файл (`<file>.<pid>.<ts>.tmp`), затем
`fs.rename()` (атомарна на POSIX и Windows). При ошибке tmp удаляется
в catch — не остаётся мусора.

## Последствия

- Плюс: файл либо старый, либо новый — никогда частичный; ENOSPC-safe
- Плюс: тесты chaos-disk-full (Q-013) подтверждают инвариант
- Минус: двойная запись на диск (tmp + rename) — незначительно
