## Known baseline quirks (not failures of retrieval)

LongMemEval 3/5 reproduces the quirk already noted in the NEXT2-007 smoke run
(BM25, no stemming). Both misses are **suite keyword-design artifacts**, and the
correct document WAS retrieved top-1 in both cases (Recall@5 = 100%):

- `lme-001` (33%): expected keywords `['react', 'preferred', 'session']` —
  source text says *"I **prefer** React over Vue…"* (`prefer` ≠ `preferred`
  without stemming) and the word `session` never appears in the source text.
  Only `react` can match. Retrieval correct, scoring penalized.
- `lme-002` (33%): expected keywords `['postgresql', 'database', 'uses']` —
  source text says *"I **use** PostgreSQL…"* (`use` ≠ `uses`) and `database`
  never appears. Same story.

No timeouts, no hangs, no errors in any suite.

## Interpretation

- BM25-only retrieval answers 18/20 harness questions with 100% Recall@5
  across all suites; per-question search latency is single-digit ms.
- The 2 misses measure keyword stemming/suite design, not memory quality —
  fixing them by re-tuning BM25 or editing keywords would inflate the baseline
  and is explicitly out of scope (see recommendations).

## Recommendations (future tasks, NOT done here)

1. Add optional stemming to the BM25 path and re-run to quantify the delta
   (expect LongMemEval → 5/5) — separate task, needs its own BACKLOG item.
2. Consider embedding-mode (`onnx-cpu`) runs for a BM25-vs-vector comparison
   matrix once the ONNX model is available in the sandbox.
3. Expand suites beyond 5 questions each before claiming superiority over
   Mem0/Zep/Cognee — current harness proves plumbing, not leadership.
