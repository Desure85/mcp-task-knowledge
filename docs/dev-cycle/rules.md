# Правила цикла: контролёр и исполнитель

Правила общие для всех поручений цикла. Они разделяют две роли: контролёр принимает решения и
работает с удалённым репозиторием, исполнитель меняет код в своём worktree. Всё, что не разрешено
явно, считается запрещённым.

Правила не дублируют `AGENTS.md` и `CONTRIBUTING.md`. Если они расходятся, приоритет у `AGENTS.md`
как источника конвенций проекта.

## Контролёр

### Что разрешено

- Push, открытие PR и merge в `master` за исполнителя, если он сам этого не сделал.
- Merge только при зелёном CI по текущему `headRefOid` и `mergeStateStatus=CLEAN`, по одной PR за
  тик и по одной за раз.
- Разрешение конфликта с `master` обычным merge, без force-push.
- Принимать решения по проработке и приоритетам и фиксировать их файлом в `docs/dev-cycle/decisions/`.
- Отправлять поручения через `OC_BRIDGE` только в `idle` сессию.
- Читать `DEVCYCLE_DB` в режиме только чтение для пульса сессий.
- Создавать worktree от свежего `origin/master` и делать резервные копии вне репозитория.

### Что запрещено без явной просьбы владельца

- Force-push, rebase опубликованных веток.
- Удаление веток и worktree.
- YouTrack и смена статусов задач.
- Любые действия вне этого репозитория.
- Решения по гейтам владельца и по необратимым операциям над данными.
- Остановка или перезапуск дев-стенда и макетов на портах 3000, 3001, 3300.
- Флаг `--force` в мосту: отправлять в занятую сессию нельзя.
- `pkill -f` и `killall`.
- Удаление или правка чужой работы в worktree.

## Исполнитель

### Рабочая среда

- Каждая задача в новом worktree от свежего `origin/master`:
  `git fetch origin`, затем `git worktree add <каталог> -b <ветка> origin/master`. Чужие worktree
  не трогаются, их в системе много.
- Зависимостей в новом worktree нет. Делаются симлинки `node_modules` на общий стенд в корне и в
  `web-ui`. Git симлинки игнорирует.
- Next 16 на симлинках работает только с `next dev --webpack` и `npm run build -- --webpack`.
  Turbopack падает.
- Порты стенда владельца: 3000 для UI, 3001 для MCP-сервера, 3300 для макетов. Их нельзя трогать
  и останавливать. Свои тестовые серверы и UI поднимаются на свободных портах из диапазона,
  выданного в поручении; перед запуском проверяется `ss -ltn`.
- Переменная порта это `MCP_PORT`, а не `PORT`. С `PORT` сервер молча занимает чужой порт.
- Свои процессы останавливаются по PID (`kill <pid>` из `ss -ltnp`), никогда через `pkill -f` и
  `killall`.
- `/tmp` это tmpfs в памяти и очищается при перезагрузке. Большие данные только под своим
  каталогом в `/tmp`, с удалением за собой; следить за `df -h /tmp` и `df -i /tmp`.
- Скриншоты: `playwright-core` ставится во временный каталог, Chrome берётся по пути из
  окружения. Для входа в UI логин и пароль задаются при запуске своего сервера вместе со своим
  `JWT_SECRET`; пароль нигде не коммитится.
- Сервер для проверки запускается с явным окружением:

```
EMBEDDINGS_MODE=none DATA_DIR=/tmp/<свой каталог> MCP_TRANSPORT=http \
MCP_PORT=<свободный порт> MCP_HOST=127.0.0.1 MCP_CORS_ORIGIN='*' \
JWT_SECRET=<свой> MCP_LOGIN_USER=admin MCP_LOGIN_PASSWORD=<свой> node dist/index.js
```

- MCP по HTTP требует `mcp.authenticate` с JWT из `POST /auth/login`. Инструмент называется с
  точкой.

### Качество и стиль

- Только токены дизайн-системы и примитивы `web-ui/components/ui`. Зашитые tailwind-цвета и
  `#hex` запрещены, охранный тест сканирует все страницы и компоненты.
- Контраст WCAG AA проверяется автотестом по всем палитрам и режимам. Новые цвета добавляются
  парами, пороги не ослабляются.
- Вместо `window.confirm` используется `Dialog`. У полей есть подписи, у иконок `aria-label`,
  фокус видимый, клавиатура работает.
- Ответы сервера идут через `ok()` и `err()` со стабильными кодами ошибок и zod-схемами.
- Для каждого поведенческого изменения нужен тест и revert-check: откатить точечно, увидеть
  падение, вернуть.
- Проверки перед отчётом: в корне `npm run build`, `npm run test:types`, `npm run lint`,
  `npm run lint:md`, `npm run backlog:check` и полный `npm test`. В `web-ui`:
  `npx tsc --noEmit`, `npm test`, `npm run build -- --webpack`.
- Если `chaos-shutdown` падает из-за занятого порта 4001 чужим процессом, об этом говорится
  прямо. Обходить проверку нельзя.
- Скриншоты лежат в `docs/ui/screens/<id>/`, каждый не больше 150 КБ, всего не больше примерно
  14 файлов. Их нужно просмотреть глазами и исправить очевидные недостатки.
- В `BACKLOG.md` обновляются статус пункта и ссылки на тесты и скриншоты, пересчитываются таблицы
  этапов и строка «Итого»; `npm run backlog:check` обязан проходить.
- В строках таблиц нельзя использовать вертикальную черту внутри code-фрагментов и пробелы
  внутри code-span: это ломает таблицу и markdownlint.
- `CHANGELOG.md`, `README` и docs правятся по необходимости.
- Новые npm-зависимости и мажорные обновления запрещены.
- Коммиты: `<type>: <описание> [Session-ID]`, логическими шагами, локально.

### Границы

Разрешено: новый worktree, правки по задаче, тесты, локальные коммиты, свои процессы на выданных
портах, временные файлы под своим каталогом в `/tmp` с удалением.

Запрещено: `git push`, `gh pr create`, `gh pr merge`, `gh pr close`, YouTrack, force-операции,
удаление веток и worktree, остановка процессов на 3000, 3001 и 3300, правка общего стенда,
реализация соседних пунктов бэклога, новые зависимости.

Push, PR и merge делает контролёр. Если нужно решение владельца, исполнитель останавливается и
описывает развилку в отчёте.

### Отчёт

В отчёте: worktree, ветка, sha коммитов, список файлов, принятые решения, вывод проверок и
revert-check, пути скриншотов, что не удалось проверить. Отчёт без sha и без вывода проверок не
принимается: контролёр всё равно проверит git и CI сам.

## Секреты

Токены, пароли, приватные URL и содержимое `.env` не попадают в лог, PR, сообщения, документацию
и коммиты. Учётные данные передаются только через окружение процесса. Файлы состояния цикла и
резервные копии не коммитятся.
