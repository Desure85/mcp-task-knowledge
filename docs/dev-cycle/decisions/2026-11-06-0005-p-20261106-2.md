# 2026-11-06 — P-20261106-2: осиротевшие серверы из тестов (Q-017)

Вопрос: после трёх полных `npx vitest run` на ветке оставалось 10 процессов `node dist/index.js`
(ppid 3575, cwd = каталог worktree), после ещё одного успешного прогона (pre-push) — ещё 3; они
держали 4002/4003, обычный `kill` их не брал, помогал только `kill -9`, а
`tests/chaos-shutdown.test.ts › SIGINT triggers graceful shutdown` падал 6/6, пока сироты жили, и
4/4 после их убийства. Хук pre-push из-за этого блокировал push.

Решение:

1. Каждый спавн `dist/index.js` в тестах идёт через `tests/support/server-process.ts`:
   `spawnTrackedServer` (или `trackServer` для транспорта, который спавнит сам), `terminateServer`
   в finally с SIGTERM, ожиданием exit и SIGKILL через grace, `terminateTrackedServers` в afterAll.
   Порты — `getFreePort` от ОС вместо фиксированных счётчиков 4000/4400/4600/4700/4800/4950/4970/5050.
2. Хелперы, которые создают клиент, закрывают транспорт, если `client.connect()` бросил: иначе
   таймаут теста (5 с по умолчанию) во время connect оставлял уже запущенный сервер без владельца.
   Это и был воспроизведённый корень: под 100 busy-loop
   `__tests__/resources_and_tools_resources.test.ts` падал по таймауту в `createClient`, а его
   `dist/index.js` оставался жить (ppid=systemd, DATA_DIR=`/tmp/mcp-resources-test-*`).
3. `waitForExit` в chaos-shutdown навешивает слушатель до отправки сигнала (иначе быстрый exit
   терялся и тест получал null), а каждый тест гасит ребёнка в finally.
4. Глобальный страж `tests/support/orphan-guard.ts` (vitest globalSetup/teardown): сравнивает
   список процессов `dist/index.js` с cwd = корень проекта с baseline, снятым на старте; новый
   процесс → падение прогона с PID и слушающими портами. Baseline исключает ложное срабатывание на
   dev-сервер, запущенный до прогона.

Почему не «убивать всё по имени» и не `pkill -f`: на машине работают чужие MCP-серверы (cwd =
другие каталоги) и стенд владельца; фильтр по cwd обязателен. Почему не оставить SIGTERM без
ожидания: exit теряется, тест продолжает считать процесс живым и не эскалирует в SIGKILL — это
второй корень. Почему не поднять таймаут вместо фикса: таймаут лечит симптом, а осиротевший
процесс отравляет следующий прогон портом.

Проверено:

- ДО: одиночные прогоны всех 28 наборов, стартующих `dist/index.js`, сирот не оставляют — утечка
  требует условия. Воспроизведение: 100 busy-loop, полный `npx vitest run` → 1 сирота
  `dist/index.js` (ppid 3575, cwd worktree, без портов), DATA_DIR=`/tmp/mcp-resources-test-*`,
  тест `__tests__/resources_and_tools_resources.test.ts` упал по таймауту 5 с в `createClient`.
  До фикса chaos-shutdown с занятым 4002 падал на `waitForReady`, а `waitForExit` при уже ушедшем
  процессе отдавал null.
- Мутация стража: временный набор, который спавнит сервер и не гасит, → `orphan-guard` красный:
  `1 orphaned server process(es) … pid=1271445 ppid=3575 ports=44957`, exit code 1; файл удалён,
  сирота убит, повторный прогон зелёный.
- ПОСЛЕ: три полных `npx vitest run` подряд — 271 файл / 3115 тестов зелёные, 0 сирот после
  каждого; `sh .husky/pre-push` — exit 0, 0 сирот; `npm run e2e:full` — 30 файлов / 122 теста,
  0 сирот; полный прогон под 6 busy-loop — 3115 зелёных, 0 сирот; исходное условие (100 busy-loop)
  — 0 сирот (остались только таймаутные падения `__tests__`, `cold-start` TTFB и `mcp-inspector`,
  не связанные с утечкой).
- Проверки: `npm run build`, `npm run test:types`, `npm run lint`, `npm run lint:md`,
  `npm run backlog:check`.

Продуктовый дефект (отдельно, не чинился — правки `src/**` запрещены): stdio-сервер не
завершается, когда умирает родитель. Проверка: родитель спавнит `node dist/index.js` (stdio),
получает `initialize`, затем убивает себя `SIGKILL`; через 2 с сервер жив (ppid=systemd). Причина
по коду: `src/transport/stdio-transport.ts:28-30` подключает SDK-транспорт, но не подписывается на
его `onclose` (SDK вызывает его на `end` stdin —
`node_modules/@modelcontextprotocol/sdk/dist/esm/server/stdio.js:67`), поэтому EOF stdin ничего не
останавливает, а живые таймеры (prune сессий, sweeper задач) держат event loop. Предложение
контролёру: отдельный пункт — на `stdin` end/close вызывать `app.shutdown()` с бюджетом и
`process.exit` после `stop()`.

Не проверено: поведение на не-Linux (страж читает /proc и на других платформах возвращает пустой
список — guard молча зелёный); утечка при SIGKILL самого vitest-воркера (наш `process.once('exit')`
не срабатывает) — такой случай ловит только страж, но процесс остаётся, его нужно добить вручную.

Остаточный риск: тесты `__tests__` под экстремальной перегрузкой (100 busy-loop на 72 ядра) всё ещё
падают по таймауту 5 с — это не утечка, но прогон красный; стабилизация их таймаутов вне Q-017.
Страж не убивает найденные процессы, только сообщает.
