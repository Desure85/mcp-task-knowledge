# 2026-11-10 00:30 — fix: executable-docs больше не падает по 60-секундному бюджету под нагрузкой CI

- **Пункт:** стабильность теста `tests/executable-docs.test.ts` (DX-24), не новый пункт бэклога
- **Ветка / sha:** `fix/executable-docs-timeout`, от `origin/master` `51be937` (PR #337 влит)
- **Причина:** `bulk-smoke` падал на PR #336 и #337 с `AssertionError: code=1` в `executable-docs`;
  перезапуск зелёный. Тест запускает `scripts/executable-docs.mjs` через `execFile` с `timeout:
  60_000`; под контеншеном CI (тесты идут в 4 воркера плюс coverage) скан всех docs занимал больше
  60 секунд, процесс убивался по таймауту, а `execFile` в этом случае не отдаёт exit code — тест
  видел `e.code ?? 1` и репортил голый `code=1`. Это тот же класс проблемы, что TS-01 уже чинил
  для других spawn-тестов.

## Вопрос

Почему один и тот же прогон executable-docs то зелёный, то красный на неизменном коде, и как
сделать бюджет сканирования достаточным, не отключая проверку?

## Решение

Бюджет `execFile` для скана поднят с 60 000 до **180 000 мс**, таймаут `beforeAll` — с 120 000 до
**240 000 мс** (константы `SCAN_TIMEOUT_MS`/`SCAN_HOOK_TIMEOUT_MS` с комментарием). Сам скан не
менялся: те же документы, те же проверки, тот же exit code; увеличивается только окно, в котором
скан обязан уложиться. Это низкорисково: при реальной регрессии скрипт по-прежнему вернёт `code=1`
через свой exit code, а не через убийство по таймауту.

Почему не другие варианты: уменьшать число проверяемых docs — потеря покрытия; распараллеливать
spawn-ы — снова упрёмся в контеншен; повышать worker-лимит — на 4-ядерном runner хуже; оставлять
60 с и перезапускать — это то, что уже три PR подряд стоило ручных перезапусков.

## Проверено

- `npm run build`, `tsc -p tsconfig.test.json --noEmit`, eslint — зелёные.
- Локально сам `executable-docs` на Windows **не является валидным сигналом**: bash-блоки документов
  падают в этой среде (файл входит в известный Windows-baseline, 17 файлов), поэтому решающая
  проверка — `bulk-smoke` на Linux CI; изменение снимает причину `code=1` (таймаут), не ослабляя
  проверки.
- `markdownlint`, `backlog:check` — зелёные.

## Откат

Вернуть `timeout: 60_000` и `}, 120_000);`, удалить константы и комментарий. Правка test-only,
поведение сервера не затрагивается.
