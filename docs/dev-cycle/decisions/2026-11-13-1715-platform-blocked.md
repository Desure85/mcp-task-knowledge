# 2026-11-13 17:15 — оставшиеся пункты платформенно-зависимы

## Вопрос

- **Контекст:** после 419 закрытых пунктов в BACKLOG остались 8 `blocked` + 1 `deferred`.
- **Ответ владельца (2026-11-13):** «тут как будто бы платформенно зависимые штуки… мы пока
  универсальное все пилим».
- **Ветка:** `docs/platform-blocked-boundary`, от `origin/master` `0373ca3`.

## Решение

Ничего из оставшихся 8 не выдаётся за сделанное и не удаляется. Они остаются `blocked`,
потому что каждый требует данных/доступа конкретной платформы владельца, а не универсального
кода:

| Пункт | Что нужно от платформы |
|---|---|
| INT-008 | записываемый токен YouTrack и правила полей/статусов их трекера |
| DX-21 | реальный release pipeline (подпись, checksums, per-platform бинари) |
| DX-27 | доступ к official MCP registry и решение о публикации |
| KE-06 | ALB-репозиторий: `common/messages`, Bitrix24 field defs |
| AA-10 | решение владельца по `agent-drafts`, `/opt/mcp/*`, проекту `alb` |
| CM-03b | рабочая CLI-сессия Claude/OpenCode (сейчас claude зависает, opencode key expired) |
| CM-05 | точные model ids и provider key для слабых моделей |
| CM-06 | зависит от CM-05 |

`TD-003` (legacy-пути знаний) остаётся `deferred`: удаление поддержки без миграции данных
сломает старые DATA_DIR; это не универсальная задача.

## Почему

Не закрываем «дизайном»:

Для DX-21/DX-27/KE-06/INT-008/AA-10 дизайн-документ не заменяет доступ к их данным и
release-инфраструктуре. Для CM-05 нужны модель и ключ, а не текст. Закрытие таких пунктов
создало бы ложное «done».
