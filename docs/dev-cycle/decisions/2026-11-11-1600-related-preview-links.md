# 2026-11-11 16:00 — связанные задачи открываются в том же превью

- **Тип:** прямой запрос владельца, ветка `fix/related-task-preview` от `master` `fcff25c`
- **Затронуто:** `web-ui/components/board/TaskQuickView.tsx`, `web-ui/app/tasks/page.tsx`, e2e

## Вопрос

Почему ссылки на сопутствующие задачи (зависимости, блокируемые, подзадачи) в превью уводят на
страницу задачи, и как оставить пользователя в превью, не теряя контекст доски?

## Решение

- В `TaskQuickView` ссылки на `Depends on`, `Blocks` и `Subtasks` заменены на кнопки, которые
  вызывают `onOpenRelated(id)`.
- `TasksPage.openRelatedTask` загружает полную задачу через `api.tasks.get(..., { includeGraphMetrics: true })`
  и заменяет `viewTask`; Dialog остаётся открытым и просто перерисовывается на новую задачу.
- При смене `task.id` quick view сбрасывает `details`, `tasks`, `children`, `deps` и показывает
  состояние загрузки, чтобы не мигнуть старыми данными.
- Кнопка **Edit** по-прежнему открывает полную страницу в новой вкладке.

## Почему

- Превью — режим чтения; уход на отдельную страницу ломает просмотр цепочки.
- Один Dialog и замена данных сохраняют фокус/Esc/возврат к карточке; отдельный стек диалогов
  не нужен.

## Проверено

- `task-quick-view.spec.ts` — **1/1**: клик по подзадаче внутри диалога не меняет URL (`/tasks`),
  заголовок Dialog становится именем подзадачи; Esc закрывает превью.
- web tsc чистый; сборка production; тест выполнен на SQLite-демо.
- Остальные сценарии быстрого просмотра (зависимости, claim, Edit в новой вкладке) не менялись.

## Ограничения

- История переходов внутри превью не ведётся: вернуться к родительской задаче можно закрытием и
  повторным открытием карточки.
- Каждый переход делает `tasks_get` (и обновляет список для заголовков); на очень больших проектах
  это отдельный запрос, не кешируется.
- `Depends on` и `Subtasks` могут показывать одну и ту же задачу дважды — это разные связи, не
  дубликат.

## Откат

Revert ветки: возвращаются `<Link href="/tasks/<id>">` в трёх блоках и удаляется
`onOpenRelated`/`openRelatedTask`; тест снова не проверяет внутридиалоговый переход.
