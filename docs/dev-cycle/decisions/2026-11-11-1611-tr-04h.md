# 2026-11-11 16:11 — TR-04h: реальный запуск validate-schemas, не зеркало

- **Ветка / sha:** `fix/tr-04h-validate-schemas`, от `origin/master` `bcf8b0d`

## Вопрос

`tests/schema-validation.test.ts` проверял схемы через собственный Ajv и **не запускал**
`scripts/validate-schemas.mjs`. В скрипте была ошибка: `let _obj = null; try { obj = JSON.parse(...) }` —
валидная JSONL-строка падала с `ReferenceError` и попадала в «invalid JSON», то есть любой feedback
файл делал `Validation failed` (rc=2) даже при корректных данных. Юнит-тест этого не видел.

## Решение

- `scripts/validate-schemas.mjs`: объявлена `let obj` вместо `_obj`; валидные строки теперь реально
  валидируются схемой.
- `tests/schema-validation.test.ts` — новый интеграционный кейс:
  - создаёт temp `DATA_DIR` с `prompts/mcp/experiments/events.jsonl`;
  - запускает **настоящий** `node scripts/validate-schemas.mjs`;
  - валидная строка → rc 0 и `Validation passed`;
  - строка с `ts: "not-a-date"` → rc 2 и `Validation failed` (stderr).
- Существующие Ajv-тесты схем оставлены: они проверяют мета-схему и примеры, новый кейс — сам скрипт.

## Почему

- Зеркальная копия логики не может поймать поломку CLI (что и произошло).
- Реальный запуск проверяет пути DATA_DIR, fast-glob, gray-matter, Ajv и коды выхода вместе.
- Temp-директория исключает зависимость от `.data` репозитория и гонки.

## Проверено

- `tests/schema-validation.test.ts` — **15/15** (14 старых + новый).
- **Мутация N1 RED:** вернуть `let _obj` и `obj = JSON.parse` → валидная строка падает, тест краснеет;
  восстановление 15/15.
- `node scripts/validate-schemas.mjs` на репозитории → `Validation passed`, rc 0.

## Ограничения

- Проверяется feedback-JSONL-ветка (там была поломка); tasks/knowledge/prompts-ветки по-прежнему
  покрыты только Ajv-тестами и прогоном на репозитории, где файлов может не быть.
- Temp-фикстура не проверяет legacy-пути `mcp/tasks|knowledge`.
- Тест запускает дочерний node-процесс — на медленном CI добавляет ~0.7 с.

## Откат

Вернуть `_obj`/`obj` и удалить новый describe; прод-поведение скрипта вернётся к ошибочному.
