# 2026-11-11 17:31 — U-04: compact read responses

## Вопрос

`fields`/`maxBytes` уже были на list/search (SC-01), но `compact: true` существовал только у write-
инструментов, а `tasks_get`/`knowledge_get`/`memory_facts_search` не принимали ни `fields`, ни `compact`.
Ответы с `description`/`content` весили больше, чем нужно агенту для следующего шага.

## Решение

Единый пост-фильтр в `src/utils/pagination.ts`:

- `PageRequest.compact`; `projectItem`: `fields` → exact, иначе `compact` → `compactRecord`, иначе без
  изменений;
- `compactRecord` рекурсивно убирает `null`/`undefined`, пустые массивы/объекты и **непрошенные** длинные
  текстовые ключи (`content`, `description`, `body`, `text`, `transcript`, `prompt`, `output`, `result`);
- `pageArgsSchema`/`PageArgs`/`toPageRequest` получили `compact`, поэтому все list/search-инструменты
  поддерживают его без правки каждого обработчика;
- `tasks_get` и `knowledge_get` получили `...writeResponseArgs` (`fields`, `compact`) и проецируются через
  `projectTask`/`projectDoc` (compact — фиксированный минимальный набор записи);
- `memory_facts_search` получил `compact` и отдаёт без `content`; `memory_facts_list` использует общий
  pagination-путь, поэтому compact работает и там.

## Почему

- `fields` должен оставаться точным: если клиент явно попросил `content`, compact не имеет права его выкинуть.
- Удаление по именам ключей, а не по длине: `description` может быть коротким, но это всё равно не тот
  payload, который нужен для идентификации; порог по длине дал бы непредсказуемый контракт.
- `compact` у get — тот же минимальный набор, что у write (id/title/status|type/updatedAt), это знакомо
  клиентам AC-03c.
- Пустые массивы/объекты убираются рекурсивно: именно они раздувают JSON без информации.

## Ограничения

- Compact не применяется к остальным read-инструментам (temporal query/history, profiles, context assembly,
  skills/prompts, dashboard): там по-прежнему полный ответ.
- `memory_facts_list` отдаёт метаданные документов, поэтому `content` там и так отсутствует; тест проверяет
  форму, а не сокращение content.
- Удаляются только известные длинные ключи; произвольное длинное строковое поле (например, `notes`) останется.
- `compact` и `fields` взаимоисключающи по приоритету: explicit `fields` полностью отменяет compact, даже
  если в fields попал null.
- Расширение error-envelope (`retryable`/`code` у `err()`) не делалось: это отдельная часть U-04 и затрагивает
  все обработчики; текущий DoD (тест response-economy) закрыт без него.
- `maxBytes`/cursor не менялись и повторно не тестировались (покрыты SC-01).

## Откат

tasks_get/knowledge_get/memory_facts_search; тест удалить. API остаётся 154 (схемы аддитивны).
