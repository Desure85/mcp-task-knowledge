# 2026-11-03 06:10, пересмотр MU-01, MU-08 и этапа AA (по замечанию владельца)

Ошибка контролёра: при постановке этапа AA не сверила его с этапом MU, хотя владелец спрашивал
именно про «запуск в нескольких режимах с общим ядром», и ответ уже был в бэклоге (MU-01, MU-08).

1. **MU-01** возвращён в pending (предыдущая запись 05:50, п.3 отменена). Почему: lock на
   `DATA_DIR` нужен при любой архитектуре и закрывает вопрос «два ядра на одном каталоге» из
   AA-01. AA-01 берёт его входными данными.
2. **AA-03 тождественен MU-08** (Thin Proxy как stdio-шим). Решение: оставить MU-08, поднять до
   high, перенести в него DoD AA-03; AA-03 удалить с примечанием в описании этапа, нумерацию AA не
   менять. Откат: восстановить строку AA-03 из коммита 7ce4b3a.
3. **AA-02** (несколько транспортов в одном процессе) остаётся: отвечает на явную просьбу
   владельца «и http, и stdio вместе»; пересечения с MU нет (MU-08 это отдельный мост).

Урок для процесса: перед добавлением этапа искать пересечения по смыслу (ключевые слова и
просмотр всех этапов), а не только по ID.
