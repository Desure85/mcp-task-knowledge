# 2026-11-13 08:20 — MU-06: целостность и снимки графа памяти

- **Пункт:** MU-06 (low, был `blocked` на design)
- **Ветка:** `feat/mu-06-temporal-graph-snapshots`, от `origin/master` `bff3329`

## Вопрос

Граф фактов (~750 КБ JSON) переписывается целиком на каждый факт; нет политики атомарности
и снимков при нескольких клиентах; в git его класть нельзя.

## Решение

1. Зафиксировано: запись уже атомарная (`writeFileAtomicSync` = temp + rename); при ошибке
   temp удаляется, старый граф остаётся.
2. Добавлены **снимки**: после успешной записи, не чаще **раза в час**, копия в
   `<storagePath>.snapshots/`, хранится **24** новейших; ошибка снимка не ломает запись;
   параметры `snapshot.{dir,intervalMs,keep}`.
3. Политика нескольких клиентов — **last-write-wins на уровне процесса**: атомарный rename
   защищает от порванного JSON, но не от потери факта, добавленного другим процессом.
   Один писатель на DATA_DIR; кросс-процессного lock/CRDT нет.
4. Документ `docs/features/memory-integrity.md`: запись, снимки, восстановление, лимиты.

## Почему

- Снимки локальные и ограниченные, в git не попадают.
- Не делать append-only/CRDT сейчас: граф мал, а смена формата — отдельный риск.
- Честно записать LWW: иначе «атомарность» прочитают как «не теряет обновления».

## Проверено

- `tests/temporal-graph-snapshots.test.ts` — **3/3**: снимок при interval=0, отсутствие
  лишнего снимка при interval=60s, keep=2 оставляет 2 файла.
- Revert-check: удаление проверки интервала → RED (1 failed); восстановление 3/3.
- `tsc` чистый; существующие memory-тесты не менялись.
- `backlog:check` — **418 done / 0 wip / 0 pending / 9 blocked / 1 deferred**.

## Ограничения

- Кросс-процессные конкурентные записи теряют обновления (LWW); снимки не защищают от этого.
- Нет инструмента/UI восстановления из снимка; нет контрольных сумм.
- Снимок — копия файла, не инкремент; при росте графа займёт место (24 × размер).
- Несколько клиентов в одном процессе безопасны, это не проверялось e2e с двумя процессами.

`{storagePath}`, удалить тест/документ; вернуть MU-06 в `blocked`, сводку 417/10.
