# 2026-11-12 15:30 — MU-03/SC-07: git history design gate

- **Пункты:** MU-03 (high), SC-07 (medium)
- **Ветка / sha:** `docs/mu-03-sc-07-git-adr`, от `origin/master` `13fd979`

## Вопрос

Выбрать транспорт git-истории (`execFile` vs `isomorphic-git`) и пакетную модель коммитов,
чтобы 100k+ файлов не давали O(N) `git add/status` на каждую операцию; зафиксировать
поведение без git, dirty-tree и откат.

## Решение

- `execFile('git', ...)`, без новой зависимости; `isomorphic-git` отклонён (не установлен,
  латентность не измерена, лишний размер).
- Батч: очередь путей (файл `DATA_DIR/.history/queue.jsonl`), flush по 100 путям или 2 с,
  **один коммит**; блокировка репозитория только на flush.
- Dirty tree на старте → `recovered`-коммит; без git — WARN и работа без истории.
- Откат — новый коммит; автор из сессии; `.gitignore` для audit/backups/memory/queue.

## Почему

- Замер: `git add -A && git commit` на 100 файлах — median **170 ms** (min 155.3, max 183.3),
  то есть цена на коммит, а не на файл; per-operation коммит всё равно O(N) и запрещён SC-07.
- Очередь + flush даёт один коммит на N операций и переживает падение через queue.jsonl.
- `execFile` не добавляет зависимость и совпадает с уже используемым git-тулингом.

## Проверено

- Бенчмарк 10 коммитов в temp-репо (100 файлов): median 170 ms.
- `package.json`: `isomorphic-git` отсутствует.
- ADR: `docs/adr/ADR-2026-11-12-git-history.md`; реализация не входила в этот PR.

## Ограничения

- Это design-only: `git-history-batch`/`tests/git-history-batch.test.ts` ещё нет.
- `isomorphic-git` не измерен; решение основано на отсутствии зависимости и замере CLI.
- Пакетная задержка: одиночная правка может попасть в историю не сразу, а после flush.
