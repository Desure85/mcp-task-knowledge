# 2026-11-12 10:20 — AA-02: several transports in one process

- **Пункт:** AA-02 (medium)
- **Ветка / sha:** `feat/aa-02-multi-transport`, от `origin/master` `a59ece7`

## Вопрос

`MCP_TRANSPORT` принимал только одно значение; ADR AA-01 допускает «и http, и stdio к общему ядру».
Нужен список транспортов в одном процессе с обратной совместимостью одиночного значения.

## Решение

- `AppContainer` парсит `MCP_TRANSPORT` как CSV (`stdio,http`), дедуплицирует; одиночное значение
  работает как раньше.
- `transportTypes: string[]` в opts; `adapters` — список; `start()` создаёт/подключает каждый адаптер,
  `stop()` закрывает все в обратном порядке; `getTransports()` отдаёт список, `getTransport()` — первый.
- `ServerContext` остаётся один; `stdio`-адаптер подключает основной `ctx.server`, HTTP-адаптер
  использует его request handlers.
- Сигналы включаются, если есть любой не-stdio транспорт; закрытие stdio-пайпа не завершает процесс
  (SDK закрывает только transport).
- `AuthManager`/SessionManager/Cluster выбираются по первому сетевому транспорту (fail-closed для
  `http/tcp`); `transport.type` в schema допускает CSV-список.

## Почему

- Один контекст/хранилище — второй адаптер не дублирует init и lock.
- Обратная совместимость: `MCP_TRANSPORT=http` даёт ровно один адаптер, старые тесты не меняются.
- CSV в схеме валидируется regex, а не произвольной строкой.

## Проверено

- `tests/multi-transport.test.ts` — **1/1** на реальном процессе: `stdio,http`, HTTP tools/list
  совпадает со stdio tools/list, закрытие stdin не убивает процесс, HTTP продолжает отвечать,
  SIGTERM завершает процесс.
- `npm run build` — чисто; bundle пересобран.
- backlog:check **379/19**.
- Мутация: одиночный `transportType`-адаптер сохранён; список покрыт e2e-тестом.

## Ограничения

- Несколько **сетевых** транспортов на одном порту не поддерживаются (один `MCP_PORT`); сценарий
  `stdio,http` — целевой.
- Windows SIGTERM проверен локально, отдельный `windows-latest` job для этого теста не добавлен.
- Auth/Session/Cluster выбирают первый сетевой транспорт; per-adapter policy нет.
- `ctx.server.connect()` вызывается только stdio; два stdio-транспорта не поддерживаются.

## Откат

Вернуть одиночный `transportType`/`adapter`, удалить `transportTypes`/`adapters`/`getTransports`,
CSV-regex в schema и тест; поведение `http`/`stdio` не меняется.
