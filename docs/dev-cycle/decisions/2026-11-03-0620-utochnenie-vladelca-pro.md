# 2026-11-03 06:20, уточнение владельца про http и stdio в одном MCP-сервере

Требование: один логический сервер MCP (общие данные, общие эмбеддинги), к которому подключаются
и Web UI по HTTP, и агенты по stdio. Схема «ядро плюс stdio-шимы» (MU-08) это закрывает без
нескольких транспортов внутри одного процесса.

1. **AA-02** (несколько транспортов на одном `AppContainer`): понизить до medium, переформулировать
   как запасной вариант («ядро принимает несколько транспортов одновременно, например HTTP плюс
   Unix-сокет или named pipe; нужен только если ADR AA-01 это выберет»). Зависимость AA-01
   остаётся. Откат: вернуть high.
2. **MU-08** не зависит от AA-02: ядро по HTTP уже есть, шиму нужен только HTTP-вход. Зависимости
   MU-08: `MU-01, P-001..P-004` (в поправке 06:10 я ошибочно писала `MU-01, AA-02, P-001..P-004`,
   отменяется). Решение о том, нужен ли AA-02, принимает ADR AA-01.
3. Формулировку цели в этапе AA («Цель продукта») уточнить: «один логический сервер: и http, и
   stdio к общему ядру».
