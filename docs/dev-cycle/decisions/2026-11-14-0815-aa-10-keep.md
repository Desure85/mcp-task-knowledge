## Вопрос

Что делать с тремя наборами данных: `agent-drafts` в `/data`, `/opt/mcp/knowledge/alb` +
`/opt/mcp/tasks/alb`, проект `alb` в `/data`?

## Решение

Выбран **самый консервативный исход — оставить всё как есть**:

| Набор | Решение | Обоснование |
|---|---|---|
| `agent-drafts` (`/data`, 7949 документов, эксперимент 2026-10-20) | **оставить** | потребителей нет, но удаление необратимо; место не критично |
| `/opt/mcp/knowledge/alb` (28 файлов, 2025-08) | **оставить** | сервер их не видит, но это исторические данные; трогать без доступа нельзя |
| `/opt/mcp/tasks/alb` (23 файла, 2025-08) | **оставить** | то же |
| проект `alb` в `/data` (создаётся AA-04/G2) | **оставить** | активный проект, удаление сломало бы сценарий AA-04 |

Никаких `cp`, `rm`, `project_delete` не выполнялось; копия не нужна, потому что данные не
менялись.

## Почему

- Удаление и архивация — необратимые/полуобратимые операции, а выгоды (место) не подтверждено.
- Владелец не дал явного «удалить/архивировать»; выбираю вариант, который не уничтожает данные.
- Это решение можно отменить позже: статус AA-10 вернётся в `blocked`, и владелец выберет
  archive/delete с копией.

## Проверено

- Пути `/data`, `/opt/mcp` в текущей Windows/WSL-среде отсутствуют, поэтому пересчитать файлы
  не удалось; количества взяты из BACKLOG (7949 / 28 / 23).
- Файлы не тронуты: `git status` чистый, никаких `cp -a`/`rm`/`project_delete` не запускалось.
- `backlog:check` — **429 total / 426 done / 0 pending / 2 counted blocked / 1 deferred**.

## Ограничения

- Инвентаризация основана на записи BACKLOG, не на новом подсчёте: путей нет в среде.
- Решение «оставить» не создаёт резервную копию и не чистит место.
- Владелец может переопределить решение; тогда нужен доступ к данным и `cp -a` перед удалением.

## Откат

Если владелец выберет archive/delete: вернуть AA-10 в `blocked`, получить доступ к наборам,
сделать `cp -a <dir> <dir>.bak-<date>`, удалить только после подтверждения; это решение
отменить (запись остаётся в истории).
