# 2026-11-11 18:00 — UI-30: «Всё про X» — карточка узла и переходы

- **Пункт:** UI-30 (high); зависит от UI-28 и UI-25 (закрыт PR #384)
- **Ветка / sha:** `feat/ui-30-entity-card`, от `origin/master` `c638236`
- **Сырьё:** `web-ui/components/graph/NodePanel.tsx`, `web-ui/app/graph/page.tsx`,
  `search_tasks`, `search_knowledge`, `memory_temporal_query`, task/knowledge routes

## Вопрос

Как на существующих связях показать единую карточку сущности со связанными задачами и документами
и открыть её как из графа, так и из задачи/документа, не добавляя серверных форматов?

## Решение

- **NodePanel:** у выбранной сущности появился блок **Related work** — серверный `search_tasks` и
  `search_knowledge` по имени сущности (по 8 результатов), ссылки на `/tasks/<id>` и
  `/knowledge?doc=<id>`. Пустое состояние объясняет отсутствие связей; факты/co-occurring остались.
- **Граф:** `/graph?entity=<title>` выбирает entity-узел. Сначала точное совпадение label, затем
  самый длинный label, входящий в переданную строку (из задачи/документа приходит title с
  суффиксом). Selection применяется один раз на параметр, ручной выбор дальше не перебивается.
- **Задача:** кнопка **Open in graph** в шапке ведёт на `/graph?entity=<title>`.
- **Документ:** кнопка **Open in graph** в reader; `/knowledge?doc=<id>` открывает документ по
  прямой ссылке (для перехода из карточки сущности).
- Новых MCP-инструментов/полей нет; используются существующие поисковые и temporal-инструменты.

## Почему

- Связь «сущность → задача/документ» уже выводится из текста; поисковый индекс — единственный
  существующий путь без нового wire-формата.
- Deep link по title позволяет прийти из любой сущности без знания её synthetic graph id; substring
  fallback нужен, потому что заголовок задачи — `«Entity task»`, а label узла — `«Entity»`.
- Один параметр `entity` и одноразовое применение выбора не ломают ручную навигацию по графу.

## Проверено

- `e2e/entity-card.spec.ts` — **1/1**: temporal fact с entity; graph?entity открывает entity-панель,
  Related work показывает task и document; клик по task ведёт на `/tasks/<id>`; **Open in graph**
  из задачи и из `/knowledge?doc=` снова открывает entity (substring match); cleanup.
- Существующие `task-quick-view` 1/1, `task-tree` 1/1, `knowledge-tree` 1/1 — без регрессий.
- web tsc чистый; `design-guards` 9/9.
- **Мутация RED:** отключение substring-fallback (только точный label) роняет entity e2e на переходе
  из задачи/документа.

## Ограничения

- Связи ищутся по BM25-тексту заголовков/тел; совпадение имени сущности в тексте не гарантирует
  релевантность, и наоборот — синонимы не находятся.
- Не более 8 задач и 8 документов; «показать все» не сделано.
- Карточка реализована для entity-узлов; fact-узлы не получили Related work.
- Deep link по title может выбрать не тот узел при неоднозначных подстроках; выбран самый длинный
  совпавший label.
- `/knowledge?doc=` открывает документ в текущем проекте; кросс-проектные ссылки не поддерживаются.
- NodePanel делает два поисковых запроса при выборе сущности; они не кешируются.

## Откат

Revert ветки: удаляются Related work/useEffect из NodePanel, `?entity`/`?doc` deep links и кнопки
Open in graph; e2e удаляется. Существующие graph/search/temporal инструменты не меняются.
