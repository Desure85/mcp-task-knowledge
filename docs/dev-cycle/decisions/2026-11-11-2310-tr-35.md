# 2026-11-11 23:10 — TR-35: явные ошибки web-crawler

- **Пункт:** TR-35 (low)

## Вопрос

`webcrawler_fetch_page` превращал HTTP 404/timeout/network в `{ok:true,title:'',content:'',links:[]}`;
`webcrawler_crawl_site` считал такой URL страницей и возвращал `{ok:true,crawled:N,synced:0}`, так
что вызывающий не мог отличить пустую страницу от недоступного сайта.

## Решение

- `fetchPage` возвращает discriminated union: успешная страница `{ok:true,url,title,content,links}`,
  ошибка `{ok:false,url,error:{message}}`.
  - non-2xx: `HTTP <status> <statusText>`;
  - исключение fetch/timeout: сообщение ошибки.
- `crawlSite` не увеличивает `crawled` для ошибок; добавляет `failed` и `errors[]`, продолжает обход
  остальных URL. Envelope остаётся `{ok:true,crawled,synced,failed,errors}` для завершённого краула.
- `webcrawler_fetch_page` (одиночный запрос) теперь отдаёт `{ok:false,error}`.
- Docs `docs/features/connectors.md` описывает оба контракта.

## Почему

- Одиночный fetch — атомарная операция: ошибка должна быть ошибкой, а не пустым содержимым.
- Краул — пакетная операция: один недоступный URL не должен отменять остальные, поэтому ошибки
  перечислены в `errors[]`, а не схлопнуты.
- `crawled` теперь означает «успешно обработано», `failed` — «не удалось», счётчики не смешиваются.

## Ограничения

- `crawlSite` при полном отказе всех URL всё равно возвращает `ok:true` с `crawled=0, failed=N`;
  это пакетный контракт, одиночная ошибка видна в `errors`.
- HTML-парсер и лимиты не менялись; глубина/очередь прежние.
- `errors[]` растёт до `maxPages`; отдельного лимита на строку нет.

## Откат

Вернуть `{ok:true,...empty}` в non-ok/catch и убрать `failed/errors` из `crawlSite`; удалить тест/
абзац документации.
