# 2026-11-11 22:00 — Z-11: агент в промптах и реестр агентов

- **Пункт:** Z-11 (medium); зависит от Z-10 (закрыт)
- **Ветка / sha:** `feat/z-11-agent-target`, от `origin/master` `c2e8197`
- **Сырьё:** `prompts_list target`, `project_agents_get/set`, `web-ui/app/prompts`, `nav-config`

## Вопрос

Как довести поддержку агентов Z-10 до UI: серверный фильтр `target`, бейдж агента, редактор
одиночного target и страница реестра — без клиентской фильтрации всего каталога?

## Решение

- **API-клиент:** `api.agents.list/set` поверх `project_agents_get`/`project_agents_set`;
  `api.prompts.list` принимает `target`, элементы каталога содержат `target`.
- **Prompts:**
  - `PromptDraft` получил `target`; `promptToDraft`/`buildPromptPatch` читают и пишут
    `metadata.target` (по умолчанию `universal`); `validatePromptDraft` target не требует.
  - фильтр **Agent target** — одиночный select, значение уходит в `prompts_list` параметром
    `target` (не клиентская фильтрация); в пустом состоянии и Clear filters он учтён;
  - бейдж `agent: <id>` в карточке и в детали;
  - select target в форме создания и в редакторе; create пишет `metadata.target`.
- **Страница `/projects/settings/agents`:** список built-in/custom, добавление slug-цели,
  удаление custom, **Save registry**; built-in показаны, но не удаляются (сервер их всегда
  восстанавливает). Ошибка `AGENT_TARGET_IN_USE` показывается серверным сообщением. Ссылка
  добавлена в nav и page-meta.

## Почему

- Серверный `target` уже реализован Z-10; UI просто перестаёт фильтровать каталог на клиенте.
- Одиночный select соответствует контракту Z-10 (target — скаляр), без мультиселекта.
- Реестр — тот же `project_agents_*`, что используют промпты; отдельной модели нет.

## Ограничения

- Built-in targets нельзя удалить (так устроен сервер); UI это показывает.
- Перемещение промптов при удалении используемого target (`moveTo/moves`) в UI не реализовано —
  сервер вернёт `AGENT_TARGET_IN_USE`.
- Реестр — страница, а не вкладка внутри `/projects/settings`; ссылка добавлена в sidebar.
- `target` в форме создания не валидируется по slug на клиенте (сервер нормализует).
- Z-03 (high) в этом раунде не начат: Z-01/Z-02 не подключены к MCP-инструментам чтения/записи
  пакетов, для UI нужен отдельный серверный инкремент. Это зафиксировано, а не выдано за done.

## Откат

Revert ветки: удаляются target-поля/фильтр/бейджи/селекты, `api.agents`, страница реестра и nav-
пункт; промпты снова фильтруются только по статусу. Серверный wire-формат не меняется.
