- **Основание:** ADR-009 §«Интерфейсы» (Store, HistoryProvider, LockProvider), §«Что уже

## Вопрос

После Y-02a контрактом покрыты только задачи и знания. Остальная часть Store-интерфейса — это
промпты, память, метаданные проекта, журнал событий, — плюс отдельные HistoryProvider и
LockProvider. Если сложить это в один инкремент с Y-02a, контрактные тесты снова стали бы
проверять смесь «слой доступа + новая коллекция», а не эквивалентность старому поведению.

## Решение

1. **Разбить остаток Y-02 на три инкремента** (итого четыре):
   - **Y-02a** — задачи и знания (done, PR #320);
   - **Y-02b** — метаданные проекта, журнал событий, история, замки (этот PR);
   - **Y-02c** — промпты и память (две коллекции с собственными файловыми форматами);
   - **Y-02d** — профиль в `AppContainer`, регистраторы получают хранилища из контекста,
     guard-тест «в `src/register/**` нет прямых импортов хранилища».
2. **Интерфейсы Y-02b** добавлены в `src/storage/contracts.ts`:
   - `ProjectStore` — list/detail/create/remove/readMetadata/updateMetadata/workflow;
   - `EventLogStore` — append/since/snapshot/snapshots/compact;
   - `HistoryProvider` — list/restore с `kind: 'doc' | 'task'`;
   - `LockProvider` — `withLock(key, fn)`.
   Файловый профиль реализует их делегированием (`src/projects.ts`, `src/workflow.ts`,
   `src/sync/event-log.ts`, `src/fs.ts`).
3. **История задач — явный отказ.** В файловом профиле версии есть только у документов
   (`.versions`, TD-005); история задач — это git этапа R, и она не выставляется наружу. Запрос
   `kind: 'task'` бросает `StoreError('CAPABILITY_UNAVAILABLE')`, а не возвращает `[]`: пустой
   список читался бы как «версий нет».
4. **Пути наружу не меняются.** `ProjectInfo`/`ProjectDetail` сегодня содержат `paths`, и
   визибл-формат ответов инструментов Y-02 менять не имеет права (граница из ADR-009). Поэтому
   контракт возвращает текущие типы (type-only импорт из `src/projects.ts`), а удаление путей из
   wire-формата — отдельное изменение контракта инструментов после Y-02, а не тихая правка здесь.
5. **Журнал событий — фабрика, а не синглтон.** `EventLog` пишет один JSON-файл, путь задаёт
   вызывающий (правило 1 ADR-009); в профиле это `events(storagePath)`, чтобы SQLite/Postgres
   профили могли отдать таблицу вместо файла.

## Почему

- Четыре маленьких контракта с парными проверками против текущих функций дают ту же гарантию
  эквивалентности, что и Y-02a, и не раздувают PR до необозримого.
- `CAPABILITY_UNAVAILABLE` для истории задач — первый реальный пользователь этого кода ошибок;
  заодно проверено, что «отсутствие возможности» не выглядит как пустой успешный ответ.
