## Вопрос

Какие из четырёх кандидатов AC-04e воспроизводятся на текущем master, и какие нужно исправить
в `logs_tail`, не ломая wire-формат?

## Решение

Проверены кандидаты:

1. **Сквозной `requestId` для прямых вызовов** — **не воспроизведён как дефект**.
   `requestId` создаётся только для вложенных вызовов `tools_run`/`tools_batch`
   (`src/core/tools-diagnostics.ts`); у прямого MCP-вызова такого id нет, поэтому «потерять» его
   нельзя. Добавление id на уровне `wrapToolHandler` изменило бы wire-формат каждого ответа и
   требует отдельного решения — не входит в AC-04e.
2. **`logs_tail` не фильтрует по `requestId`** — **воспроизведено и исправлено**:
   `requestId` добавлен в схему `logs_tail`, `LogTailOptions` и `passesFilters`.
3. **Читается только активный файл, `.1`/`.2` недостижимы** — **воспроизведено и исправлено**:
   `readLogTail` читает `.2` → `.1` → активный (старые первыми), возвращает `segments` и
   `truncated` учитывает окно каждого файла.
4. **`project` принимается и игнорируется** — **воспроизведено и исправлено**:
   `project` фильтрует JSON-записи по точному полю; `logs_tail` возвращает `project`/`requestId`
   в ответе и реально применяет их.

## Решение (изменения)

- `src/core/log-file.ts`: `requestId`/`project` в `LogTailOptions`, `segments` в результате,
  `jsonField`/`passesFilters`, чтение ротаций.
- `src/register/logs.ts`: новые поля схемы и ответа, передача фильтров.
- `tests/log-tail.test.ts`: AC-04e — чтение трёх сегментов, фильтры reader'а, проброс через tool.

## Почему

- `requestId` уже пишется для вложенных сбоев; без фильтра `logs_tail` не мог найти строку по id.
- Ротации — часть opt-in лога; читать только активный файл значит терять диагностику после ротации.
- `project` принимался, но игнорировался — мёртвый параметр и межпроектная выдача.

## Ограничения

- Фильтр `project` строгий: записи без поля `project` и не-JSON строки отбрасываются.
- Читаются только `.2`/`.1`/active (текущий `LOG_ROTATE_KEEP=3`); при другом keep более старые
  сегменты не видны.
- Окно 256 KiB на сегмент; очень старые строки внутри сегмента могут быть отрезаны.
- Прямой `requestId` не добавлен (см. кандидат 1); wire-формат не менялся, кроме аддитивных
  полей `logs_tail`.
