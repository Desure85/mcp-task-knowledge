## Вопрос

`tests/transport-wire-snapshots.test.ts` импортирует только SDK
(`serializeMessage`/`deserializeMessage`/`ReadBuffer`) и не проверяет ни одного файла `src/`.
Он либо должен стать тестом нашего wire-слоя, либо быть явно помечен контрактом зависимости и
исключён из покрытия проекта.

## Решение

- Файл помечен `@dependency-contract` с явным объяснением: его задача — фиксировать Q-011
  (JSON-RPC framing SDK), а не покрывать `src/`.
- Покрытие уже исключает его: `vitest.config.ts` `coverage.include` = `['src/**/*.ts']`;
  тестовые файлы в покрытие не входят. Дополнительная конфигурация не потребовалась.
- Расхождения наших транспортов ловят integration/e2e (stdio/http/tcp), а не этот файл.

## Почему

- Переписывать тест на наш wire-слой значило бы дублировать SDK-кодек; полезнее зафиксировать
  контракт зависимости и явно назвать его границы.
- Метка делает исключение из покрытия осознанным, а не случайным.

## Ограничения

- Если SDK изменит framing, тест упадёт — это ожидаемый контракт, а не покрытие продукта.
- Наш собственный wire-слой по-прежнему проверяется только e2e; отдельного unit-теста на него
  этот пункт не добавляет.
- `coverage.include` может измениться в будущем; тогда исключение надо перепроверить.
