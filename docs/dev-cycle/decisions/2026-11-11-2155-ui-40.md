# 2026-11-11 21:55 — UI-40: палитра статусов и типов

- **Пункт:** UI-40 (medium), зависит от UI-10, UI-34, UI-35
- **Ветка / sha:** `feat/ui-40-palette`, от `origin/master` `78310f7`

## Вопрос

Проект мог выбрать только шесть `st-*` и три `ty-*`; новые оттенки и ссылки на цвета темы
отсутствовали, пикер был `<select>` без образцов/предпросмотра, а DESIGN §3/§4 не описывали
палитру. Произвольный hex в данных проекта не должен находить визуального применения.

## Решение

### Токены

- 12 оттенков `st-slate`, `st-blue`, `st-indigo`, `st-violet`, `st-pink`, `st-red`, `st-orange`,
  `st-amber`, `st-green`, `st-teal`, `st-cyan`, `st-gray` и `info` — в шести вариантах
  `globals.css` (light/dark × indigo/petrol/copper), с `@theme inline`-маппингом.
- 5 ссылок на тему: `accent`, `success`, `warning`, `danger`, `info` (последний — новый токен
  `--info`; классы `bg-success`, `bg-warning`, `bg-danger`, `bg-info`).
- `STATUS_COLOR_TOKENS` = старые 6 + hue + theme refs; `TYPE_COLOR_TOKENS` = старые 3 + те же.
  Старые имена остаются валидными; существующие проекты не мигрируются.
- `COLOR_TOKENS` расширен, поэтому prepaint-скрипт и custom-theme применяют новые CSS-переменные.

### Контраст

- `theme-pairs.ts`: `HUE_COLOR_TOKENS`, `THEME_COLOR_TOKENS`, `PALETTE_COLOR_TOKENS`; `TEXT_PAIRS`
  проверяет все новые токены на `surface` 4.5:1 и `surface-2` 3:1, `info/canvas` 3:1.
- Итог: **94 пары × 6 вариантов**, минимум 3.09:1 (все AA).
- Custom themes: `HUE_SEED` + `pick` подбирают каждый токен на `surface` 4.5:1; fallback при
  неудаче — уже валидный `muted`/`accent`/`danger`, поэтому тема не блокируется новым оттенком.
  Старые custom-темы без новых ключей `parseTokens` дочитывает fallback-цветом, `parseTheme`
  сразу пересчитывает из base.

### UI

- `ColorTokenPicker` — `role="radiogroup"`, кнопки-образцы с названием, `aria-checked`,
  `var(--token)` и двумя чипами `color-mix` (светлый/тёмный) — без hex в данных.
- `StatusesTab`/`TypesTab`: `<details>` popover с сеткой; старый `<select>` цвета убран, выбор
  пишет имя токена.
- `board.ts`/`board-lanes.ts`: новые токены → сгенерированные `bg-st-*`/`bg-accent`… классы;
  неизвестное значение (включая hex) по-прежнему падает на категорию/`ty-task`.
- `/design`: секция «Status & type palette» с обоими предпросмотрами.
- `DESIGN.md` §3.7 + §4.7, `TOKEN_PURPOSE`, `npm run design:doc` перегенерирован.

## Почему

- Имена токенов в данных, а не hex: тема меняет оттенки без миграции проектов и без потери AA.
- Палитра общая для статусов и типов: одна сетка и одна матрица контраста, меньше расхождений.
- Ссылки на тему (`accent`, `success`, `info`) дают семантический выбор без дублирования hex.
- `color-mix` от того же токена сохраняет связь предпросмотра с реальным цветом.
- Fallback для старых custom-тем не ломает уже сохранённые темы и не блокирует их применение.

## Ограничения

- Сервер (`src/workflow.ts`) по-прежнему принимает любую строку цвета; UI не предлагает hex, но
  API-клиент может прислать hex, и он отрисуется fallback'ом категории, а не ошибкой.
- Палитра фиксированная (12 оттенков + 5 ссылок); произвольные оттенки не добавляются.
- `color-mix` требует современного браузера; в старых — обычный фон без смеси.
- Custom-theme старые темы до пересчёта получают fallback-цвета только после `parseTheme`; до
  hydration prepaint видит неполный набор и рисует базовую палитру.
- `details`-поповер не закрывается по клику вне (нативный `<details>`); это не модалка.
- Локальный `npm --prefix web-ui run test` на Windows красный только по `design-doc.test.ts`
  (pre-existing среда), CI Linux — гейт.

шести, `ColorTokenPicker` → `<select>`, откатить `DESIGN.md`/`theme-pairs`; API/сервер не менялись.
