# 2026-11-12 15:15 — TR-22: remove dead FTS/migration modules

- **Пункт:** TR-22 (low; design gate «wire FTS5 or delete»)
- **Ветка / sha:** `chore/tr-22-remove-dead-sqlite`, от `origin/master` `cb679fb`

## Вопрос

`src/behavioral/fts-search.ts` (FtsMemorySearch) и `src/db/migration-framework.ts` (MigrationFramework)
экспортировались, но не имели runtime-потребителей. Выбрать: подключить FTS5 к `query_memory` или
удалить мёртвый код.

## Решение

Удалить оба модуля и их spec-файлы, а также barrel-экспорты:

- `src/behavioral/fts-search.ts` + `.spec.ts`, экспорт из `src/behavioral/index.ts`;
- `src/db/` целиком (`migration-framework.ts`, `.spec.ts`, `index.ts`) — у `src/db` не осталось других
  экспортов/потребителей.

`better-sqlite3` **не удаляется**: он используется SQLite-профилем (`storage/profiles/sqlite`), а не
только удалёнными модулями.

## Почему

- Ноль runtime-импортов: модули были доступны только через barrel и собственные тесты.
- Подключение FTS5 к `query_memory` — отдельная функциональность, не входящая в DoD TR-22 и
  требующая миграции/кэша; удаление снижает поверхность без риска.
- SQLite-профиль остаётся на `better-sqlite3`; заявление «убрать dep» из TR-22 отвергнуто как неверное.

## Проверено

- `rg` по `src/tests/scripts`: потребителей `FtsMemorySearch`/`MigrationFramework`, `db/index`,
  `behavioral/index` больше нет; build (`tsc`) чистый.
- Удалены только экспортные строки и мёртвые файлы; wire/API surface не менялся.
- `backlog:check` **382 done / 0 pending / 38 blocked / 1 deferred**.

## Ограничения

- `better-sqlite3` остаётся зависимостью (SQLite-профиль); DX-20 single-binary по-прежнему требует
  замены драйвера, TR-22 этого не решает.
- FTS5 для памяти не подключён и не планируется этим решением.

## Откат

Восстановить три файла `src/db/*`, `src/behavioral/fts-search.*` и две экспортные строки из git.
