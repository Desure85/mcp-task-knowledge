## Вопрос

UI и агенты знали о соседях только разрозненно: `tasks_dag`/`tasks_get_deps` — для задач,
`knowledge_list.parentId` — для документов, а связи «факт упоминает X» не собирались вовсе. Одного вызова
«что связано с X и почему» не было.

## Решение

`graph_neighbors({id, project?, limit?, fields?})` — read-only, существующие хранилища, без нового серверного
формата:

- задача: `dependsOn` → `depends_on/out`; задачи, которые зависят от неё → `blocks/in`; `parentId` →
  `parent/out`; дети → `child/in`;
- документ: `parentId` → `parent/out`, дети → `child/in`;
- память: `TemporalGraph.query({includeInvalidated:false,limit:1000})`; факт считается упоминанием, если
  его `entities` содержит точную метку (регистронезависимо) или (для метки ≥3 символов) statement содержит
  её как слово;
- `title` для задачи/документа — реальный title, для памяти — statement;
- `limit` 1..200 (default 50), `fields` проецирует `kind/id/title/relation/direction`;
- неизвестный id/entity → `ok`, `total:0`, пустой список;
- отсутствующий/битый temporal-файл не скрывает task/doc-соседей.

## Почему

- Один инструмент закрывает три существующих источника без дублирования графа в памяти.
- `direction` отличает «зависит от» и «блокирует», иначе список не отвечает на «почему».
- Слово-граница для коротких меток: `title:'A'` не должен совпадать с любым фактом, где есть буква `a`.
- `fields` даёт тот же экономичный контракт, что `fields` у list-инструментов (U-04).

## Ограничения

- Только прямые соседи (без depth/BFS).
- Dependencies/parent ищутся в пределах одного project; межпроектные связи не видны.
- Memory query ограничен 1000 фактами и не фильтруется по project/entity-индексу.
- Для метки <3 символов совпадение только по точному `entities`; statement-поиск отключён.
- `fields` — простая проекция, не вложенные поля; `total` считается до `limit`.
- Нет `graph_neighbors` в компактном каталоге и UI-панели.
