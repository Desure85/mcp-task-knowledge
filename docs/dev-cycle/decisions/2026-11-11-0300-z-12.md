# 2026-11-11 03:00 — Z-12: развёртывание скиллов и промптов по типам агентов

- **Пункт:** Z-12 (high)
- **Ветка / sha:** `feat/z12-agent-deploy`, от `origin/master` `e47ce19` (PR #370 влит)
- **Основание:** BACKLOG Z-12; Z-10 (`target`/реестр), Z-01/Z-02 контейнеры

## Вопрос

Как развернуть скилл/промпт в каталог конкретного агента, не получив запись вне allowlist, не пройдя
через предпросмотр, без снимка для отката и без явного подтверждения внешнего/удаляющего действия?

## Решение

- `src/skills/agent-deploy.ts`:
  - у цели есть `root` и `format` (`skill-md` → `<root>/<id>/SKILL.md`, `markdown` → `<root>/<id>.md`);
    по умолчанию `universal` = `$HOME/.agents/skills`, `claude` = `$HOME/.claude/skills`,
    `opencode` = `$HOME/.config/opencode/skills`; в тестах/вызовах roots инжектируются;
  - `previewAgentDeploy` **ничего не пишет**: планирует create/update/delete, запрещает `..`/абсолютные
    пути, проверяет принадлежность каталогу и **симлинки** (lstat + realpath по каждому существующему
    компоненту), external-артефакты требуют `allowExternal`, delete — `allowDelete`;
  - `applyAgentDeploy` требует `confirm === true` и совпадения токена предпросмотра, снимает копии
    всех затрагиваемых файлов в `$HOME/.mcp-task-knowledge/deploy-snapshots/<id>/` (включая удаляемые),
    затем пишет атомарно;
  - `rollbackAgentDeploy` восстанавливает изменённые/удалённые файлы и удаляет созданные;
  - hooks/scripts/`.mcp.json` не разворачиваются этим модулем (Z-04 оставляет их выключенными).
- `src/register/agent-deploy.ts`: MCP `agents_deploy` (dry-run по умолчанию, `apply:true` требует
  `confirm` или успешной MCP-элицитации; apply/rollback — только admin role на authenticated-транспорте)
  и `agents_deploy_rollback`. Preview доступен без admin, запись — нет.
- `docs/api-reference.md` перегенерирован (143 tools), `docs/features/tools.md` — строки и total
  141/143/145.

## Почему

- Разделены план и запись: предпросмотр отдаёт diff-действия и токен, а apply не может «передумать»
  и записать другой набор.
- Снимок берётся до первой записи и включает удаляемые файлы — иначе откат после delete невозможен.
- Symlink-проверка идёт по существующим компонентам пути через lstat+realpath: одной проверки
  «path.resolve внутри root» недостаточно, если каталог — junction.
- Admin-гейт на apply/rollback закрывает обход «обычный пользователь вызвал инструмент».

## Ограничения, записанные честно

- Веб-страницы админки для деплоя нет: действие выполняется MCP-инструментом с confirm-флоу; это
  записано как отдельный UI-слой, а не выдано за готовый.
- Кастомные цели из Z-10 пока не имеют собственного deploy-root в метаданных: `agents_deploy` знает
  built-in пути; для custom target нужен явный конфиг (не реализован).
- Конвертации между форматами нет: один артефакт адресуется одному target, opencode-формата в
  `SkillExportFormat` по-прежнему нет; вопрос «один промпт для claude и opencode» остаётся открытым.
- External-артефакт требует только `allowExternal`; показ команд/разрешений из Z-04 в этом слое не
  дублируется — Z-04 остаётся источником политики.
