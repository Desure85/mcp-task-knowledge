## Вопрос

При > 50k файлов в одном проекте `tasks/<project>/` и `knowledge/<project>/` деградируют
`readdir`, backup и listing. Нужно писать в `tasks/<project>/<ab>/` и
`knowledge/<project>/<ab>/` (ab — первые 2 символа id), читать оба layout без дублей, не удалять
закрытые задачи при автоархиве и дать компакцию.

## Решение

- `src/storage/sharding.ts`: `shardOfId`, `listDataFiles`, `resolveDataFile`, `migrateToShards`,
  `compactShards`, `writeDataPath`, маркер `.sharded`.
- Tasks: `writeDataPath` на create, `resolveDataFile` на read/update/delete, `listDataFiles` в
  `listTaskEntries`, `listTasks`, `pruneExpiredClaims`.
- Knowledge: create идёт через `writeDataPath`, read/update/delete — через `resolveDataFile`;
  list читает root и shard-каталоги.
- Чтение: root → shard → legacy flat; `listDataFiles` дедуплицирует по id и предпочитает root.
- Автоархив: `archiveStaleClosedTasks` ставит `archived`/`archivedAt`, **не меняет статус и не
  удаляет**; opt-in `TASK_ARCHIVE_AFTER_DAYS` в `AppContainer.init`.
- Компакция: `compactTaskStorage`/`compactShards`; таймера нет, вызов внешний.
- Seed: `scripts/bench/seed-scale.mjs --sharded` пишет shard-layout и распределяет id по 256
  префиксам.

## Почему

- Первые два символа id дают 256 бакетов, достаточно для 100k (≈400 файлов/шард здесь).
- Чтение обоих layout сохраняет совместимость с существующими DATA_DIR и legacy flat.
- Root-first dedupe делает миграцию безопасной: половина перенесённых файлов не даёт дублей.
- Архив без удаления обратим и не требует миграции.

## Проверено

- `tests/sharding.test.ts` — **6/6**: shardOfId, migrate+read обоих layout без дублей, write after
  migration, compact back, tasks read/update/delete, docs read/update/delete, archive без удаления.
- `npm run build` — чисто.
- **Мутация:** shard-путь в `resolveDataFile` подменён на несуществующий `.never` → тесты не

- **100k benchmark:** `seed-scale --n 100000 --sharded --tasks-only` → 256 shard-каталогов,
  100000 файлов, max 443/шард; `readdir` шарда `00` (374 entry) — **0,67 ms** (<100 ms DoD).
- backlog:check **367/31**.

## Ограничения

- Только file profile; SQLite/Postgres не менялись.
- Ленивый счётчик порога process-local; внешние записи подхватятся при следующем подсчёте.
- Миграция последовательная, без транзакции на весь проект.
- Компакция не фоновая: нет таймера, вызывается вручную/кроном.
- Бенчмарк — локальный SSD, один шард; end-to-end поиск с холодным кэшем не измерялся.
