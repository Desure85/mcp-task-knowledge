# 2026-11-11 22:30 — AA-07: bundle.json и install-agent

- **Пункт:** AA-07 (high), зависимости DX-29/DX-10/DX-11/DX-26/AA-05/Z-04
- **Ветка / sha:** `feat/aa-07-bundle`, от `origin/master` `701262d`

## Вопрос

Установка агентских плагинов, команд и прокси-шима была ручной (`cp` в `~/.config/opencode/...`),
без манифеста, sha256, идемпотентности, dry-run и отката. Ссылка DX-29 давала только сниппет MCP,
но не комплект.

## Решение

### Манифест

`bundle.json` (schema 1, генерируется `scripts/gen-bundle.mjs`, проверяется `npm run bundle:check`)
содержит:

- `server`: имя пакета, версия, команда `npx -y mcp-task-knowledge@<version>`, sha256
  `package.json`;
- 11 компонентов: 8 OpenCode plugins (включая `sync` и `session-draft`), consolidation command,
  draft collector script, proxy shim; у каждого `version`, `source`, `sha256` и `targets` по
  клиентам (`opencode` / `claude-code`) с корнем (`opencode` конфиг, `claude`, `share`);
- `package.json#files` теперь публикует `bundle.json` и `extensions/opencode/`, чтобы npx-пакет
  содержал собственные источники.

### Installer

`src/cli/install-agent.ts` + `dist/index.js install-agent`:

- `--client opencode|claude-code`, `--home`, `--bundle`, `--dry-run`, `--rollback`;
- только Node (без bash), `PATH` не нужен;
- проверяет каждый sha256 **до** первой записи, отклоняет `..`/absolute/drive target;
- пишет `~/.config/opencode/opencode.json` (`mcp.mcp-task-knowledge.type=local`) или
  `~/.claude.json` (`mcpServers.mcp-task-knowledge`);
- бэкапит существующие файлы и конфиг в `~/.mcp-task-knowledge/backups/<client>/`, пишет манифест
  `~/.mcp-task-knowledge/<client>-install-manifest.json`;
- повторный запуск сравнивает хэши → `no changes`; обновление сохраняет исходный backup для
  rollback; `--rollback` восстанавливает/удаляет всё;
- dry-run ничего не создаёт (проверено на пустом HOME).

## Почему

- Хэш источника до записи исключает частичную установку из подменённого bundle.
- Backup + manifest дают точный откат, а не «удали то, что нашли».
- Идемпотентность через хэш таргета не зависит от mtime и CRLF: хэширование нормализует `\r\n`.
- `--dry-run` — отдельная ветка без mkdir/backup, а не «показать после записи».
- Плагины копируются, но не исполняются установщиком; их запускает клиент с правами пользователя
  (Z-04: перед установкой нужно ревью bundle/plugins).

## Ограничения / что не доказано

- **Живая загрузка плагинов OpenCode и поиск тестового драфта в трекере не проверены**: в песочнице
  нет аутентифицированной agent-сессии/модели (см. CM-03). Тесты доказывают установку файлов в
  auto-discovery путь, конфиг и хэши, но не runtime-эффект плагина.
- `npx` скачивает пакет при первом запуске клиента; установщик не скачивает и не проверяет tarball.
- Существующий JSONC-конфиг OpenCode не редактируется (используется `opencode.json`).
- Запись не транзакционная: crash между файлами оставит частичную установку без manifest; повторный
  запуск сходится.
- Windows job добавлен, но на момент записи решения ещё не прогнан (CI PR покажет).
- Плагины исполняются клиентом с правами пользователя; автоматической sandbox-проверки Z-04 нет.

## Откат

Удалить `bundle.json`, `scripts/gen-bundle.mjs`, `src/cli/install-agent.ts`, CLI-dispatch, тесты и
docs; убрать `bundle` scripts/`files` и CI job, вернуть setup-link markdown без Bundle; `install-agent`
не трогает данные, только HOME-файлы, поэтому пользовательский rollback — `--rollback`.
