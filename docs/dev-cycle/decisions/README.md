# Журнал решений: файл на решение

Записи решений контролёра лежат в этом каталоге, по файлу на решение. Один PR меняет свой файл и
не конфликтует с остальными.

<!-- preamble:start -->
Владелец 2026-11-03 разрешил: решения по проработке и приоритетам принимает контролёр, фиксирует
здесь; по запросу владельца отдаёт отчёт одним документом. Формат записи: время, пункт, вопрос,
решение, почему, чем проверено, как откатить.

Не решается без владельца: удаление данных (`/data`, `/opt/mcp`, agent-drafts), публикация вовне,
YouTrack, force-push, права и аутентификация в production-контуре сверх уже описанного в
бэклоге.

Основание: замысел из `BACKLOG.md` (вводные и «Решения владельца» этапов), ADR и docs; в каждой
записи ссылка на конкретное место замысла. Если замысел молчит или расходится, записывается «жду
владельца», решение не принимается.

## Формат записи

Первый заголовок `#`, затем поля прежнего журнала:

- **Вопрос** — что решалось.
- **Решение** — что выбрано.
- **Почему** — основание и отвергнутая альтернатива.
- **Проверено** — команда, тест или источник, подтверждающий решение.
- **Откат** — как вернуть прежнее состояние.

Исторические записи сохраняют свой текст дословно; часть из них пишет «Основание/Решение/Почему/
Проверено/Откат» вместо явного «Вопрос». Новые записи содержат все пять полей.

## Имя файла

`YYYY-MM-DD-HHMM-<id-slug>.md`

- `YYYY-MM-DD` — дата записи из заголовка.
- `HHMM` — время записи из заголовка; формат ключа единый у всех файлов.
- Если времени в заголовке нет (исторические записи 2026-11-05 и 2026-11-06), назначен
  синтетический возрастающий ключ `0001`, `0002`, … по порядку таких записей внутри даты.
  Это сохраняет исходный порядок: сортировка по имени совпадает с хронологией, а
  `devcycle status` и `report` читают «последние N» верно.
- `<id-slug>` — id пункта из заголовка латиницей в нижнем регистре (`dx-16`, `tr-04a`,
  `p-20261106-1`, `y-09`, `q-016`). Если id в заголовке нет — транслит первых значимых слов
  заголовка (`razmetka-bekloga-vetka`).
- Совпадение имён (одна дата, одно время, один id) — суффикс `-2`, `-3`.

Порядок записей определяется именем файла. Имя существующего файла не меняется: это меняет историю.

## Как добавить запись

1. Возьми реальное время записи в формате `HHMM`.
2. Создай новый файл по маске; чужие файлы не дописываются.
3. Заполни все пять полей.
4. В `docs/dev-cycle/decisions-log.md` запись не добавляй: там только указатель.

## Правила

- Чужие файлы решений не правятся.
- Текст уже созданной записи не меняется; уточнение оформляется отдельной записью.
- `decisions-log.md` — указатель для старых ссылок, а не место для новых записей.
