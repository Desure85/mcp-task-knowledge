# 2026-11-07 04:48, TR-04c: contract и fuzz переписаны на реальный код (ветка test/tr04c-rewrite-real)

Вопрос: как переписать `tests/cli.tools_list.contract.test.ts` и `tests/jsonrpc-fuzz.test.ts`, чтобы
поломка `src/` их красила, — не меняя `src/` (кроме временных мутаций) и не добавляя новых артефактов
сверх строки бэклога и этой записи.

## Решение

1. **`tests/cli.tools_list.contract.test.ts` → in-process на реальной регистрации.** SUT — не текст, а
   продовый путь: `createServerContext()` создаёт настоящий `McpServer`, `defaultRegistration(ctx)`
   (`src/core/app-container.ts:161`) вызывает все `register*Tools` ровно как сервер. `src/register/setup.ts:299`
   подменяет `server.registerTool` своей обёрткой (дедуп + реестр), поэтому спай ставится **на инстанс
   после `createServerContext()`**, а не на `McpServer.prototype`: иначе дубль, который обёртка молча
   пропускает, в спай не попадёт. Шесть проверок: пол (>100 захваченных имён — против вакуумного зелёного),
   banned single-tools литералом, обязательное ядро (19 имён), непустой `description` у всех,
   `inputSchema` — непустой объект валидаторов (у `tasks_create` есть `title`/`project`), уникальность имён.

2. **`tests/jsonrpc-fuzz.test.ts` → реальный HTTP-разбор.** Копия `normalizeEnvelope` удалена: такой
   функции в `src/` нет вообще (`git grep normalizeEnvelope src/` пуст). Фаззится фактический путь
   `HttpTransportAdapter.handleRequest` (`src/transport/http-transport.ts:381-425`): `readBodyWithCap` →
   `JSON.parse` с fallback в строку → `authorizeHttpCall`/`extractHttpCall` (`src/core/auth-gate.ts:330`) →
   SDK. Один живой сервер на порту от ОС, один keep-alive сокет; на каждый мусорный payload — с сессией и
   без, затем `ping` на **том же** сокете (`res.socket.localPort` сравнивается).

3. **Контракт свойства:** статус < 500 и из объявленного набора; тело — валидный JSON-RPC 2.0 либо пустой
   202 (уведомление); код ошибки из `-32700/-32600/-32601/-32602` плюс два документированных неспековых
   (`-32000` — нет сессии/413, `-32001` — fail-closed гейт); нет stack-кадров (`file.ts:line:col`), нет
   абсолютных путей (`process.cwd()`), нет `node_modules`; соединение живо. Плюс детерминированная таблица
   наблюдений (6 строк) — она пинит фактические коды и не даёт свойству «уплыть» при рефакторинге.

4. **Транспорту даётся permissive `AuthManager({requireAuth:false})`** — конфигурация сервера без логина.
   Без него `decideMethodCall` при отсутствии `authManager` на http закрывается fail-closed (`-32001` на
   любой не-lifecycle метод), и до протокольных ошибок (`-32601`) дело не доходит: тест проверял бы
   артефакт харнесса, а не разбор.

## Почему

- **In-process, а не живой `tools/list`:** wire-форма `{type:'object', properties}` уже покрыта
  `tests/e2e-full/tcp-transport.test.ts:166` и `tests/e2e-full/mcp-inspector.test.ts:37`; второй wire-тест
  дублирует, а in-process красится от правки `src/register/*` без сборки. Ссылка из поручения соблюдена.
- **Banned-list сохранён литералом:** исходный файл проверял bulk-only политику, а не наличие ядра. Замена
  одного другим удалила бы единственное реальное утверждение файла; поэтому обе проверки живут вместе.
- **Точное число инструментов не пинится:** 126/128 меняются от `CATALOG_ENABLED`/динамических тулов; пин
  точного числа — хрупкость, которую следующий агент «починит» правкой цифры. Пол >100 ловит поломку
  регистрации, не запрещая добавлять инструменты.
- **`inputSchema` проверяется как ZodRawShape:** при регистрации это `{ project: z.string().optional() }`,
  `{type:'object'}` появляется только в wire-`tools/list` (SDK конвертирует). Ассерт `type==='object'` на
  уровне регистрации был бы ложным.
- **Seed фиксирован ради воспроизводимости матрицы,** а не ради зелёного: RED мутации (c) проверен на двух
  seed (20261107 и 424242).

## Находки вне скоупа (не чинились, `src/` не менялся)

1. **Sessionless-мусор отвечает `-32000`, а не `-32700`** (`src/transport/http-transport.ts:428` и `:451`).
   JSON-RPC 2.0 требует Parse error для неразбираемого тела. Тест фиксирует текущее поведение и допускает
   оба кода; предложение — отдельный подпункт TR-04c-1: различать «нет сессии» и «тело не разобрано».
2. **Пустой batch `[]` → 202 с пустым телом** (поведение SDK через транспорт). Для JSON-RPC это
   `-32600 Invalid Request`; для MCP транспортный 202 семантически означает «принято, ответа нет».
   Наблюдение, приоритет низкий.
3. **Дубль регистрации расходится между реестром и SDK** (`src/register/setup.ts:302-318`): при
   `STRICT_TOOL_DEDUP=0` обёртка пишет новое определение в `toolRegistry` (`toolRegistry.set`) и
   возвращается, не вызывая SDK. Итог: `tools_list`/`tool_schema`/`tools_run` видят второе определение, а
   нативный `tools/call` — первое (зарегистрированное SDK). Приоритет средний, предложение — отдельный
   тикет на `MCP_STRICT_TOOL_DEDUP=1` по умолчанию или запрет перезаписи реестра в дубль-ветке.
