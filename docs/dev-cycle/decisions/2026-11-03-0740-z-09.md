# 2026-11-03 07:40, Z-09: обновление и слияние скиллов (решение владельца)

Решение владельца: скилл, скачанный извне и не менявшийся у нас, обновляется; если менялся, не
сливаем автоматически, а выдаём инструкцию для копирования, которую человек передаёт агенту,
чтобы тот слил наши правки с внешним репозиторием.

Основание: этап Z, решения владельца (в) и (г) (3-way, `prompts_merge_prepare` и
`prompts_merge_apply`, «Copy merge prompt», результат как черновик с подтверждением человеком),
(д) (сеть только по запросу, без фоновых запросов).

Моя трактовка (владелец может поправить): обновление немодифицированного пакета выполняется одним
явным действием (кнопка или команда) без подтверждения diff, так как локальных правок нет;
фонового автообновления нет, периодическая проверка новых версий по расписанию выключена по
умолчанию и включается явно. Слияние измененного: сервер ничего не склеивает сам, выдаёт данные и
инструкцию (UI «Copy merge prompt», MCP-подсказка), человек передаёт её агенту, агент вызывает
`prompts_merge_apply`, результат попадает черновиком и применяется только после подтверждения
человеком; автономное слияние агентом без подтверждения не допускается. Z-09 закрыт; Z-07
разблокирован по этому гейту (остаются Z-06, MU-02).

Откат: вернуть Z-09 в blocked и «Гейт владельца».
