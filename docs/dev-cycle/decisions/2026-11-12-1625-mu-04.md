## Вопрос

Дать агентам инструменты истории по сущностям: список коммитов, дифф одного коммита и откат к
версии — без стирания истории.

## Решение

- `GitHistory`: `tracked`, `logPaths`, `diffCommit`, `readAt`, `restoreFile`.
- `src/register/history.ts`:
  - `tasks_history/diff/restore`, `knowledge_history/diff/restore`, `skills_history/diff/restore`;
  - поиск пути через tracked-glob по `project/id` (flat и shard layout);
  - `restore` пишет содержимое из коммита и создаёт **новый коммит** `history: restore …`.
- Инструменты требуют `HISTORY_ENABLED=1`; при выключенной истории возвращают `ok:false`.
- Регистрация в `AppContainer`.

## Почему

- path-level git log/diff переиспользует уже замерженный `GitHistory`, не вводя второй формат истории.
- `restoreFile` — новый коммит, а не `checkout`/`reset`, поэтому параллельные изменения не теряются.
- Glob поддерживает и плоский `tasks/<project>/<id>.json`, и shard `tasks/<project>/<xx>/<id>.json`.

## Ограничения

- DoD называл `*_restore`, но это конфликтует с bulk-only policy; выбраны `*_version_restore`, чтобы не ломать контракт.

- `restore` восстанавливает **все** найденные файлы сущности на текущем пути; при смене shard-пути
  старый файл может быть создан заново, новый останется.
- Skills — это файлы `prompts/<project>/**/<id>@*.json`; отдельного skill-store нет.
- История opt-in; без `HISTORY_ENABLED=1` инструменты отказывают.
- UI-вкладка истории (MU-05) не сделана.
