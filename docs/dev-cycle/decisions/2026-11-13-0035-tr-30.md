## Вопрос

`web-crawler fetch(url)` не ограничивал scheme, private IP, redirect и DNS — SSRF и ingestion произвольного URL.

## Решение

`src/connectors/egress.ts`:

- `assertEgressAllowed`: только http/https, без credentials, блок localhost/`.local/.internal`,
  private IPv4/IPv6, DNS-резолв всех адресов, optional exact `allowedHosts`;
- `safeFetchText`: `redirect: manual`, проверка каждого `Location`, лимит `maxRedirects` (default 5);
- коды `EGRESS_SCHEME/PRIVATE/CREDENTIALS/HOST/REDIRECT/DNS`;
- `WebCrawlerConnector` использует `safeFetchText`; конфиг `allowedHosts`, `allowPrivate`, `maxRedirects`.

## Почему

- Проверка на каждом redirect закрывает классический обход через 302.
- DNS-проверка всех A/AAAA не даёт направить имя на 127.0.0.1.
- `allowPrivate` — только для локальных тестов, по умолчанию false.

## Проверено

  allowlist; redirect→private и redirect-loop; success.

## Ограничения

- DNS rebinding между проверкой и `fetch` не закрыт.
- Нет allowlist портов/CIDR.
- Контент не санитизируется от prompt injection (TR-01).
- `crawlSite` не менялся, кроме проверок в `fetchPage`.

## Откат

Удалить `src/connectors/egress.ts`, вернуть прямой `fetch` в crawler, удалить тест/документацию.
