# 2026-11-03 07:20, Y-09: источник правды это активный провайдер хранения (решение владельца)

Решение владельца: MCP разворачивается с одним из провайдеров хранения, он и есть источник
правды. Моя прежняя рекомендация («файлы остаются источником, индекс производный») отменяется как
общий принцип: она верна только для файлового профиля.

Основание: Y-01 (интерфейсы `Store`, `SearchProvider`, `VectorProvider`, `HistoryProvider`,
`LockProvider`, `BlobProvider`), Y-05/Y-06 (профили SQLite, Postgres), Y-08 (`migrate-storage`),
SC-02 (индекс метаданных при файловом профиле).

Следствия, которые записать в ADR Y-01:

1. В развёртывании один активный профиль; двойной записи в два хранилища нет. В файловом профиле
   источник файлы, SQLite-индекс производный и пересобирается (SC-02, SC-03); в профилях SQLite и
   Postgres источник сама база, файлов задач и знаний на диске нет, экспорт идёт инструментами
   (export/Obsidian).
2. Смена профиля только через `migrate-storage` (Y-08) с dry-run, проверкой целостности и
   откатом; бэкап и восстановление (DX-16) работают по активному профилю.
3. История (MU-03) и lock (MU-01) входят в профиль: файловый профиль использует git и lock-файл,
   SQLite и Postgres используют таблицу версий и транзакции (`HistoryProvider`, `LockProvider` из
   Y-01).
4. Хранилище пользователей (T-01): интерфейс `UserStore` входит в тот же контракт профиля.
   Файловый профиль хранит пользователей в `DATA_DIR/auth.db` (SQLite, исключение: учётные данные
   транзакционные), профили SQLite и Postgres держат их в своей базе. Решение 06:50 по T-01 этим
   уточняется, не отменяется.
5. Y-09 закрывается этим решением; Y-05, Y-06, Y-08 разблокированы по этому гейту (остаются их
   остальные зависимости Y-02, Y-03, Y-05).

Откат: вернуть Y-09 в blocked и пометку «Гейт владельца».
