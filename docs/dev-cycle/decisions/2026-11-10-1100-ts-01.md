# 2026-11-10 11:00 — TS-01: жёсткий потолок воркеров, стабильность флейков, замер RSS

- **Пункт:** TS-01 (high, зависит Q-015/Q-017)
- **Ветка / sha:** `feat/ts-01-vitest-workers`, от `origin/master` `10a39f8` (PR #353 влит)
- **Основание:** BACKLOG TS-01 (72-ядерная машина уходила в OOM), инциденты CI: executable-docs
  timeout, auth-session-stress «server did not become ready», pagination order по mtime.

## Вопрос

Достаточно ли потолка воркеров в `vitest.config.ts`, если `npm test`, `test:coverage` и
`.husky/pre-push` передают свой `--maxWorkers`, и можно ли на Windows воспроизвести «зелёный полный
прогон» из DoD без маскировки платформенных падений?

## Решение

1. **Единственный источник истины — конфиг.** `vitest.config.ts` уже содержит
   `resolveMaxWorkers(cores, env)`: `VITEST_MAX_WORKERS` (валидное ≥1) иначе `min(4, cores/2)`.
   Из `npm test`, `npm run test:coverage` и `.husky/pre-push` убраны жёсткие `--maxWorkers=...`:
   иначе CLI перекрывал формулу (на 2-ядерной машине запускалось 4 воркера). Env-переопределение
   остаётся через конфиг.
2. **Тест-страж** `tests/vitest-limits.test.ts` (5 тестов): потолок на 72/64/16/8/4/2/1 ядрах,
   `VITEST_MAX_WORKERS` и мусорные значения, реальный `config.test.maxWorkers`, и запрет
   `--maxWorkers` в `package.json`/pre-push.
3. **Флейки — по причине, без retry:**
   - `pagination.unit.test.ts`: порядок страницы — mtime desc; фикстура спала 2 мс на элемент и
     зависела от часов ФС → фиксированные `utimesSync` (коммит 3c70065). **20/20 зелёных**,
     медиана 2.1 с.
   - `e2e-full/auth-session-stress.test.ts`: причина — устаревший `dist` (dist-guard) и отсутствие
     stderr в диагностике; после `npm run build` — **20/20 зелёных**, медиана 7.2 с; stderr теперь
     прикладывается к ошибке (3c70065).
   - `executable-docs.test.ts`: один общий скан вместо четырёх спавнов + бюджет 60→180 с (3c70065,
     2026-11-10-0030). На **Windows 20/20 красных** (документы исполняют bash-блоки, которых нет в
     среде) — это платформенное ограничение, CI Linux по этому файлу зелёный.
4. **RSS:** `npx vitest run` без флагов (конфиг даёт 4 воркера на 36 ядрах) — пик суммы RSS дерева
   процессов **1300 МБ** и **1677 МБ** в двух прогонах, оба ≤ 8 ГБ.
5. **Полные прогоны:** на Windows полный `vitest run` остаётся красным — 19 файлов / 75 тестов в
   классах, которые среда не поддерживает (symlink-привилегии, Unix-сокеты, генерация TLS-сертификатов,
   LAN multicast, системный tar, `fs.link`-локи devcycle, bash-блоки executable-docs). **Зелёные полные
   прогоны — CI Linux `bulk-smoke` на #350–#353** (там же `npm test` идёт с конфигом); это записано как
   ограничение среды, а не выдано за локальную зелень.

## Почему

- CLI-флаг в скрипте — скрытый второй источник истины; удаление флага делает поведение одинаковым для
  всех входных точек и сохраняет env-переопределение.
- Флейки чинились причиной (mtime, общий скан, диагностика), а не `retry`/`fileParallelism:false`;
  проверено, что маскировки в конфиге нет.
- Windows baseline перечислен явно, чтобы зелёный CI не смешивался с локальным шумом.

## Проверено

- `tests/vitest-limits.test.ts` — **5/5**; **3 мутации RED**: потолок снят (`cores`), env-переопределение
  выключено, `npm test` снова передаёт `--maxWorkers=4`.
- Флейк-серии: pagination **20/20**, auth-session-stress **20/20** после build; executable-docs —
  **20/20 fail на Windows** (причина и CI-статус записаны); медианы 2.1 с / 7.2 с / 3.0 с.
- RSS: 1300 МБ / 1677 МБ (два прогона, ≤ 8 ГБ).
- `npm run test:types`, build, eslint, markdownlint, `backlog:check` — зелёные; `retry`/`fileParallelism`
  в конфиге отсутствуют.

## Ограничения, записанные честно

- Локальная Windows-зелень полного прогона недостижима из-за платформенных классов; DoD-пункт
  «3 полных зелёных прогона» подтверждён CI Linux (bulk-smoke #350–#353), а не этой машиной.
- executable-docs на Windows детерминированно красный (bash-блоки); это не регресс TS-01.
- `failing files` в Windows-прогоне 19 (75 тестов) — список классов выше, не逐一 перечислен.

## Откат

Revert ветки: возвращаются `--maxWorkers=${VITEST_MAX_WORKERS:-4}` в `package.json`/pre-push и
удаляется тест-страж; конфиг и флейк-фиксы не откатываются (они уже в master). Wire-формат не затрагивается.
