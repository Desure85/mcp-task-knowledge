## Вопрос

Не было единой таблицы «Claude Desktop / Cursor / Windsurf / VS Code / Claude Code / OpenCode»:
какие клиенты реально проверены, а какие только получают конфиг от установщика. Без даты и
разделения «config / protocol / live» статус легко завысить.

## Решение

- `docs/compatibility.md`: колонки Config, Protocol, Live, Last checked, Notes.
- Легенда: `✓` проверено, `✗` попытка заблокирована средой, `?` не проверялось.
- В таблице честно: config-level для Desktop/Cursor/Windsurf/VS Code; Claude Code и OpenCode —
  config-level, live `✗` (Claude CLI не залогинен, OpenCode без MCP-конфига);
  protocol-колонка `?` для GUI-клиентов, потому что реальный `initialize` из их UI не выполнялся.
- Ссылка на таблицу в README; инструкция обновлять при релизе.

## Почему

- `?` и `✗` не дают выдавать размещение файла за подтверждённую совместимость.
- Разделение config/protocol/live показывает, где именно пробел: конфиг, MCP-хендшейк или UI.
- Дата обязательна: клиенты меняют формат конфига.
