## Вопрос

Нужно было проверить, что поле `instructions` реально уходит в `initialize`, непустое, короткое и
содержит живой протокол поиска инструментов; плюс клиентская проба Claude Code/OpenCode.

## Решение

Код не менялся: CM-03a уже добавил `src/core/server-instructions.ts` и проводку в
`defaultRegistration`, HTTP/TCP/Unix-сессии и bridge. Закрытие фиксирует протокольный контракт и
честный результат клиентской пробы.

- `toolDomains` группирует имена по ведущему namespace; `buildServerInstructions` генерирует
  6 строк (лимит 15) с числами из реестра.
- `Client.getInstructions()` на живом stdio-сервере вернул 6 строк, 155 инструментов, 25 доменов;
  `tests/server-instructions.test.ts` сверяет каждый домен и его count с `ctx.toolRegistry`.
- `docs/features/server-instructions.md` — вывод и ограничения.

## Клиентская проба

В чистом `HOME` (`USERPROFILE` тоже) без проектного скилла:

- `claude -p 'Reply with the exact first line…'` → exit 1, `Not logged in · Please run /login`;
- `opencode run '…'` → exit 0, ответ `NONE`; лог показывает, что он прочитал
  `.config/opencode/opencode.jsonc`, но MCP-сервер там не настроен.

Обе CLI не дали модели подключённый сервер, поэтому видимость instructions в модели **не
подтверждена**. Это не «клиент не показывает», а отсутствие аутентифицированной MCP-сессии; CM-03b
помечен blocked, CM-04/CM-06 остаются усилителями. CM-03 закрывается на протокольном контракте.

## Почему

- Приватное поле `_instructions` — единственный доступный путь в SDK без пересоздания McpServer
  после регистрации; тест через настоящий Client ловит поломку при апгрейде.
- Лимит 15 строк и генерация из реестра не дают инструкции устареть при добавлении инструментов.
- Клиентская проба без сервера ничего не доказывает; записывать её как pass было бы нечестно.
