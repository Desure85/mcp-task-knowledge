# 2026-11-10 11:30 — DX-11: runtime health-gate в `doctor`

- **Пункт:** DX-11 (`doctor`: Node ≥20, DATA_DIR, конфиг, порт, клиентский конфиг; health-gate для setup)
- **Ветка / sha:** `feat/dx-11-doctor-health`, от `origin/master` `1c6897f` (PR #354 влит)
- **Основание:** BACKLOG DX-11, существующий `src/cli/doctor.ts` (данные/схема/индексы/профиль)

## Вопрос

Какие runtime-проверки должен давать `doctor`, чтобы «здоровье» установки было видно до запуска
сервера, и как переиспользовать тот же гейт в `setup`, которого пока нет?

## Решение

1. Новый `src/cli/health.ts` с инъектируемым `runHealthGate(options)`:
   - **node** — major `process.versions.node` ≥ 20;
   - **data-dir** — существует и writable (`fs.access(W_OK)`), отсутствие — ошибка;
   - **config** — `reloadFileConfig()`: валидный файл/`MCP_CONFIG_JSON` — ok; **отсутствие** файла —
     тоже ok (env/дефолты — штатный путь); сломанный JSON — ошибка;
   - **port** — при `MCP_TRANSPORT=http` или явном `MCP_PORT` проверяется реальная занятость
     (`net.createServer.listen` на 127.0.0.1), busy → ошибка; для stdio — «not applicable» warning;
   - **clients** — известные пути Claude Desktop (APPDATA/Library/.config), Cursor `~/.cursor/mcp.json`,
     проектный `.mcp.json`; среди `mcpServers` ищутся записи вида `mcp-task-knowledge`, у команд
     проверяется существование пути/скрипта. Отсутствие конфигурации — **warning**, не ошибка
     (клиенты опциональны); `url`-записи не пробуются по сети (offline-честность).
2. `doctor` получил секцию `health` в JSON и строку `Health: …` в тексте; неуспешные checks попадают
   в `issues` с уровнем из check (node/data-dir/config/port — error, clients — warn).
3. Гейт экспортирован как `runHealthGate` для будущего `setup` (DX-10): setup-команды в репозитории
   пока нет, поэтому «в конце setup» — зафиксированное ограничение, а не сделанная интеграция.

## Почему

- Проверки с инъекцией параметров (версия, порт, пути конфигов, reloadConfig) тестируются без
  зависимости от машины и не занимают реальные порты в CI.
- Отсутствие файла конфигурации не должно превращать нормальную установку в «больную»: сервер
  штатно живёт на env/дефолтах.
- Клиентский конфиг — подсказка, а не блокер: пользователь может ставить сервер до настройки клиента.

## Ограничения, записанные честно

- `setup` (DX-10) ещё не реализован: гейт экспортирован, но в конце setup не вызывается — это
  записанный follow-up DX-10, а не выполненная интеграция.
- Liveness клиентского конфига проверяется статически (путь бинаря/скрипта); `npx`-пакеты и `url`
  записи не пингуются — offline-проверка, без сетевых побочек.
- Известные пути клиентов ограничены Claude Desktop/Cursor/проектным `.mcp.json`; другие клиенты —
  расширение списка в DX-10.

## Откат

Revert ветки: удаляются `src/cli/health.ts`, тест и секция `health` в `doctor`; остальные проверки
доктора не меняются. Wire-формат и серверный код не затрагиваются.
