# 2026-11-10 17:00 — CM-03a: серверные `instructions` (генерация + wiring)

- **Пункт:** CM-03a (часть CM-03, high)
- **Ветка / sha:** `feat/cm-03-server-instructions`, от `origin/master` `0991d53` (PR #360 влит)
- **Основание:** BACKLOG CM-03; MCP `initialize.instructions`; живой `ToolRegistry`

## Вопрос

Можно ли отдавать клиенту короткую инструкцию сервера в `initialize`, сгенерированную из **живого**
реестра инструментов (домены и числа — не хардкод), и доказать это протокольным тестом?

## Решение

- `src/core/server-instructions.ts`:
  - `toolDomains()` группирует имена по префиксу (`tasks_list` → `tasks`, `mcp.authenticate` → `mcp`);
  - `buildServerInstructions()` даёт ≤15 строк: число инструментов/доменов, протокол
    `tools_list search` → `tool_schema` → `tools_run`, `tools_batch`, строку доменов с числами;
  - `setServerInstructions()` пишет в низкоуровневый `_instructions`, который читает `initialize`
    (публичного setter у SDK нет — это зафиксировано в коде).
- Wring: `defaultRegistration()` выставляет инструкцию после регистрации всех инструментов; TCP/Unix и
  HTTP per-session серверы берут её из `serverCtx.toolRegistry`; bridge получает короткий текст о
  форвардинге (своего реестра у него нет).
- Полная инструкция/профили — по-прежнему AA-08; здесь только проверяемая часть, поверхность
  инструментов не сокращается.

## Почему

- Инструкция должна отражать **реальный** реестр: ручной список доменов неминуемо разойдётся с
  регистрацией, а тест на «удаление домена» это ловит. Поэтому счётчики берутся из
  `toolRegistry.list({limit:300})`, а не из констант.
- SDK не даёт публичного setter, но `initialize` читает `_instructions` низкоуровневого сервера;
  запись после регистрации — единственная точка, где реестр уже полон, а поле ещё можно выставить.
- TCP/HTTP создают отдельный per-session McpServer, который обрабатывает `initialize`; без явного
  переноса текста туда клиент не увидел бы инструкцию на этих транспортах.

## Проверено

- `npx vitest run tests/server-instructions.test.ts` — **4/4**, включая живой
  `Client.getInstructions()` после `createServerContext()` + `defaultRegistration()`: непустая,
  ≤15 строк, протокол на месте, для каждого домена из `toolRegistry.list({limit:300})` в тексте есть
  `${domain} ${count}`.
- **3 мутации RED**: из генератора выпадает один домен; инструкция не выставляется (пустая);
  генератор отдаёт >15 строк.
- `tsc`/build чистые.

## Не сделано и почему (честно)

Живая проба **Claude Code** и **OpenCode** не получена в этой среде: обе CLI установлены
(`claude 2.1.319`, `opencode 1.19.5`), но `claude -p` зависает и на простом запросе (45 c), и на
MCP-пробе (180 c) — рабочей agent-сессии/авторизации нет. Поэтому CM-03 **не закрывается**: добавлен
CM-03b «проба клиентов в чистой сессии», а CM-03a фиксирует реализацию и протокольное доказательство.
Если в целевой среде клиент не покажет инструкцию — это будет записано как вывод и усилит CM-04/CM-06,
как и предусмотрено DoD.
