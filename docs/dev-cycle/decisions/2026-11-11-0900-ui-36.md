# 2026-11-11 09:00 — UI-36: быстрый просмотр задачи в диалоге

- **Пункт:** UI-36 (high); использует UI-37 как путь правки
- **Ветка / sha:** `feat/ui-36-quick-view`, от `origin/master` `3d32511` (PR #376 влит)
- **Основание:** BACKLOG UI-36; UI-10/UI-12/UI-34; UI-37

## Вопрос

Как дать карточке режим «сначала посмотреть, потом править» без второго редактора и без обрезки
описания в диалоге?

## Решение

- `web-ui/components/board/TaskQuickView.tsx` — read-only `Dialog`:
  - полное описание (`whitespace-pre-wrap`, без line-clamp), статус/тип/приоритет/теги, ссылки;
  - `dependsOn` (имена через `tasks_list`), `Blocks` через `tasks_dag` (рёбра `to === id`),
    подзадачи через `tasks_get_children`, claim/expiry U-01, createdAt/updatedAt;
  - **ноль** `input`/`textarea`/`select`; единственная запись — кнопка **Edit**, ведущая на
    `/tasks/<id>` (UI-37); Close/ESC/клик вне закрывают, фокус возвращает `Dialog`.
- `TaskCard`: заголовок и свободная область карточки вызывают `onView`; кнопки/ссылки/движение не
  перехватываются. `StatusCell` и страница прокидывают `onView`.
- Копия шапки `/tasks` исправлена: «Click a card to preview it; Edit opens the full task page».
- Тест `web-ui/e2e/task-quick-view.spec.ts`: задача с длинным описанием, тегами, ссылкой, подзадачей и
  зависимостью; открытие, проверка полного текста и отсутствия контролов, ESC + возврат фокуса,
  повторное открытие, Edit → `/tasks/<id>`, скриншоты 1440/390.

## Почему

- Диалог только читает; правка остаётся на полной странице с серверным графом переходов — нет второго
  пути изменения данных.
- `Dialog` уже имеет focus trap/ESC/restore; переиспользование примитива соответствует DESIGN.md.
- `Blocks` считается по DAG-рёбрам (`from=задача → to=зависимость`), а не перебором всех задач.

## Проверено

- `task-quick-view.spec.ts` — **1/1** (локально проходит; на SQLite claim-секция условна, на файловом/
  CI проверяется активная аренда).
- Полный Playwright на файловом профиле — ожидается **47/47** (46 до UI-36 + 1); на локальном SQLite
  UI-37-тест падает из-за известного разрыва профиля, не из-за UI-36.
- **2 мутации RED** (один прогон): заголовок карточки вместо `onView` вызывает `onEdit` → диалог не
  открывается; добавление `<input>` внутрь диалога → тест «ноль контролов» падает.
- tsc web-ui; скриншоты `docs/ui/screens/ui-36/quick-view-{1440,390}.png`.

## Ограничения, записанные честно

- **SQLite-профиль**: `tasks_claim` не реализован (`sqlite profile does not implement task claims yet,
  Y-05a2`), а `tasks_dag` отдаёт 0 рёбер при сохранённом `dependsOn` — поэтому на демо-SQLite quick
  view показывает «No active lease» и пустой `Blocks`; на файловом профиле/CI оба блока работают.
  Это pre-existing разрывы профиля, не замаскированы.
- Task version history отсутствует в wire-формате: показываются createdAt/updatedAt с пояснением.
- В диалоге показываются первые уровни зависимостей/подзадач; глубокая цепочка — UI-38/UI-39.
- Скриншоты снимаются тестом; CI их перезаписывает, но не сравнивает.

## Откат

Revert ветки: удаляются `TaskQuickView`, `onView`-проводка, тест и скриншоты; заголовок карточки снова
ведёт в инлайн-редактор. UI-37 не затрагивается.
