## Вопрос

Шаблоны задач с полями по умолчанию; повторяющиеся задачи без дублей после перезапуска; двусторонние
ссылки задача↔документ (сейчас `links` односторонние).

## Решение

- `task-templates.json`: `{id,name,defaults:{description,priority,type,tags,links}}`; CRUD.
- `task-recurring.json`: `{id,project,title,templateId?,schedule,nextAt,createdKeys[]}`;
  schedule daily/weekly/monthly (UTC time).
- `tasks_recurring_tick({now?})` создаёт по одному экземпляру на occurrence, ключ `${id}:${nextAt}`;
  повторный вызов/рестарт не плодит дубли (createdKeys, ≤200).
- `Task.relatedDocIds`, `KnowledgeDocMeta.relatedTaskIds`; `task_document_links_set` синхронизирует обе стороны,
  `task_document_links_get` читает по taskId/docId.

## Почему

- Tick вместо таймера: сервер может не работать постоянно; детерминированный вызов безопасен и тестируем.
- Ключ идемпотентности строится из времени occurrence, а не «сейчас».
- Двусторонние ссылки — два массива id, без новой схемы.

## Ограничения

- Фонового планировщика нет: tick должен вызывать внешний cron/агент.
- Monthly ограничен 1..28 (нет 29–31).
- Нет UI шаблонов/повторяющихся/ссылок.
- Удаление документа не вычищает `relatedDocIds` у задач.
