## Вопрос

Можно ли реализовать и проверить двустороннюю синхронизацию с YouTrack в этой среде?

## Решение

Оставить **blocked** с явной причиной: INT-007 — read-only коннектор, записываемого токена/инстанса
YouTrack нет. Без записи нельзя проверить циклическую синхронизацию, идемпотентность и конфликты.

## Почему

- DoD требует живой трекер: «циклическая синхронизация не плодит дубли и не зацикливается».
- Мокать обе стороны и объявлять done — значит выдать непроверенное за сделанное.

## Проверено

- В BACKLOG INT-008 остаётся `blocked`, причина дополнена `[env]`.
- Закрытые зависимости: INT-007 (read-only), MU-02 (version/CAS).
- `backlog:check` — 392 done / 0 pending / 28 blocked / 1 deferred.

## Откат

Убрать `[env]`-причину и вернуть задачу в pending, когда появится записываемый трекер.
