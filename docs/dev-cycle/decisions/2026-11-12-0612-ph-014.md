## Вопрос

Нужен e2e поверх WS relay + `resources/*` + `prompts/get`. Проверка выявила реальный дефект:
на свежем DATA_DIR `registerMcpPrompts` вызывался **до** DX-14 seed, поэтому `prompts/list`
возвращал `[]`, а сиды появлялись только после рестарта.

## Решение

- `registerMcpPrompts(ctx)` перенесён из `defaultRegistration` в `AppContainer.init` **после**
  `seedPromptsIfEmpty` и `triggerPromptsReindex`; в `defaultRegistration` оставлен комментарий.
- `tests/protocol-surface.test.ts`: реальный stdio — `tasks_create`, `resources/list`,
  `resources/read` `tasks://current` (созданная задача в JSON), `prompts/list` (непустой),
  `prompts/get` первого промпта.
- WS relay с реальным пиром уже покрыт `tests/realtime.spec.ts` (два WebSocket, broadcast);
  новый тест его не дублирует.

## Почему

- Регистрация MCP prompts — snapshot каталога на старте; до seed каталог пуст.
- Перенос после seed не меняет wire-формат, только порядок инициализации.
- Один e2e проверяет три protocol-метода на настоящем сервере, а не мок.

## Проверено

- `tests/protocol-surface.test.ts` — **1/1** (~3.4 s), реальный dist.
- **Мутация RED:** убрать вызов `registerMcpPrompts` → `prompts/list` пуст, тест падает;
  восстановление 1/1, build чистый.
- `npm run build`, `npm run test:types` — чисто.
- backlog:check **372/26**.

## Ограничения

- `prompts/get` проверен на первом сиде с аргументом `demo`; шаблоны с обязательными enum не
  перебираются.
- Ресурсы проверены только `tasks://current`; шаблоны `tasks://project/{id}` и knowledge не входят.
- WS relay проверен существующим `realtime.spec.ts`, а не отдельным новым тестом с сервером+клиентом.
- Регистрация промптов по-прежнему snapshot: новые промпты до рестарта не видны (SPEC-04).

## Откат

Вернуть `await registerMcpPrompts(ctx)` в `defaultRegistration` и убрать вызов после seed;
удалить `tests/protocol-surface.test.ts`. Промпты на свежем старте снова будут пустыми.
