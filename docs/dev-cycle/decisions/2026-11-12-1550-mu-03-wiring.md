## Вопрос

Подключить `GitHistory` к записи задач/документов/промптов и жизненному циклу, чтобы операции
попадали в историю одним пакетным коммитом, а не отдельным O(N) коммитом.

## Решение

- `src/history/service.ts`: process-wide `GitHistory`, `initHistory`/`closeHistory`,
  `enqueueHistory` (relative to `DATA_DIR`), author из `currentSessionId()`.
- `AppContainer.init()` → `initHistory()`, `stop()` → `closeHistory()`.
- Задачи: `updateTaskUnlocked` после записи; документы: `createDoc`/`updateDoc` после записи;
  промпты: `prompts_bulk_create`/`prompts_bulk_update` после записи.
- `GitHistory.setAuthor` фиксирует автора на момент enqueue; flush использует его.
- История отключена в `NODE_ENV=test` и `HISTORY_ENABLED=0`; `HISTORY_ENABLED=1` включает.

## Почему

- Один сервис на процесс исключает гонку нескольких экземпляров.
- Enqueue после успешной записи + durable queue даёт восстановление после падения.
- Автор на enqueue сохраняет сессию даже если flush произошёл позже.

## Ограничения

- Промпты: подключены только bulk create/update; provenance/build/sources пишут мимо очереди.
- `currentSessionId` — id сессии, не userId; git-author имеет вид `ses <ses@session>`.
- No-git ветка не покрыта тестом (WARN + disabled по коду).
- Dirty-tree recovery на первом включении может закоммитить весь существующий `DATA_DIR` (baseline).
- `HISTORY_ENABLED` по умолчанию выключена в тестах, включена вне test.

## Откат

Удалить `src/history/service.ts`, вызовы `initHistory`/`closeHistory`/`enqueueHistory`; ядро
`GitHistory` оставить или удалить отдельным revert.
