# 2026-11-10 13:00 — DX-10: `mcp-task-knowledge setup`

- **Пункт:** DX-10 (`setup` — интерактивный установщик клиентов)
- **Ветка / sha:** `feat/dx-10-setup`, от `origin/master` `68b896b` (PR #356 влит)
- **Основание:** BACKLOG DX-10 (deps AUD-01/AUD-03 done), DX-11 health gate, ADR-009

## Вопрос

Как поставить `mcp-task-knowledge` в существующие MCP-клиенты одной командой, не затирая чужие
`mcpServers` и не выдавая «настроено» без проверки, что сервер реально отвечает `tools/list`?

## Решение

1. `src/cli/setup.ts`:
   - **детект клиентов** по путям: Claude Desktop (APPDATA/Library/.config), Cursor
     (`~/.cursor/mcp.json`), Windsurf (`~/.codeium/windsurf/mcp_config.json`), VS Code
     (`<cwd>/.vscode/mcp.json`, ключ `servers` + `type`), Claude Code (`~/.claude.json`);
   - **ответы**: transport (stdio/http), DATA_DIR, опциональный token; интерактивно по умолчанию,
     `--client X --yes` — для CI; `--transport`, `--data-dir`, `--server-url`, `--token`;
   - **идемпотентный merge**: сохраняет чужие записи и неизвестные ключи; при изменении — бэкап
     `<file>.bak-<ISO>` и атомарная запись (tmp+rename); повторный запуск даёт `unchanged` без
     нового бэкапа;
   - **self-check**: реальный спавн stdio (`initialize` → `initialized` → `tools/list`), счёт
     инструментов; в live-прогоне — **129 tools**; probe использует временный DATA_DIR, чтобы не
     оставить `.server.lock` в каталоге пользователя, и корректно завершает процесс по EOF;
   - **health gate** DX-11 в конце: DATA_DIR создаётся до проверки, health-модуль импортирует
     config только после выбора каталога (setup запускается без `DATA_DIR`).
2. `src/index.ts`: `setup` добавлен в CLI-диспетчер до `AppContainer`; текстовый вывод/коды 0/1/2.
3. `src/cli/health.ts`: статический импорт `config.js` заменён динамическим внутри
   `runHealthGate`, чтобы setup мог работать до конфигурации DATA_DIR.

## Почему

- Один merge-путь с глубоким сравнением JSON — единственный способ не дублировать записи и не
  ломать чужие MCP-серверы; бэкап обязателен, потому что клиентский конфиг — пользовательский файл.
- Self-check проверяет именно протокол (`tools/list`), а не «файл записан»; probe в temp-DATA_DIR
  исключает ложные блокировки при повторной установке.
- `--yes` делает установку пригодной для CI и автотестов, где интерактив невозможен.

## Проверено

- `tests/dx10-setup.test.ts` — **8/8**: детект пяти клиентов и ключей `servers`; merge сохраняет
  чужие записи и делает бэкап; повторный merge — `unchanged` без бэкапа; VS Code `type:stdio`;
  http-entry с Bearer и ошибка без URL; `--yes` пишет entry и вызывает health-gate; ошибки
  http/unknown client; self-check с фейковым stdio-сервером; timeout.
- **4 мутации RED**: merge перестаёт быть идемпотентным; бэкап не создаётся; VS Code пишет в
  `mcpServers`; self-check засчитывает ответ с 0 инструментов.
- **Live**: `node dist/index.js setup --client cursor --yes --data-dir …` →
  `✓ 129 tools (stdio self-check passed)`, `Health: ok`, exit 0; повторный запуск —
  `cursor: unchanged` (бэкап не плодится).
- `tsc` test-проекта/build чистые; eslint/markdownlint/`backlog:check` — на PR.

## Ограничения, записанные честно

- Self-check проверяет **собранный `dist/index.js`**, а не `npx -y mcp-task-knowledge` из entry:
  сетевой fetch пакета в self-check не выполняется. Это проверка сервера, а не registry-доставки.
- Интерактивный режим минимален (transport/DATA_DIR; выбор клиентов — авто по детекту или
  `--client`); расширенные вопросы (auth-режим, порт) — при необходимости отдельным инкрементом.
- Известные пути клиентов ограничены пятью; Claude Code использует `~/.claude.json`, проектный
  `.mcp.json` не трогается.

## Откат

Revert ветки: удаляются `src/cli/setup.ts`, диспетчер `setup`, тест; health-модуль возвращается к
статическому импорту config (доктор от этого не зависит). Клиентские конфиги, записанные setup,
остаются — их откатывает бэкап `<file>.bak-*`.
