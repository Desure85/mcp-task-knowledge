## Вопрос

`benchmarks/` не подключены к CI, пороги не нормированы, максимальный датасет и memory
ceiling не задокументированы.

## Решение

Первый тезис пункта устарел: weekly `scale-bench.yml` уже запускает 100k seed,
`run-scale` и `gate-scale` (2× baseline + абсолютные caps). Добавлено недостающее:

1. **RSS ceiling**: `gate-scale.evaluateGate` проверяет `rssAfterLoadMb`; baseline cap
   **3072 MB** (измерено 2.1–2.2 GB после нагрузки на 100k).
2. **`docs/benchmarks/capacity-budgets.md`**: enforced budget, recommended max 100k,
   1M не валидирован, что не в CI и почему, как обновлять baseline, ограничения.
3. `scripts/bench/README.md` больше не утверждает «не входит в CI»; gate-тесты переведены
   на CLI-контракт (файловый `--out`, без захвата pipe), 3/3.

## Почему

- 100k уже проверяется; не хватало memory-потолка и честного описания пределов.
- 1M в отчёте 2026-10 — заглушки + экстраполяция, а не замер; выдавать его за поддержку нельзя.
- CLI-тест не зависит от Vite-трансформации `.mjs` и проверяет то, что реально гоняет CI.

## Ограничения

- 1M не измерен на реальном ext4 с memory ceiling; рекомендация — 100k.
- UI/graph/sqlite-index бенчмарки остаются вне CI (браузер/время/данные).
- Gate смотрит медиану, не p95; один GitHub runner, разброс 2–6×.
- RSS берётся из `/proc/<pid>/status`, не cgroup.
