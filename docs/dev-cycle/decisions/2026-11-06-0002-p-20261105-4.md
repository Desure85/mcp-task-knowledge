# 2026-11-06 — P-20261105-4: пропуск proxy-образов в docker-build-base сохранён, но проверяется

Основание: инцидент 2026-10-30..11-05 — после перехода на Node 24 `ghcr.io/desure85/mcp-node:24-bullseye` ни разу не публиковался, потому что на push proxy-джобы пропускались слепо (один run-шаг с `exit 0` и условие `steps.skip-check.conclusion != 'success'` на всех следующих шагах); 6 base-джоб падали с `not found` в прогоне 42070606130, лечилось ручным `workflow_dispatch` (42083930937 — 11 джоб зелёные). Решение владельца: пропуск сохранить, базовые на push не ускорять, `max-parallel` и триггеры не менять (BACKLOG, PH-016; пересечение по смыслу с DX-31 «опубликовать mcp-node:24-*»).
Решение: в `.github/workflows/docker-build-base.yml` логин в GHCR и `docker buildx imagetools inspect` выполняются до решения о пропуске. Образ есть → proxy-джоба зелёная без сборки, как раньше. Образ отсутствует (`not found`/404) → джоба собирает и публикует proxy на этом push. Любая другая ошибка проверки (права, сеть, 5xx) → джоба падает с `::error::` и подсказкой запустить `workflow_dispatch`, а не зеленеет. Для `workflow_dispatch` поведение не менялось (собирается всё); `max-parallel`, триггеры, матрица, теги, build-args и пины actions по SHA не тронуты.
Почему: слепой пропуск переносил отказ на 6 base-джоб и маскировал его зелёным статусом proxy-джоб; проверка наличия сохраняет экономию на push, но не даёт ловушке вернуться при следующей смене тега базового образа.
Проверено: actionlint — 0 замечаний на изменённом файле (на версии master тоже 0); разбор YAML (7 шагов, условия как задумано); встроенный блок прогнан на заглушке `docker` в трёх сценариях: образ есть (exit 0, `present=true`, сборка пропущена), 404 (exit 0, `present=false`, сборка), прочая ошибка 403 (exit 1, два `::error::`); `npm run lint:md`, `npm run backlog:check` (402/277/5/96/23/1). Боевой прогон не запускался — его делает контролёр после мержа.
Откат: revert PR.
