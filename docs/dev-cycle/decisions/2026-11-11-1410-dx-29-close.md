`admin_setup_link`, API-клиент и UI на `/access` уже реализованы. Нужно было проверить сквозной путь

## Решение

Нового кода нет. Пункт закрыт по evidence:

- **Ядро:** `SetupLinkStore` — UUID OTP, TTL 15 мин, одноразовый `redeem`, `maxFailedAttempts` с
  инвалидацией, scoped JWT (project+role+exp), audit `setup_link.create`/`setup_link.redeem`,
  `buildSetupMarkdown` с server/transport/default project/role/TTL/capabilities/token и stdio-вариантом
  (`npx -y mcp-task-knowledge` + env).
- **Backend:** `POST /admin/setup-links` (admin-only), `GET /.well-known/mcp-setup/<otp>` (one-time,
  410 на повтор), MCP-инструмент `admin_setup_link` для админов без Web UI, `api.admin.setupLink`.
- **Web UI:** `/access` — форма project/role/TTL/baseUrl, список последних ссылок.

## Проверено

## Ограничения

- OAuth DCR как альтернатива не реализовывалась: setup-link остаётся основным путём; DCR не оценивался
  отдельным ADR (в BACKLOG это было «оценить при дизайне»).
- Setup-link store in-memory; перезапуск сервера инвалидирует выданные, но ещё не полученные ссылки.
- UI не имеет отдельного e2e на генерацию ссылки; живая проба выполнена через MCP-инструмент.
- `npx`-сниппет генерируется, но не проверяется установкой пакета в чистом окружении.
