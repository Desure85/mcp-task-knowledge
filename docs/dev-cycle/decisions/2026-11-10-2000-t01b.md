## Вопрос

Как дать администратору управлять пользователями и личными токенами через MCP, не показывая
plaintext-токены в списках, и как подключить личные токены к существующему `AuthManager`, не ломая
JWT/static-валидаторы?

## Решение

- `src/register/users.ts` — восемь admin-инструментов:
  `admin_users_list`, `admin_user_create`, `admin_user_set_password`, `admin_user_set_roles`,
  `admin_user_disable`, `admin_tokens_list`, `admin_token_create`, `admin_token_revoke`.
  - на authenticated-транспортах требуется роль `admin` (роли берутся из metadata сессии);
  - на локальном stdio без `authManager` процесс уже доверенный — разрешено (как остальной local-only
    surface);
  - `admin_token_create` возвращает raw-токен **один раз**; списки отдают только prefix/metadata.
- `src/auth/user-token-validator.ts` — `createUserTokenValidator(store)` + `composeTokenValidators`.
  Личный токен проверяется первым, затем прежний JWT/static/TokenManager-валидатор; отзыв/истечение/
  disabled обрабатываются в `UserStore.verifyToken`.
- `AppContainer.buildDefaultValidator()` оборачивает базовый валидатор через `withUserTokens()`, когда
  в контексте есть `userStore`; регистрация admin-инструментов добавлена в `defaultRegistration`.

## Почему

- Отдельные MCP-инструменты не требуют web-UI для первичного управления и тестируются без браузера.
- Композиция «personal-first, fallback-second» сохраняет все существующие способы входа и не делает
  личные токены особым случаем в `AuthManager`.
- Admin-check на уровне инструментов, а не только UI, закрывает обход через прямой MCP-вызов.

## Проверено

- `tests/admin-users.test.ts` — **5/5**: регистрация 8 инструментов, создание/список/роли,
  токен возвращается один раз, список без plaintext, revoke, non-admin deny, missing store, валидатор
  , fallback, revoke → null.
- **3 мутации RED**: admin-check отключён; fallback-валидатор не вызывается; токен не возвращается
  при создании.
- build/tsc чистые; eslint/markdownlint/`backlog:check` — в PR.

## Ограничения, записанные честно

- Web-админка (страница управления пользователями/токенами) **не сделана** — вынесена в T-01c.
- Роль admin на stdio не проверяется (доверенный локальный процесс) — это осознанное правило, не
  забытый guard.
- `admin_token_create` с `expiresAt` ожидает ISO; невалидная дата отклоняется `UserStore` с понятной
  ошибкой.
