# 2026-11-07 08:47 — web-ui: единая высота контролов доведена до кода

## Вопрос

Коммит `92ca1d6` в `master` утверждает «единая высота контролов» и правит только `CHANGELOG.md`:
код правки (поля 32px как `Button` md, `Topbar` 28px, `md` у кнопок в таблицах настроек) остался
незакоммиченным в рабочем дереве владельца. Нужно решить: приземлить этот код как есть, или
перепроверить его как чужую работу и исправить найденное.

## Решение

Код приземлён; патч перепроверен и исправлен в двух местах, где «одна высота в строке» не
выполнялась:

1. `web-ui/components/settings/StatusesTab.tsx`, `TypesTab.tsx` — стрелки порядка (`↑`/`↓`)
   переведены из `size="sm"` (28px) в `md` (32px). Патч поставил их в один ряд, но оставил
   меньше остальных контролов строки таблицы: в одном `<tr>` было 28px против 32px у
   `Input`/`Select`/`Delete`.
2. `web-ui/components/ui/Field.tsx` — текстовый input внутри `ColorField` получил ту же
   константу `SINGLE_LINE`, что `Input`/`Select`. Свотч `ColorField` — 32px, а текстовое поле
   рядом оставалось 28px: одна и та же «однострочная» роль имела две высоты.
3. `web-ui/lib/design-guards.test.ts` — новый страж 4: высота `Button` size md и константа
   полей сравниваются между собой (инвариант, не пиксель), константа обязана стоять на трёх
   однострочных полях и не попадать на `Textarea`.

`Textarea` и `Select multiple`/`size>1` не затронуты: фиксированной высоты не получают, мультиселекта
в UI нет.

## Почему

- DESIGN.md §2.1 разрешает контролы 28–32px, но §2.1 же задаёт плотность строки 32px, а `Button`
  md — 32px. Смешивать 28 и 32 в одной строке таблицы значит повторять исходный дефект («Search
  в Memory выделялся»), только на 4px меньше. Альтернатива — оставить стрелки 28px и считать их
  «отдельной колонкой» — отвергнута: измерение показывает их в одной визуальной строке с полями.
- `ColorField` — не декоративный свотч, а однострочный контрол: по DESIGN §4.5.1 это «свотч и
  текстовое поле». Разная высота внутри одного примитива — тот же класс дефекта.
- Коммит `92ca1d6` с одним `CHANGELOG.md` — процессный сбой: запись в CHANGELOG ушла без кода.
  Запись здесь фиксирует, что CHANGELOG-строка теперь соответствует коду.

## Проверено

Измерение `getBoundingClientRect().height` в реальном Chrome (`playwright-core`, viewport
1280×900) по шести вариантам темы (indigo/petrol/copper × light/dark), production-сборка Next 16
(`next build` + `next start`), страницы `/memory`, `/knowledge`, `/prompts`, `/projects/settings`
(statuses/types/transitions), `/tasks`, `/themes?action=create`. Сводка (до → после, px):

| Строка | До (`origin/master` 9118388) | После |
|--------|------------------------------|-------|
| Memory: `Input` «Search facts» / `Button` Search / Reset | 28 / 32 / 32 | 32 / 32 / 32 |
| Knowledge: Search / Tag / Type | 28 / 27 / 27 | 32 / 32 / 32 |
| Prompts: Search / Status | 28 / 27 | 32 / 32 |
| Settings, строка статуса: Name / Category / Colour / Initial / Archived / Delete | 28 / 27 / 27 / 28 / 28 / 28 | 32 везде |
| Settings, строка статуса: стрелки порядка | 28 (в столбик) | 32 (в ряд) |
| Settings, строка типа: Name / Colour / Icon / Delete | 28 / 27 / 27 / 28 | 32 везде |
| Topbar: project label / Auth / Sign out против Realtime и Theme (28) | 26.5 / 26.5 / 26.5 | 28 / 28 / 28 |
| `/themes`: свотч / текстовое поле `ColorField` | 32 / 28 | 32 / 32 |

`Δ = 0` во всех шести вариантах темы для всех перечисленных строк. Отдельно измерена
промежуточная фаза «только сохранённый патч»: она ещё давала `Δ 4` на строке статуса
(`button:28` у стрелок против `32` у остальных контролов) и `Δ 4` на каждой строке
`ColorField` (`32/28`). Это и есть доказательство, что две правки выше — не полировка, а
закрытие реальных расхождений; финальная фаза даёт `Δ 0` в тех же строках. Остались расхождения вне
скоупа: `/tasks` — нативный `input[type=checkbox]` 14px рядом с кнопкой 28px (`TypeMultiSelect`,
известный долг UI-16, примитива Checkbox нет); нативный `select` внутри подписи проекта в Topbar
имеет 16px — это внутренний элемент 28px-оболочки, а не отдельный контрол.

Стражи и сборки: `npx tsc --noEmit` (0 ошибок), `npx vitest run` в `web-ui`, `npm run build` в
`web-ui`, `npm run design:doc -- --check` (без диффа), корень — `npm run build`, `npm run
test:types`, `npm run lint:md`, `npm run backlog:check`. Revert-check стража 4: без
`SINGLE_LINE` в `ColorField` тест падает (`expected 2 to be 3`), с исправлением — зелёный.

## Откат

`git revert` этого коммита: возвращает поля к 27–28px и стрелки к `size="sm"`, страж 4 исчезает
вместе с файлом. Точечно — убрать `SINGLE_LINE` из `ColorField` и вернуть `size="sm"` двум
стрелкам в обеих вкладках настроек. `CHANGELOG.md` и строка про высоты при откате остаются
неверными, поэтому откат кода обязан сопровождаться откатом записи CHANGELOG.
