# 2026-11-11 05:00 — UI-12b: offline/empty разграничение и возврат после истёкшей сессии

- **Пункт:** UI-12b (часть UI-12, high); UI-12 закрыт вместе с UI-12a
- **Ветка / sha:** `feat/ui-12b-states`, от `origin/master` `f73c88e` (PR #372 влит)
- **Основание:** BACKLOG UI-12; UI-12a (loading/not-found/login-баннер)

## Вопрос

Как гарантировать, что при недоступном MCP на каждом из 11 маршрутов видно ошибку и «Повторить», а
не пустое состояние, и что истёкший JWT возвращает пользователя на исходный `next` после логина?

## Решение

- `AppShell` получил третье состояние `error`: если первичный probe `api.projects.list()` падает
  не-auth ошибкой, shell рендерит **одно** сообщение «Server unavailable» с кнопкой **Retry** и не
  рендерит children — страницы не показывают пустые состояния одновременно с ошибкой. Retry
  увеличивает `probeNonce`, эффект повторяет probe.
- `AUTH_EXPIRED_EVENT` больше не перезаписывает уже начатый переход: если shell уже на `/login`,
  повторный auth-fail от Topbar игнорируется. Раньше Topbar успевал вызвать `toLogin(true)` после
  первого перехода и терял `next`, оставляя только `expired=1`.
- `web-ui/e2e/states.spec.ts`:
  - 11 маршрутов (`/`, `/tasks`, `/knowledge`, `/prompts`, `/search`, `/analytics`, `/graph`,
    `/memory`, `/projects`, `/system`, `/access`) с `page.route('**/mcp**', abort)` — один
    `role="alert"` с «Server unavailable» и Retry; children не рендерятся (нет «No tasks/No documents/
    No projects»);
  - просроченный JWT → `/login?...expired=1&next=%2Ftasks`, баннер, реальный логин, возврат на
    `/tasks`.

## Почему

- Один shell-level error-state — единственный способ гарантировать «error побеждает empty» на всех
  страницах без правки 11 независимых компонентов.
- Retry на уровне shell повторяет probe, а не перезагружает страницу; после восстановления сервера
  children появляются без потери маршрута.
- Сохранение `next` — часть контракта логина; гонка двух auth-fail путей (probe и Topbar) ломала её,
  поэтому guard стоит на событии, а не на URL после факта.

## Проверено

- `web-ui/e2e/states.spec.ts` — **12/12** (11 offline + expired/next). Полный Playwright suite —
  **27/27** (UI-15 15 + UI-12b 12).
- Revert-check по факту итераций: до `setGate('error')` все 11 offline-тестов падали на пустом
  состоянии/`Checking session…`; до guard на `/login` expired-тест получал `/login?expired=1` без
  `next`. После фиксов — зелёные.
- `tsc --noEmit` web-ui чистый; markdownlint/backlog:check — в PR.

## Ограничения, записанные честно

- Offline-тест отменяет `**/mcp**`; при другом пути API (например, кастомный reverse-proxy) паттерн
  нужно синхронизировать с `NEXT_PUBLIC_MCP_API_URL`.
- Проверяется shell-level контракт; страницы, которые сами делают запросы после `ready`, могут
  показывать свои ошибки — это ожидаемо, но их собственные empty/error состояния отдельно не
  аудировались.
- Expired-тест использует реальный `/auth/login`; в CI он поднимается тем же job.

## Откат

Revert ветки: возвращаются `GateState='checking'|'ready'`, `setGate('ready')` на не-auth ошибке и
безусловный `onExpired`; spec удаляется. UI-12a не затрагивается.
