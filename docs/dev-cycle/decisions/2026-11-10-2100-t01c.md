## Вопрос

Как дать администратору управлять пользователями и личными токенами из существующей страницы
`/access`, не заводя второй API и не обходя MCP admin-инструменты?

## Решение

- `web-ui/lib/api-client.ts`: типы `AdminUser`/`AdminToken` и методы `api.admin.usersList`,
  `userCreate`, `userSetPassword`, `userSetRoles`, `userDisable`, `tokensList`, `tokenCreate`,
  `tokenRevoke` — все поверх `callTool` (MCP admin tools из T-01b).
- `web-ui/app/access/page.tsx`:
  - карточка **Users**: список (username/roles/disabled), создание пользователя (username/password/
    roles), disable/enable, «Tokens» выбирает пользователя;
  - для выбранного пользователя — смена пароля, смена ролей, создание токена (name + optional
    `datetime-local` expiry), список токенов (prefix/status/expiry) и revoke;
  - сырой токен показывается **один раз** с кнопкой Copy; списки его не содержат;
  - используются только примитивы `Card/Input/Button/CopyButton`, без нативных контролов и
    `window.confirm`; ошибки admin-role показываются тем же текстом.
- API админки остаётся MCP-поверхностью: UI не ходит в `auth.db` напрямую.

## Почему

- Один источник правды для операций — admin-MCP-инструменты; UI лишь вызывает их, поэтому права,
  аудит и поведение совпадают с CLI/агентом.
- Отдельная страница не нужна: `/access` уже про сессии и токены, пользователи логично живут там.
- Raw-токен не сохраняется в state дольше одного показа, списки всегда только prefix.
