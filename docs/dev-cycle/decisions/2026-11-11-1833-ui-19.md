# 2026-11-11 18:33 — UI-19: System и Access как админ-раздел

- **Пункт:** UI-19 (medium), зависит от UI-10
- **Ветка / sha:** `feat/ui-19-system-admin`, от `origin/master` `48a7c35`

## Вопрос

`/system` уже показывал сессии, embeddings и каталог, но:

- каталог грузил первые 100 без страниц — «хвост» из 155 инструментов не открыть;
- у сессий не было фильтра, ограничения строк и действия «завершить»; `session_kill` не существовал;
- auth-блок был двумя абзацами вместо шагов, ссылки на `/access` не было;
- таблица сессий не адаптировалась под мобильный экран, высота страницы не ограничивалась.

## Решение

- **Backend** `session_kill({sessionId})` в `src/register/session.ts`: admin-only, отказ для своей сессии,
  `SessionManager.close(id,'manual')` + `RateLimiter.remove`; `session_list` теперь отдаёт
  `selfSessionId` (аддитивное поле).
- **Catalog**: страница по 20 (`toolsList(search, 20, offset)`), диапазон `1–20 of 155`, Previous/Next с
  disabled на краях; поиск сбрасывает offset; фильтр по имени находит хвостовой инструмент.
- **Sessions**: фильтр по session/remote/user/project, выбор 5/10/20 строк (default 5), `selfSessionId`
  скрывает кнопку Terminate у своей сессии; destructive `Dialog` для подтверждения.
- **Mobile**: таблица `hidden md:block`, карточки `md:hidden`.
- **Auth**: `ol` из трёх шагов (Access page → sessionStorage/rotation → вставить токен) со ссылкой
  `/access`; текст про cookie/XSS сжат до одной строки шага 2.
- `docs/features/tools.md`: `session_kill`, total 155.

## Почему

- `session_kill` должен быть серверным, а не «закрыть вкладку»: без него `session_list` не отражает
  обещанное управление сессиями.
- `selfSessionId` — минимальное аддитивное поле, чтобы UI не предлагал заведомо неуспешное действие.
- Пагинация offset подходит `tools_list` (у него уже offset/limit и стабильный реестр), а не cursor:
  каталог инструментов меняется редко и поиск всё равно сбрасывает страницу.
- 5 строк по умолчанию — требование DoD по высоте; пользователь может выбрать 10/20.

## Ограничения

- `session_kill` действует только в текущем процессе/`SessionManager`; между инстансами кластера сессия
  не закроется.
- UI-e2e не подтверждает фактическое закрытие через кнопку: в нём только Dialog; удаление проверено
  unit-тестом `session_list`.
- `session_list`/`session_kill` работают на TCP/HTTP; на stdio `available:false`.
- Пагинация инструментов — offset, не cursor; при hot-register инструмента страница может сдвинуться.
- Мобильные карточки не показывают `lastActivityAt`, только remote/user/project.
- Auth по-прежнему принимает raw JWT в поле; OAuth/device-flow не добавлялись.
- Высота `<2000` проверена на локальном наборе (5 строк, 20 инструментов); при 20 сессиях/длинных
  описаниях может вырасти.

## Откат

Убрать `session_kill`/`selfSessionId`, пагинацию/фильтры/карточки/Dialog и e2e-тест; API 155 → 154.
