## Вопрос

Write-инструменты возвращали записанную запись целиком: `tasks_create`/`tasks_update` —
~0.3 КБ на вызов, в замере 55 вызовов ≈ 16 КБ дублирующего контекста. Нужно было дать клиенту
способ попросить меньше, не меняя ответ по умолчанию (клиенты, читающие полную запись, не должны
сломаться).

## Решение

1. **Два независимых аргумента у write-инструментов:** `fields: string[]` — ровно запрошенные
   поля (та же проекция, что у list/search, через `pickFields`), `compact: true` — фиксированный
   минимальный набор. Без флагов ответ байт-в-байт прежний.
2. **`compact` определён явно, а не «как получится»:** задача — `id, title, status, priority,
   updatedAt`; документ — `id, title, type, updatedAt`. Это то, что нужно агенту, чтобы
   продолжить работу, и не больше.
3. **Один модуль на все инструменты** (`src/register/write-response.ts`): аргументы, наборы полей
   и `projectTask`/`projectDoc`. Иначе каждый регистратор придумал бы свой минимальный набор.
4. **Область — запись задач и знаний, кроме импортов.** Покрыты `tasks_create`, `tasks_update`,
   `tasks_set_deps`, `tasks_bulk_create`, `tasks_bulk_update`, `knowledge_bulk_create`,
   `knowledge_bulk_update`. Импорты (`knowledge_import_*`) не трогали: у них своя форма ответа
   (план импорта и счётчики), проекция полей там не имеет смысла — записано как ограничение.
5. **`fields`/`compact` объявлены в схемах**: после AC-01 неизвестный аргумент — ошибка
   `UNKNOWN_PARAM`, поэтому необъявленный флаг был бы отклонён; схемы обновлены, `api:reference`
   перегенерирован.

## Почему

- `fields` уже есть у list/search — одна конвенция на всю поверхность.
- `compact` отдельным флагом, а не «возвращай меньше всегда»: полноценный ответ нужен при
  создании сложной задачи, когда клиент показывает её целиком.
- Минимальный набор зафиксирован в коде и покрыт тестом, чтобы «compact» не расползся.

## Проверено

- `tests/response-filters.test.ts` (часть 3, 5 тестов): `tasks_create` с `fields: ['id']` —
  фактический текст ответа ≤ 120 байт; `compact: true` даёт ровно `id/title/status/priority/
  updatedAt`; без флагов возвращается полная запись (`description`, `createdAt`, `tags`);
  `tasks_update` и `tasks_set_deps` проецируются (`deps.task` — минимальный при `compact`);
  `knowledge_bulk_create` с `fields: ['id']` отдаёт только `id`.
- Revert-check: 3 мутации RED — отключить проекцию `fields` (3 теста), игнорировать `compact`
  (2 теста), убрать проекцию в `tasks_create`/`tasks_update` (3 теста).
- `npm run build`, `tsc -p tsconfig.test.json --noEmit`, `npm run api:reference` (+31 строка:
  аргументы у семи инструментов), `backlog:check`, markdownlint — зелёные.

## Закрытие AC-03

PR #304), AC-03b (`tasks_dag`: фильтры, страница, бюджет, PR #305), AC-03c (этот PR). DoD AC-03

`meta.ms` есть в каждом конверте, `tasks_list({ids})` возвращает ровно запрошенные задачи.
