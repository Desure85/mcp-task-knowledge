## Вопрос

DX-26 требует CLI-полировки. Первый срез — `--help` и `config show` (эффективный конфиг
env > file > defaults), причём `--help` не должен требовать `DATA_DIR`.

## Решение

- Новый `src/cli/help-config.ts`:
  - `runHelp()` — статический usage, без импорта `config.js`;
  - `runConfigShow()` — ленивый `import('../config.js')` и маскировка секретов по имени ключа,
    плюс `scrubSensitiveText` для строк;
  - ошибка загрузки конфига → exit 2 с hint про `DATA_DIR`.
- `src/index.ts` диспетчеризует `--help`/`-h` и `config show` до `AppContainer`, поэтому сервер не
  поднимается и lock не создаётся.
- `tests/cli-help-config.test.ts` спавнит `dist/index.js` (help без DATA_DIR, config с DATA_DIR,
  config без DATA_DIR → 2).

## Почему

- `--help` обязан работать в сломанном окружении — поэтому `config.ts` не импортируется на верхнем
  уровне.
- `config show` печатает эффективный конфиг, а не сырой env; секреты не утекают.
- Остальные подкоманды DX-26 (`ui`, `init --demo`, `uninstall`, actionable errors) не входят в этот
  срез, родитель не закрывается.

## Проверено

- `tests/cli-help-config.test.ts` — **3/3**.
- `node dist/index.js --help` без DATA_DIR → usage, exit 0.
- `node dist/index.js config show` с DATA_DIR → JSON, exit 0.
- `npm run build` — чисто; bundle hash пересобран.
- backlog:check — DX-26 остаётся pending; счётчики не меняются.

## Ограничения

- `config show` показывает `ServerConfig`, а не все env-переменные, которые читает `config.ts`.
- Маскировка по имени ключа; произвольные секреты в нестандартных полях не гарантированы.
- `ui`/`init --demo`/`uninstall` и actionable-errors для занятого порта не сделаны.

## Откат

Удалить `src/cli/help-config.ts`, ветки диспетчера в `src/index.ts` и тест; остальной код не
затрагивался.
