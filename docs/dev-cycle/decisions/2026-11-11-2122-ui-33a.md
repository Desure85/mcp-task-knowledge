# 2026-11-11 21:22 — UI-33a: темы в серверном профиле

- **Пункт:** UI-33a (medium), зависит от UI-33, T-01

## Вопрос

Тема и пользовательские темы жили только в localStorage: на втором устройстве после входа был
дефолт, удаление/изменение на сервере не доходило, офлайн-переключение не имело очереди.

## Решение

### Server

- `src/profiles/store.ts`: `UserProfileStore` в `DATA_DIR/user-profiles.json`.
  - запись атомарная (temp+rename), очередь операций, лимит 32 KiB;
  - LWW по `updatedAt`: старый write → `{applied:false, conflict:true, profile:current}`;
  - равный timestamp + равный JSON → `duplicate:true`; равный + другой JSON → conflict.
- `src/register/profile.ts`: `profile_get` / `profile_set`; пользователь из
  `AuthManager.getUserId(sessionId)`, для stdio — `local`. Зарегистрированы в `AppContainer`.
- `docs/api-reference.md` 157 tools; `docs/features/tools.md` + totals.

### Client

- `web-ui/lib/api-client.ts`: `api.profile.get/set`.
- `web-ui/lib/theme-sync.ts`: один snapshot `{theme,mode,customThemes,activeCustomId,updatedAt}`;
  `mergeThemeSnapshots` по `updatedAt`; `syncThemeProfile` (pending → get → apply/push/in-sync);
  `pushLocalThemeChange` (тот же snapshot + `mcp.themePending` при offline).
- `web-ui/components/ThemeSync.tsx` в AppShell (после gate ready): mount/login sync, `online`
  retry, `mcp:theme-change` push; server-applied event помечен `source:'server'` и не зацикливает.
- `ThemesScreen.persist/remove` теперь шлют `mcp:theme-change`; `ThemeManager` получает в
  server-event theme/mode (иначе он записывал `"undefined"` — найденный баг).
- `docs/features/theme-sync.md`.

## Почему

- Один snapshot вместо append-истории: повторная синхронизация не создаёт дубликатов тем, а LWW
  по `updatedAt` разрешает расхождение без векторных часов.
- localStorage остаётся кэшем/первым пейнтом; сервер — источник после входа.
- `source:'server'` разделяет локальный push и применение сервера, иначе бесконечный цикл.
- Очередь — один слот: при офлайне важен последний выбор, а не история.

## Ограничения

- Синхронизация на mount/login и локальных изменениях, не live; другое устройство увидит после
  reload/login.
- Офлайн-очередь хранит только последний snapshot (без merge).
- `updatedAt` клиентский; clock skew решает конфликт. Equal-time divergence → конфликт, клиент
  применит сервер на следующем проходе.
- stdio без auth использует общий профиль `local`.
- JSON профиля не шифруется; секреты туда класть нельзя.
- Удаление пользовательской темы передаётся снапшотом (пустой список/active null), без tombstone.
- Тема синхронизируется только на страницах AppShell (не на `/login`).

без серверного события; API 157 → 155.
