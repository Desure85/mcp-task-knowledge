## Вопрос

`gdrive` читал `refreshToken/clientId/clientSecret`, но не использовал: после истечения access-token все
tools падали до рестарта. Чинить refresh-флоу или удалить поля?

## Решение

- `src/connectors/oauth-refresh.ts`: `refreshGoogleAccessToken` — POST `oauth2.googleapis.com/token`,
  `grant_type=refresh_token`, парсит `access_token/expires_in`; ошибки `OAuthRefreshError`.
- GDrive: `ensureToken()` (обновление при истечении), `tokenExpiresAt`, refresh при `401` + один retry,
  refresh на init, если access-token отсутствует.
- Gmail/OneDrive не имеют мёртвых refresh-полей; для них зафиксировано «external refresh» в документации.

## Почему

- Refresh-флоу убирает часовой простой и использует уже существующие поля.
- 401-retry страхует access-token без известного срока.
- Gmail/OneDrive не трогаем: у них нет refresh-конфига, добавлять нечего.

## Проверено

- `tests/gdrive-oauth-refresh.test.ts` — **3/3**: обмен refresh→access; ошибка 400; 401→refresh→retry
  с `Bearer stale` → `Bearer fresh`.
- build чистый; `backlog:check` **401/0/19/1**.

## Ограничения

- Нет фонового refresh: только на init/expiry/401.
- Gmail/OneDrive остаются с externally-provided token.
- Секреты читаются из конфига; ротация/хранение не менялись.

## Откат

Удалить `oauth-refresh.ts`, вернуть чтение полей без refresh и тест/документацию.
