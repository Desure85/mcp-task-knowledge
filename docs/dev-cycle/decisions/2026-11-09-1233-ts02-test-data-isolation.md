# 2026-11-09 12:33 — TS-02: изоляция каталога данных между тест-файлами

- **Пункт:** TS-02 (`BACKLOG.md`), продолжение TS-01

- **Основание:** TS-01 и TS-02 в `BACKLOG.md`; примечание AC-05 в `AGENTS.md` §8 («пара `search-fts` +

  комментарий `tests/search-tasks-warmup.test.ts`, где отдельный `mkdtemp` для metadata-индекса был

## Вопрос

`tests/setup.ts` задавал один `DATA_DIR = <cwd>/.tmp-vitest` на весь прогон. Все 261 тест-файл,
кроме 44 со своим каталогом, писали в него задачи, знания, промпты, `.state.json`,
`.jwt-revoked.json` и `.index/metadata.db`. Отсюда два класса проблем: сьюты видят данные друг друга
внутри одного прогона, и каталог копится между прогонами, поэтому «зелёный» результат зависит от
истории машины. Обходной путь «удалить `.tmp-vitest` перед полным прогоном» держится на памяти
человека и не защищает от загрязнения внутри одного прогона.

## Воспроизведение (до правок, `59cb80f`)

1. **Общий каталог доказан исполняемо.** Три пробных тест-файла, `--maxWorkers=1`: setup исполнился
   три раза (`pid` 3702040 / 3702299 / 3702473), все три раза `DATA_DIR` =
   `/home/dm/work/mcp-tk-ts02/.tmp-vitest`. Это же подтверждает допущение плана: vitest исполняет
   `setupFiles` на каждый тест-файл, поэтому `mkdtemp` в setup даёт изоляцию по построению.
2. **Накопление доказано файловой системой.** В основном рабочем дереве `.tmp-vitest` занимал 23 МБ и
   содержал 1031 каталог `tasks/` и 296 — `knowledge/`; `.state.json` хранил `currentProject: "mcp"`
   из прошлых прогонов. Никто этот каталог не удаляет — в `.gitignore` он только игнорируется.
3. **Названный флейк не воспроизвёлся — записываю честно.** Пара `tests/search-fts.test.ts` +
   `tests/sec003-auth-gate.test.ts` (второй в этом прогоне действительно создаёт
   `.tmp-vitest/.index/metadata.db`, 188 КБ): 10 прогонов до правок — 10/10 зелёных, 62 теста.
   Пара `tests/search-fts.test.ts` + `tests/search-tasks-warmup.test.ts` на грязном каталоге
   (1029 проектов, 23 МБ, скопирован из основного дерева): 10 прогонов до правок — 10/10 зелёных.
   Причина: `search-fts.test.ts` изолирован собственным `mkdtemp`, а `search-tasks-warmup.test.ts`
   получил свой каталог для metadata-индекса в AC-05. Описанное в `AGENTS.md` §8 падение относится к
   состоянию до этого обхода; TS-02 убирает класс проблемы, а не один воспроизведённый случай.

## Решение

1. **Каталог на тест-файл.** `tests/setup.ts` создаёт `DATA_DIR` через `mkdtempSync` в `os.tmpdir()`
   с префиксом `mcp-vitest-`; `OBSIDIAN_VAULT_ROOT` — подкаталог `vault` внутри него.
2. **Снятие после файла.** `afterAll` в setup удаляет каталог: хук исполняется после тестов файла,
   в том числе когда файл переопределил `DATA_DIR` на свой путь (тогда setup-каталог остаётся пустым).
3. **Свип осиротевших.** Упавший воркер не исполняет `afterAll`, поэтому при каждом запуске setup
   удаляет каталоги и registry-файлы с префиксом `mcp-vitest-` старше 2 часов. Граница свипа —
   только свой префикс; чужое содержимое `/tmp` не трогается.
4. **Страж.** Setup пишет строку `{pid, dataDir}` в `<tmp>/mcp-vitest-registry-<ppid>.jsonl`
   (ключ по родительскому процессу, поэтому параллельные прогоны не смешиваются), а
   `tests/data-isolation.test.ts` проверяет две вещи: каталог файла лежит в `os.tmpdir()` и вне
   репозитория, и ни один `DATA_DIR` не встречается дважды.
5. **44 файла со своим `DATA_DIR` не менялись** — они уже были изолированы, и их правка расширила бы
   diff без изменения поведения.

Отвергнуто: очистка `.tmp-vitest` перед прогоном (обход в каждом раннере, CI и на машине
разработчика, не защищает от загрязнения внутри одного прогона); `fileParallelism: false` и `retry`
(маскируют симптом и удорожают прогон вместо изоляции).

## Почему

Каталог данных — это состояние процесса, а не общий ресурс прогона: `config.ts` читает
`DATA_DIR/.state.json` при загрузке модуля и пишет его в `setCurrentProject`, metadata-индекс живёт в
`DATA_DIR/.index/metadata.db` и пересоздаётся при несовпадении `meta.data_dir`. Пока каталог общий,
любой сьют, меняющий текущий проект или индекс, влияет на соседей, а порядок файлов становится
частью контракта теста. Изоляция на уровне setup делает контракт явным и одинаковым для всех
261 файла, без правки каждого.

## Откат

Правка локальна для тестового контура: продуктовый код, схема и данные `DATA_DIR` не менялись.

1. `git revert <commit>` (или вернуть `tests/setup.ts` из `origin/master` и удалить
   `tests/data-isolation.test.ts`) — поведение setup вернётся к общему `<cwd>/.tmp-vitest`.
2. Откат ничего не восстанавливает и ничего не теряет: legacy-каталог `.tmp-vitest` не удалялся и не
   переписывался, свип трогает только каталоги с префиксом `mcp-vitest-`, созданные этой правкой.

   вернётся исходный класс флейков.
