## Вопрос

Хранить темы команды в данных проекта, чтобы участник видел их без локального импорта; правка —
только ролью с правом; удаление не ломает личную копию.

## Решение

- `ProjectMetadata.themes?: ProjectTheme[]` (`id`, `name`, `theme` JSON, `updatedAt`, `updatedBy?`).
- `ProjectMetaUpdates.themes` + запись в `updateProjectMeta`.
- MCP: `project_themes_list` (read), `project_theme_set` (write), `project_theme_delete` (write).
  Гейт T-02 классифицирует `_set`/`_delete` как write: viewer получает отказ, editor/admin проходят.
- Лимит 20 тем; id `^[a-z0-9][a-z0-9-]{1,39}$`; тема хранится как JSON-объект (web-ui `CustomTheme`).
- Удаление темы удаляет только проектную запись; личная копия в браузере не затрагивается.

## Почему

- Project metadata — уже существующий ACL-контейнер (members/statuses/types); отдельный store не нужен.
- Роль проверяется общим гейтом, а не дублируется в handler.
- Личная копия как механизм «взять тему» даёт fallback при удалении без связанного состояния.

## Ограничения

- Это **server-only срез**: на `/themes` нет списка проектных тем, кнопки «publish/copy» и выбора темы команды.
- `updatedBy` не заполняется (нет userId в handler); роль проверяется гейтом.
- Тема не валидируется по схеме CustomTheme на сервере — доверяет web-ui JSON.
- SQLite/Postgres профиль project metadata — файловый (как T-02), отдельного теста нет.

## Откат

Удалить `ProjectTheme`, поле `themes`, три инструмента, тест и строки документации; метаданные с
неизвестным полем читаются как раньше (аддитивно).
