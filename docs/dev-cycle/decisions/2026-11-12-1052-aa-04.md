## Вопрос

Нужен append-only журнал драфтов и воркер, который доводит их до knowledge через MCP с
идемпотентным ключом, ack после успеха и продолжением после обрыва; плюс upsert, не плодящий
дубли (существующий `knowledge_import_markdown` дедуплицирует только по title).

## Решение

- `src/drafts/journal.ts`: `journal.jsonl` (append-only), события `draft`/`acked`; индекс — последний
  драфт по `key`; `appendDraft` идемпотентен по ключу, `pendingDrafts`, `ackDraft`.
- `src/drafts/sync.ts`: `syncDrafts` обрабатывает pending по одному, вызывает upsert, затем ack;
  ошибка оставляет запись pending, следующие записи не теряются.
- `src/drafts/upsert.ts`: `upsertKnowledgeByExternalKey` ищет документ по `externalKey`, обновляет
  или создаёт; `KnowledgeDocMeta.externalKey` добавлен.
- MCP: `draft_append`, `draft_pending`, `draft_sync`, `knowledge_upsert` (регистрация в
  `defaultRegistration`).
- Документация: 4 строки в `docs/features/tools.md`, `npm run api:reference` → 161 tool.

## Почему

- Append-only события не перезаписывают историю; ack — отдельное событие, поэтому повторный синк
  безопасен.
- Upsert по внешнему ключу, а не по title: title может меняться, а `draft:ses_<id>#<n>` стабилен.
- Один контекст и обычные storage-функции: без нового формата wire и без второго индекса.

## Ограничения

- Журнал — один JSONL-файл; компакция/архивация не сделаны.
- `draft_sync` синхронный: один вызов обрабатывает текущую пачку, без фонового демона.
- `knowledge_upsert` ищет по `listDocs` проекта (O(docs)); индекс по externalKey не добавлен.
- После сбоя одного upsert остальные всё равно обрабатываются (failed перечислены, не всё-или-ничего).
- `search_knowledge` находится в другом tool-слое; тест проверяет список документов, не BM25-поиск.
