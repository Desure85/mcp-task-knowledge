# 2026-11-11 14:30 — TR-34: circuit breaker для коннекторов

- **Пункт:** TR-34 (medium), зависимость TR-08
- **Ветка / sha:** `feat/tr-34-connector-circuit-breaker`, от `origin/master` `c990097`

## Вопрос

Коннекторы вызывали внешние API напрямую: упавший GitHub/Jira/Slack получал полный TCP/TLS timeout
на каждом вызове, а `/readyz` не видел состояние коннекторов.

## Решение

- `ConnectorRegistry.initAll` оборачивает每一位 `registerTool`-handler коннектора в
  `ServiceAvailability` из `getServiceAvailabilityRegistry()` с ключом `connector:<id>`:
  - вызов при открытом circuit → немедленная ошибка `connector <id> is unavailable (circuit open)`
    без сетевого запроса;
  - успех → `recordSuccess()`; исключение → `recordFailure()`.
- `ConnectorRegistry.availabilityComponents()` отдаёт `ComponentHealth` каждого инициализированного
  коннектора.
- `AppContainer` регистрирует эти компоненты в `HealthChecker` (`connector:<id>`), поэтому `/readyz` и
  `/healthz` показывают `unhealthy` при открытом circuit.
- Конфиг circuit — общий `DEFAULT_CIRCUIT_CONFIG` (5 ошибок, 10 с до half-open, 2 успеха для close);
  тесты создают tracker с коротким окном до `initAll`, и `get()` переиспользует его.

## Почему

- Точка обёртки — единственное место, где все коннекторы получают `registerTool`, поэтому не нужно
  править каждый коннектор и рисковать пропустить один.
- Fast-fail на уровне tool handler сохраняет прежний контракт ошибки для клиента, но убирает
  ожидание сети.
- Health-компоненты используют существующий `toComponentHealth()`, а не новую схему.

## Проверено

- `tests/connector-circuit-breaker.test.ts` — **2/2**:
  - два падения открывают circuit; третий вызов падает `circuit open` и **не** доходит до handler;
  - `toComponentHealth()` → `unhealthy`/`ready:false`;
  - после `resetTimeoutMs` два успеха закрывают circuit (`closed`, `healthy`);
  - успешный вызов не открывает circuit.
- build/tsc.
- **Мутация RED:** `if (false && !service.canExecute())` → 1 тест падает; восстановление → 2/2.

## Ограничения

- Circuit общий на коннектор, не на отдельный endpoint/tenant.
- Конфиг фиксирован `DEFAULT_CIRCUIT_CONFIG`; env-настройки нет.
- Успешный вызов в `half-open` учитывается, но `health()` самого коннектора не влияет на circuit.
- Health-компоненты регистрируются только для **инициализированных** коннекторов; skip/ошибка init
  не появляется в `/readyz`.

## Откат

Revert ветки: убрать `guardedRegister`, `availability`, `availabilityComponents` и регистрацию в
`HealthChecker`; тест удаляется. Вызовы коннекторов снова идут напрямую.
