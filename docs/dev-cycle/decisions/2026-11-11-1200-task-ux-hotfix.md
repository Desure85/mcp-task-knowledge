# 2026-11-11 12:00 — task UX hotfix: клики, превью на SQLite, Markdown

- **Тип:** прямой запрос владельца (не пункт BACKLOG), ветка `fix/task-ux-hotfix` от `master` `28b8698`
- **Затронуто:** доска/список задач, quick view, полная страница, `tasks_get_deps`

## Вопрос

1. В **списке** клик по пустому месту строки ничего не открывал, а в **доске** — открывал превью;
   поведение расходилось.
2. Клик по **имени задачи** открывал превью, хотя владелец ожидает редактор.
3. На демо-SQLite превью падало с `Could not load this task`: `tasks_get_deps` читал задачи
   файловым `getTask`/`listTasks`, а не профилем `ctx` → `Task not found` на SQLite.
4. Не было Markdown-редактора у описания задачи.

## Решение

- **Клики:** имя (кнопка заголовка) → редактор (`onEdit`); свободная область карточки/строки →
  превью (`onView`). В `TaskCard` первый интерактивный элемент остаётся кнопкой имени; статья
  получила `tabIndex={0}` для возврата фокуса из Dialog. В таблице `<tr>` обрабатывает клик, но
  игнорирует `button, a, input, select, textarea`.
- **Сервер:** `tasks_get_deps` использует `storageProfile(ctx).tasks` для `get`/`list`, поэтому
  одинаково работает на file/SQLite/Postgres. Чистые графовые функции остаются из storage.
- **Устойчивость превью:** quick view загружает `tasks.get/list/getChildren` обязательно, а
  `tasks.getDeps` — с `try/catch`; при профильном пробеле диалог всё равно открывается, блок
  зависимостей пуст.
- **Markdown:** на полной странице у Description появился переключатель `Edit`/`Preview`
  (`renderMarkdown`, класс `prose`, `dangerouslySetInnerHTML` только через escaping-first renderer);
  quick view рендерит описание тем же renderer.

## Проверено

- `task-quick-view.spec.ts` — **1/1** на демо-SQLite после фикса: превью открывается, зависимости не
  валят загрузку; имя открывает `Edit task`, свободная область — диалог; фокус возвращается на карточку.
- `tasks-list.spec.ts`, новый сценарий — **1/1**: клик по пустой ячейке строки открывает превью,
  имя открывает редактор.
- `task-detail.spec.ts`: Markdown `Preview` показывает отрендеренный текст, возврат в Edit сохраняет
  содержимое; локальный SQLite-прогон дальше падает на известном transition-gap (pre-existing),
  файловый профиль/CI — решающий.
- web tsc чистый; `tasks_get_deps` на SQLite вручную: `ok=true`, `isBlocked=false`, без `Task not found`.
- Демо перезапущено: web `127.0.0.1:3000` (pid 40756), MCP `127.0.0.1:3001` (pid 29776), обе скрыты.

## Почему

- Единый паттерн «имя = редактировать, фон = посмотреть» убирает расхождение доски и списка.
- Профильный `getDeps` лечит корень, а не маскирует падение превью; `try/catch` оставлен как
  защита от будущих профильных пробелов.
- Markdown-рендер использует существующий escaping-first renderer (TR-02), без нового HTML-пути.

## Ограничения

- `tasks_get_deps` на SQLite всё ещё опирается на отсутствие `dependsOn` в этом профиле — рёбра
  пустые; сам вызов больше не падает.
- Markdown в quick view — только чтение; редактирование на полной странице.
- Локальный полный Playwright на SQLite содержит известные падения claim/transition (Y-05 gap);
  CI — файловый профиль.

## Откат

Revert ветки: возвращаются старые обработчики кликов, файловый `getDeps`, `Promise.all` без
fallback и Textarea без Preview. BACKLOG/счётчики не менялись.
