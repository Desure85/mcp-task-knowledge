# 2026-11-10 03:00 — Y-07a: контракт BlobProvider и файловый провайдер

- **Пункт:** Y-07a (входит в Y-07 «BlobProvider: S3 и MinIO»)
- **Ветка / sha:** `feat/y07a-blob-provider`, от `origin/master` `29095f8` (PR #341 влит)
- **Основание:** ADR-009 (абстракции за профилями, путь передаёт вызывающий), план
  `docs/dev-cycle/plans/2026-11-09-y-stage.md` (Y-07a)

## Вопрос

Какой контракт нужен для вложений, экспортов и копий, чтобы Y-07b (S3/MinIO) реализовал ровно его,
а не «похожий» интерфейс, и как хранить блобы локально без риска выйти за пределы каталога данных?

## Решение

1. **Контракт в `src/storage/contracts.ts`:** `BlobProvider` (put/get/size/delete/list), адресация
   ключом, `BlobMetadata { key, size, checksum, contentType?, updatedAt }`, `checksum` — `sha256:<hex>`
   (единая ручка целостности для копий/экспортов), `capabilities { presign: boolean; maxBytes?: number }`.
   `put` идемпотентен для одинаковых байтов; `get`/`size` для отсутствующего ключа **бросают
   `StoreError('NOT_FOUND')`** — вызывающий обязан отличать «объекта нет» от «объект пустой»;
   `delete` идемпотентен (`false`, если ключа уже нет).
2. **Файловая реализация `src/storage/blobs/file-blob-provider.ts`:** `root` передаёт вызывающий;
   ключ валидируется (только сегменты `[A-Za-z0-9._-]`, без `..`/`.`/абсолютных путей/обратных слэшей,
   до 512 символов) и резолвится с проверкой, что путь остаётся внутри `root`; запись атомарная
   (`temp` + `rename`), метаданные — в скрытом `.meta/` (list их не видит), `maxBytes` проверяется до
   записи. `kind: 'file'`, `capabilities.presign: false`.
3. **Проводка в профили:** `StorageProfile.blobs?: BlobProvider`, коллекция `blobs` в манифестах
   file и sqlite профилей. Файловый профиль размещает блобы в `DATA_DIR/blobs` (переопределяется
   `blobsDir`), SQLite-профиль — рядом с БД (`<db dir>/blobs`). Основным хранилищем задач/документов
   блобы не являются (ограничение ADR-009 и плана: MinIO/S3 — только для вложений/экспортов/копий).
4. **Общий контрактный набор:** `tests/blob-provider.test.ts` экспортирует
   `runBlobProviderContract(label, create)` — его же обязан прогнать S3-адаптер в Y-07b. Сейчас через
   него проходит файловый провайдер: round-trip бинарных байтов, идемпотентность/перезапись, NOT_FOUND,
   delete/list с префиксом, отказ ключей с выходом из root, перезапуск на том же root, maxBytes.

## Почему

- Единый `runBlobProviderContract` — единственный способ доказать, что S3-адаптер (Y-07b) совместим,
  а не «примерно похож»: иначе тесты разъедутся, и различия обнаружатся в продакшене.
- Ключ вместо пути и проверка резолва — защита от path traversal; список и метаданные не должны
  зависеть от побочных файлов, поэтому `.meta/` скрыт.
- `NOT_FOUND` вместо пустых байтов — вызывающий код не сможет случайно принять отсутствие объекта за
  валидный пустой файл.

## Откат

Revert ветки: из `contracts.ts` уходят `BlobProvider`/`BlobMetadata`/`BlobPutOptions`, поле
`StorageProfile.blobs` и коллекция `blobs`; удаляются `src/storage/blobs/file-blob-provider.ts`,
`tests/blob-provider.test.ts`; файловый/SQLite профили перестают создавать провайдер, `blobsDir`
опции удаляются. Задачи, документы, поиск, векторы и wire-формат не затрагиваются — блобы до появления
потребителей в инструментах нигде не читаются.
