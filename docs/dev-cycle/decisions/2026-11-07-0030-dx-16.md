# 2026-11-07 00:30, DX-16: ADR-008 принят (Accepted), реализация DX-16a и DX-16b разрешена

Вопрос: принимать ли ADR-008 (`admin_backup`/`admin_restore`, статус был Proposed) и разрешать ли
реализацию DX-16a и DX-16b. Restore необратимо перезаписывает данные, поэтому решение за владельцем.

Решение: владелец принял ADR-008 целиком (2026-11-07, ответ «можно всё принять» на перечень из
пяти решений). Статус в ADR изменён на Accepted. DX-16a (`admin_backup`, формат архива) идёт
первым, DX-16b (`admin_restore` и ужесточение существующего `restoreBackup`) после него, оба
отдельными PR с revert-check по списку тестов из ADR.

Почему: гейт R12 (данные) красный, ADR закрывает дефекты Д1-Д6 существующего restore
(запись по `entry.from` из манифеста, симлинки, секреты в `scope=full`, наложение вместо замены).
Защита restore в ADR: `dryRun` по умолчанию, `confirm`, автоснапшот `pre-restore`, `.restore.lock`.

Проверено: ADR прочитан контролёром, дефект Д1 подтверждён по `src/services/data-backup.ts:376-392`
(`const dst = entry.from` без `resolveUnder`); `npm run lint:md` и `npm run backlog:check` на PR #274
зелёные.

Откат: вернуть строку статуса ADR-008 в Proposed и остановить DX-16a/b; реализованные PR откатываются
revert-коммитами, автоснапшот перед restore остаётся.
