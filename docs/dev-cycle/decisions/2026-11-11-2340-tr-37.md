# 2026-11-11 23:40 — TR-37: per-item errors и изоляция исключений в bulk

- **Пункт:** TR-37 (medium)
- **Ветка / sha:** `feat/tr-37-bulk-per-item`, от `origin/master` `554a374`
- **Сырьё:** `src/register/bulk.ts`, `src/bulk.ts`

## Вопрос

Как перестать молча терять отсутствующие id и обрывать весь batch на одном исключении в
bulk-инструментах задач/документов?

## Решение

- В `src/bulk.ts` добавлен `runBulkResults(ids, op, notFoundPrefix)`:
  - `null` → `{ok:false,error:{message:"<prefix> <id>"}}`;
  - throw → изолированный `{ok:false,error}`;
  - остальные id продолжают выполняться.
- `knowledge_bulk_update`: per-item `failed` (раньше отсутствующий id молча исчезал), успешные
  результаты сохраняют прежний shape `results`; ошибка одного документа не валит остальные.
- `tasks_bulk_create`: исключение на одном item больше не теряет уже созданные задачи; ответ
  дополнен `failed: [{index,error}]`, `count` — число созданных.
- `knowledge_bulk_archive/trash/restore` и `tasks_bulk_archive/trash/restore` дополнены `failed`,
  отсутствующие id больше не исчезают без следа. Существующие `results` не заменялись на обёртки —
  это аддитивное изменение; клиенты, читающие `results`, не ломаются.

## Почему

- `src/bulk.ts` уже имел `BulkResult`/`mapResult`, но MCP-регистратор обходил его; helper вынесен
  наружу и переиспользован.
- Сохранить `results` в старом shape важнее косметики: UI-17/страницы уже читают `results`.
- `failed` с id/index даёт агенту точную причину и не заставляет повторять весь batch.

## Проверено

- `tests/bulk-per-item.test.ts` — **3/3**:
  - `knowledge_bulk_update` с валидным и missing id: `count=1`, `failed[0].id=missing`,
    `Doc not found`, успешный документ обновлён;
  - `knowledge_bulk_archive`: missing id попадает в `failed`, существующий архивируется;
  - `runBulkResults` изолирует `throw` и `null`, продолжает остальные.
- build/tsc зелёные; существующие `knowledge.bulk.test.ts` не менялись.
- **RED-наблюдение:** до фикса `knowledge_bulk_update` missing id не попадал ни в `results`, ни в
  ошибки; `knowledge_bulk_archive` молча возвращал `count=1`.

## Ограничения

- `failed` добавлен не ко всем bulk-инструментам: `tasks_bulk_delete_permanent`/dryRun уже имел свой
  формат, его не трогали.
- `knowledge_bulk_update`/archive/trash/restore не используют `src/bulk.ts` напрямую, а вызывают
  profile-aware store через `runBulkResults`; file-only helper остаётся для тестов/старых вызовов.
- Per-item shape остаётся `{id,error}` в `failed`; полная обёртка `{ok,data}` для всех id не вводилась
  (риск сломать существующих потребителей).
- `tasks_bulk_create` не откатывает уже созданные записи — это осознанно, иначе batch-частичность
  станет невозможной; клиент видит `failed`.

## Откат

Revert ветки: удаляется `runBulkResults`, `failed` из ответов и per-item обработка; поведение
возвращается к молчаливому пропуску/обрыву. Формат успешных `results` не менялся.
