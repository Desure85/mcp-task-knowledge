## Вопрос

Ни один тест не фиксировал **negotiated** `protocolVersion` на проводе. Inspector проверяет протокол
частично, а SDK мог обновить `LATEST_PROTOCOL_VERSION` или сломать downgrade — CI оставался зелёным.

## Решение

`tests/protocol-version-e2e.test.ts` спавнит **реальный** `dist/index.js` по stdio и отправляет raw
`initialize` (без SDK-клиента), затем проверяет ответ:

- `2024-11-05` (старый поддерживаемый) → сервер возвращает **тот же** `2024-11-05`;
- `LATEST_PROTOCOL_VERSION` (из SDK) → возвращает `LATEST_PROTOCOL_VERSION`;
- `1900-01-01` (неизвестный) → сервер **не эхом** отдаёт запрошенный, а возвращает `LATEST_PROTOCOL_VERSION`;
- во всех случаях `serverInfo.name === 'mcp-task-knowledge'`.

Каждый запуск — свой `DATA_DIR`; `terminateServer()` + `rm` в `afterEach`, `assertDistFresh()` перед тестом.

## Почему

- Raw stdio проверяет именно wire-поле `result.protocolVersion`, а не поведение SDK-клиента.
- `LATEST_PROTOCOL_VERSION` импортируется из SDK, поэтому обновление SDK не требует правки теста; оно
  само становится проверкой нового negotiated значения.
- Неизвестная версия — самый важный контракт: сервер обязан выбрать поддерживаемую, а не принять мусор.

## Проверено

- `tests/protocol-version-e2e.test.ts` — **3/3** (реальные spawn'ы, ~3.7 с).
- **Assertion mutation RED:** ожидание `2025-11-25` вместо `2024-11-05` → 1 тест падает; восстановление 3/3.
  (Прод-кода нет: предмет — сам контракт; мутация проверяет чувствительность утверждения.)

## Ограничения

- Тест требует `dist/index.js` (`assertDistFresh`), поэтому в unit-only прогоне без build он падает
  ожидаемо, как и другие dist-e2e.
- HTTP-транспорт не проверяется: negotiation делает SDK-сервер над stdio; HTTP добавит тот же `initialize`
  через StreamableHTTP, но отдельного теста нет.
- `initialize` отправляется без `notifications/initialized`; для проверки negotiate этого достаточно.
- OAuth/auth-обвязка не участвует.

## Откат

Удалить `tests/protocol-version-e2e.test.ts`; прод-код не менялся.
