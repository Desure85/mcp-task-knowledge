## Вопрос

Как зафиксировать модель «ядро vs клиенты» целиком: где живёт ядро, кто владеет `DATA_DIR` и
векторами, что при двух ядрах, как подключаются stdio-клиенты, какие границы у транспортов и как
ядро завершается — не переизобретая MU-01 и MU-08?

## Решение

Добавлен `docs/adr/0010-agent-core-and-launch-modes.md` (Accepted) с разделами: контекст, режимы
запуска, время жизни, Windows, сигналы, «почему не выбираем лидера», последствия, ссылки.

Ключевые фиксации:

- **stdio** — процесс на клиента, `AppContainer` живёт с клиентом (режим по умолчанию).
- **HTTP-ядро** — долгоживущий сервис, владеет `DATA_DIR` и векторами; несколько клиентов.
- **bridge** — stdio→HTTP шим (MU-08), не владеет хранилищем, stdout протокольный.
- **TCP/Unix** — те же ядро и `.server.lock`, не новая модель владения.
- `DATA_DIR` — ровно один процесс-ядро (`.server.lock`, reclaim по мёртвому pid/start-time, чужой
  hostname не удаляется); второй получает `SERVER_LOCK_HELD`, а не «выборы лидера».
- **Windows:** stdio/HTTP/TCP/bridge; Unix-сокеты не поддерживаются, named pipe **не реализован**
  (кандидат, честно записано).
- **Сигналы:** не-stdio ядро — SIGTERM/SIGINT + graceful shutdown с освобождением lock; stdio —
  signal-hook только для lock; shutdown идемпотентен, release сверяет токен.
- **Лидер не выбирается:** один локальный каталог — это владение, а не консенсус; second core —
  ошибка конфигурации, лечится остановкой первого или bridge'ем.

## Почему

- MU-01/MU-08 уже реализуют механизмы; ADR фиксирует целостную модель и границы, чтобы будущие
  изменения (named pipe, мульти-клиентское ядро) не ломали её незаметно.
- Явное «лидер не нужен» защищает от попыток превратить файловый lock в распределённый консенсус.

## Ограничения, записанные честно

- Named pipe на Windows не реализован — ADR фиксирует это как кандидат, а не как возможность.
- Windows stale-lock detection консервативнее Linux (нет `/proc`): мёртвость чужого hostname не
  доказывается автоматически, пользователю показывается путь к `.server.lock`.
- ADR — архитектурный документ; конкретные тесты lock/bridge остаются источником истины.
