# 2026-11-11 07:00 — UI-16: список/таблица, сортировка и массовое закрытие

- **Пункт:** UI-16 (high)
- **Ветка / sha:** `feat/ui-16-task-list`, от `origin/master` `a330f17` (PR #374 влит)
- **Основание:** BACKLOG UI-16; UI-10 примитивы; V-04/V-05 board

## Вопрос

Как добавить к доске список задач с сортировкой и массовыми действиями, не ломая Kanban и не
дублируя серверную логику закрытия?

## Решение

- В `app/tasks/page.tsx` добавлен переключатель **Board / List** (`aria-pressed`), вид сохраняется в
  `localStorage` под `mcp.tasksView`; при монтировании читается после рендера, чтобы SSR-доска и
  восстановленный вид не конфликтовали.
- **Таблица**: чекбоксы строк и «выбрать все», заголовки Task / Status / Priority / Tags с
  сортировкой (`aria-sort`); сортировка priority — по `PRIORITY_RANK` (high → low), title/status —
  `localeCompare`; направление переключается повторным кликом.
- **Массовое закрытие** — существующий MCP-инструмент `tasks_bulk_close` (в `api-client` добавлен
  `tasks.bulkClose`); UI применяет `results` к локальному состоянию, счётчик выделения сбрасывается,
  `failed` показывается ошибкой. Никакого нового wire-формата.
- **Быстрые фильтры** уже есть на странице (search, priority, tag); чипы «мои / без исполнителя /
  просроченные» и сохранённые фильтры по BACKLOG зависят от TK-01/TK-02, агентские действия — от
  U-01/U-03, поэтому не выдавались за сделанные.

## Почему

- `tasks_bulk_close` — серверный путь закрытия с переходами workflow и частичными ошибками; повторять
  это через `tasks_bulk_update(status)` значило бы обойти проверки.
- Сортировка на клиенте допустима: `tasks_list` уже отдаёт полный набор для проекта, а вид — чисто
  презентационное состояние; это не меняет контракт данных.
- `localStorage` — тот же приём, что у prefs доски; пользовательский выбор переживает reload.

## Проверено

- `web-ui/e2e/tasks-list.spec.ts` — **2/2**:
  - создаются high/low задачи, List сохраняется после reload, сортировка Priority меняет порядок;
  - три задачи выделяются, «Close selected» закрывает все, после reload строки остаются закрытыми.
- Полный Playwright suite — **43/43** (UI-15 15 + UI-12b 12 + UI-11b 14 + UI-16 2).
- **2 мутации RED** (в одном прогоне): без записи `localStorage` падают оба теста (вид не
  восстанавливается); при обратном `PRIORITY_RANK` падает сортировка.
- tsc web-ui чистый; design guards/no-hardcoded/board-render — 26/26; markdownlint/backlog — в PR.

## Ограничения, записанные честно

- DoD-пункты «мои / без исполнителя / просроченные» и сохранённые фильтры не реализованы: по
  BACKLOG они после TK-01/TK-02; агентские действия — после U-01/U-03.
- `tasks_bulk_close` закрывает последовательно (серверная реализация), поэтому на больших выборках
  это не батч-транзакция; UI показывает частичные `failed`.
- Массовое закрытие подтверждения не спрашивает (в отличие от permanent delete); это обратимо через
  restore.
- Сортировка клиентская по загруженному списку, не серверная пагинация (SC-04).

## Откат

Revert ветки: удаляются List-ветка, состояние `view/selectedIds/sort`, `tasks.bulkClose` и spec; доска
и `mcp.tasksBoard*` не затрагиваются.
