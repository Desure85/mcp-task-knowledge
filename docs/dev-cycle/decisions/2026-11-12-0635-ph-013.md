## Вопрос

Vector-путь проверялся только unit-спеками с guard'ами; нужен e2e с реальной ONNX-моделью и
nightly-job с кешем модели.

## Решение

- `tests/vector-e2e.test.ts`: если `EMBEDDINGS_MODEL_PATH` существует, грузит реальный
  `OnnxVectorAdapter` и проверяет семантический ранкинг (`feline…` → cat, а не finance).
  Без модели тест **skip** — обычный `npm test` не качает 300+ MB.
- `.github/workflows/vector-e2e.yml`: weekly + dispatch; cache `Xenova/all-MiniLM-L6-v2`,
  `git clone` при отсутствии, `EMBEDDINGS_MODE=onnx-cpu`,
  `EMBEDDINGS_MODEL_PATH=.../onnx/model_quantized.onnx`, `EMBEDDINGS_DIM=384`,
  `ONNXRUNTIME_NODE_EXECUTION_PROVIDERS=cpu`; запускает только этот тест.
- DoD говорил `EMBEDDINGS_MODE=local`, но конфиг поддерживает `onnx-cpu`; использован он.

## Почему

- Реальный encoder проверяет загрузку native ORT, tokenizer из локальной папки и cosine-ранкинг.
- `skip` без модели сохраняет быстрый обычный прогон и avoids network flakiness.
- Nightly cache делает job воспроизводимым; модель скачивается только при промахе кеша.

## Проверено

- **Локально с реальной моделью** (`Xenova/all-MiniLM-L6-v2`, `model_quantized.onnx` 23 MB,
  скачан 327 MB repo) — **1/1**, ~1.1 s, cat ranked first.
- **Мутация RED:** сортировка `b.score - a.score` → `a.score - b.score`; тест падает;
  восстановление 1/1, build чистый.
- `npm run test:types` — чисто.
- backlog:check **373/25**.

## Ограничения

- Workflow **не запускался** в GitHub Actions; локально проверен только тест с той же моделью/режимом.
- `EMBEDDINGS_MODE=local` из DoD не существует; использован `onnx-cpu`.
- Модель `all-MiniLM-L6-v2` (384 dim); другие модели/размерности не проверены.
- Тест один запрос/две записи; ANN, cache hit и batch не входят.
