# 2026-11-11 00:00 — Z-10: реестр целевых агентов и поле `target`

- **Пункт:** Z-10 (high)
- **Ветка / sha:** `feat/z10-agent-targets`, от `origin/master` `375f378` (PR #367 влит)
- **Основание:** BACKLOG Z-10; решение владельца 2026-11-07 (Z-13); образец `project_types_get/set`

## Вопрос

Как добавить промптам и скиллам одно скалярное поле `target` (не список) с реестром агентов на
проект, не ломая старые записи без поля и не давая удалить используемую цель молча?

## Решение

- `schemas/prompt.schema.json`: `metadata.target` — строка, `default: universal`; отсутствие/пустая
  строка нормализуется в `universal` (миграция без переписывания файлов).
- `src/agents.ts`: built-in `universal`, `claude`, `opencode`; `normalizeAgentTarget`; реестр в
  метаданных проекта (`.project.json.agents`), пользовательские цели добавляются без правки ядра.
- `project_agents_get` / `project_agents_set` (`src/register/project.ts`): set принимает
  `agents[]`, `moveTo`, `moves`; built-ins всегда остаются; удаление цели, используемой промптами,
  без move отклоняется `AGENT_TARGET_IN_USE` (до 20 id в деталях); move переписывает
  `metadata.target` в исходных JSON, затем сохраняет реестр.
- `prompts_list` и `prompts_search` получают скалярный `target` (рядом с `tag`/`tags`, те не
  тронуты). Семантика: цель `universal` видна при любом запросе; конкретная цель — только при
  совпадении. `prompts_list` теперь также объединяет каталог с исходниками (created prompt виден
  без пересборки каталога) и отдаёт `target` в элементе; `prompts_search` при отсутствии build-
  артефактов ищет по исходникам.
- `src/skills/types.ts` + `skill-manager.ts`: `Skill.target` и нормализация при create/update,
  `frontmatter.target` синхронизируется.
- `docs/api-reference.md` перегенерирован (`141 tools`), `docs/features/tools.md` — обе строки и
  новый total (139/141/143).

## Почему

- Скаляр, а не список: решение Z-13; один промпт адресуется одному агенту, `universal` — общий случай.
- Реестр в метаданных проекта повторяет проверенный `project_types_set` (нормализация, запрет
  удаления используемого, moveTo), поэтому поведение предсказуемо и не требует нового хранилища.
- Отсутствие поля = `universal` — миграция без массовой перезаписи и без изменения wire-контракта
  старых промптов.

## Проверено

- `tests/prompt-targets.test.ts` — **5/5**: missing target виден при `universal` и `claude`; `claude`
  не виден при `opencode`; search с тем же фильтром; roundtrip кастомного реестра; отказ удаления
  используемой цели без moveTo; moveTo переписывает цель; оба инструмента в api-reference.
- **3 мутации RED**: фильтр `prompts_list` отключён (2 теста), удаление используемой цели без
  проверки (1), default target не `universal` (2).
- build/tsc чистые; `docs-tools-coverage` 6/6; eslint/markdownlint — в PR.

## Ограничения, записанные честно

- `project_agents_set` переписывает только промпты; скиллы живут в глобальном `SkillManager` и не
  привязаны к проекту, поэтому move для них не выполняется — это Z-12 (развёртывание по агентам).
- UI для реестра/поля `target` не добавлялся — задача backend/API.
- Built-in цели нельзя удалить (это осознанное правило, а не забытая проверка); кастомные цели
  нормализуются в lowercase slug.
- `prompts_list` теперь читает исходники в дополнение к каталогу: на очень больших проектах это
  дополнительные `get`-чтения; кэш — отдельная оптимизация.

## Откат

Revert ветки: удаляются `src/agents.ts`, два инструмента, параметры `target`, поле схемы/типов;
исходные промпты, у которых `target` уже переписан moveTo, сохранят значение — для полного отката
нужен backup или обратный `project_agents_set`.
