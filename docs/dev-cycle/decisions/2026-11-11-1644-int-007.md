## Вопрос

Jira-коннектор был единственным трекером; его заголовок обещал «Jira/YouTrack», но YouTrack REST не
поддерживался (`INT-007`). Нужен отдельный коннектор с реальными `/api` вызовами, языком запросов
YouTrack, кастомными полями и комментариями.

## Решение

- `src/connectors/youtrack.ts`, `createYouTrackConnector`:
  - `GET /api/issues?fields=…&$top=…&query=…` — `query` передаётся как есть; `project` (config или input)
    добавляется префиксом `project: <shortName>`;
  - `GET /api/issues/{id}?fields=…` — поля `State/Priority/Assignee/Type` из `customFields`, комментарии;
  - `GET /api/admin/projects?fields=…`;
  - auth `Authorization: Bearer`, `YOUTRACK_URL` + `YOUTRACK_TOKEN` (SecretManager → config → env через
    `resolveCredential`), `connectorSignal()` (TR-33);
  - `health()` — реальный `GET /api/users/me`, не просто `!!token`.
- Регистрация в `defaultConnectorRegistrations` (`YOUTRACK_CONNECTOR_ENABLED=1`), документация
  `docs/features/connectors.md`.

## Почему

- YouTrack не совместим с Jira REST v2; отдельный коннектор не ломает Jira-код и позволяет тестировать
  оба независимо.
- `query` не парсится на нашей стороне: язык запросов YouTrack — источник правды.
- Кастомные поля сплющиваются в стабильные имена (`state`, `priority`, `assignee`, `type`), чтобы
  агент не зависел от `customFields[].name`.
- Пробы health используют существующий helper и не вводят новый контракт.

## Ограничения

- Read-only: create/update/comment-write не реализованы (пункт про чтение).
- `$skip`/пагинация не реализована: только `$top` 1..100.
- `Assignee` отдаётся как `name` (fallback `login`); `State`/`Priority` — только `name`.
- YouTrack Cloud и self-hosted не различаются; базовый URL должен включать схему и хост.
- Тесты на записанных ответах; живого YouTrack в песочнице нет.

## Откат

Удалить `youtrack.ts`, экспорт/регистрацию и тест; Jira-коннектор не менялся.
