# 2026-11-13 08:00 — DX-15: `server_capabilities`

- **Пункт:** DX-15 (low, был `blocked` на design review)
- **Ветка:** `feat/dx-15-server-capabilities`, от `origin/master` `2adf141`

## Вопрос

Домены включаются/выключаются env-флагами, но агент узнаёт об этом только через
`tool not found`. Нужен манифест: версия, MCP capabilities, включённые домены, лимиты.
Контракт — до регистрации.

## Решение

ADR `docs/adr/ADR-2026-11-13-server-capabilities.md` + `src/register/capabilities.ts`:

- read-only `server_capabilities({})` без аргументов;
- `server`: name/version/toolCount/registryVersion;
- `capabilities`: `SERVER_CAPS`;
- `features`: `tools`, `tool_resources` (enabled/exec), `catalog` (enabled/read/write),
  `prompts_build`, `git_history`, `storage_index` (enabled/mode);
- `limits`: `maxPageLimit=500`, `toolsListMax=300`, `agentBootstrapTextMaxChars=4096`;
- значения берутся из тех же config-функций, что и инструменты; секреты/пути не отдаются.

## Почему

- Агент может пропустить выключенный домен вместо слепого вызова.
- Отдельно от `agent_bootstrap`: bootstrap — статический текст, manifest — операционное
  состояние env.
- Только экспортированные config-функции, без угадывания auth/cluster/connectors.

## Ограничения

- Manifest покрывает только домены с экспортированной config-функцией; auth/cluster/
  connectors и лимиты вне констант не отражены.
- Значения читаются на момент вызова (env меняется в процессе — только явные функции).
- Под requireAuth — обычный data-tool; живой клиент не проверялся.
