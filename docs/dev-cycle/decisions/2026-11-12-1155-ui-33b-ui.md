## Вопрос

Показать проектные темы на `/themes`: участник видит тему без локального импорта, может скопировать её
в личные; публикация/удаление доступны роли с правом; удаление проектной темы не ломает выбранную
личную копию.

## Решение

- API client: `api.projects.themes.list/set/remove` → `project_themes_*`.
- `ThemesScreen`: карточка **Team themes** (`useEffect` → list), `Copy` (parseTheme → личная копия,
  новый id при коллизии), `Publish current` (личная тема → `project_theme_set`), `Delete`.
- Публикация/удаление ошибку роли показывают alert-сообщением; право решает серверный T-02 гейт.
- Тема команды не становится активной напрямую: участник копирует её, поэтому удаление проектной
  записи не трогает `activeCustomId` и личную копию.

## Почему

- Copy-to-personal переиспользует существующий `applyNow`/`persist` и fallback на палитру.
- Нет нового localStorage-формата и второго источника истины: проект — источник для просмотра,
  личный store — для применения.
- Ошибки роли не дублируются в UI (не знаем роль), а приходят из сервера.

## Ограничения

- Нет отдельного Playwright-сценария на team themes; проверены типы/стражи, не живой браузер.
- `Publish current` публикует выбранную личную тему под её локальным id; редактор темы команды
  отсутствует (только publish/copy/delete).
- Удаление без подтверждения; роль не показывается, ошибка приходит после действия.

## Откат

Убрать Team themes карточку и методы `themes` из api-client; серверные `project_themes_*` останутся
аддитивными.
