## Вопрос

Дать один язык запросов вместо россыпи фильтров: поля проекта, `#tag`, `assignee`, сортировка, скобки/OR/NOT,
сохранённые поиски и ошибки для неизвестных полей.

## Решение

- `src/query/parser.ts`: lexer+recursive descent; `project/assignee/status/type/priority/tag/text/id`,
  неявный AND, `OR`, `-`/`NOT`, скобки, кавычки, `sort by:`.
- `src/query/saved.ts`: match/sort + `saved-searches.json` (upsert/delete).
- Tools: `tasks_query`, `tasks_saved_search_list/save/delete`.
- Ошибки: `QUERY_SYNTAX`, `QUERY_UNKNOWN_FIELD` (+position).

## Почему

- Грамматика маленькая и предсказуемая; AST отделён от исполнения.
- Сохранённые поиски — файл, без миграции схемы.
- `assignee` добавлен в тип Task как опциональное TK-01-поле, чтобы запросы уже работали.

## Ограничения

- `assignee: me` не резолвит «me» в userId — нужно точное значение; задачи без assignee не совпадают.
- `fields`/`dueDate` в запросах появятся после реализации TK-01 в storage.
- Фильтрация O(all tasks) в памяти; индекса для произвольных полей нет.
- Нет UI сохранённых поисков/подсказок синтаксиса.
