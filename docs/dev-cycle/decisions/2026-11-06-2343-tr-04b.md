# 2026-11-06 23:43, TR-04b: openapi и markdown тесты переписаны на реальные модули

Вопрос: как переписать два файла со статусом MOCK-DRIFT (`tests/openapi.test.ts`,
`tests/markdown.test.ts`), чтобы поломка реального модуля их красила, не потеряв ни одного
проверявшегося сценария и не трогая `src/` (TR-04b, аудит `docs/audits/TR-04-test-quality-audit.md:34-35`).

Решение:

1. `tests/openapi.test.ts` больше не содержит копию конвертера. Импортируются настоящие
   `generateOpenAPISpec` и `createOpenAPIHandler` из `src/register/openapi.ts`, вход — реальный
   `ToolRegistry` и реальные zod-схемы (`zod/v3`). Покрыты: конвертация типов и расчёт `required`,
   фильтр по `title`, теги, мета-эндпоинты, `/auth/login`, а также HTTP-маршруты
   `/api/openapi.json`, `/api/tools`, `/api/docs`, CORS-preflight и 404. Было 9 тестов, стало 12.
2. `tests/markdown.test.ts` больше не собирает export/import руками. `registerMarkdownTools`
   вызывается с mock ServerContext, который складывает обработчики в `Map` по имени (образец —
   `tests/session-tools.test.ts:22-58`), и каждый кейс вызывает зарегистрированный обработчик.
   Было 19 тестов, стало 25; все прежние сценарии сохранены.
3. Два кейса изменены осознанно, без потери проверки:
   - «imports files without frontmatter (uses filename-based title)» → «…as Untitled»: обработчик
     никогда не брал имя файла, он падает в `Untitled` (`src/register/markdown.ts:54`); старый
     ассерт уже ожидал `Untitled`, врало только название.
   - «bundle export → single import preserves content»: bundle не является форматом для обратного
     импорта — заголовок и meta-блок стоят перед frontmatter, поэтому `knowledge_import_single`
     не видит title. Кейс сохранён и проверяет то, что действительно является контрактом:
     содержимое переживает bundle → import_single, документ создаётся один.
4. Найденные дефекты `src/` не чинились (запрет поручения) и вынесены в отчёт: конвертер читает
   `_def.inner`/`_def.element`, а zod v3 даёт `innerType`/`type` → optional/default/array деградируют
   до `{}`; `_def.shape` в zod v3 это функция, поэтому настоящий `ZodObject` даёт пустые `properties`;
   ветка тега `Dependencies` недостижима (её перекрывает первый `tasks_`); `slugify` вырезает
   не-ASCII (`\w` в JS — только латиница), поэтому кириллические заголовки дают `untitled.md`.

Почему: аудит требует, чтобы тест падал при поломке SUT; coverage-конфиг исключает
`src/register/**` (`vitest.config.ts:37-48`), поэтому ценность здесь поведенческая, а не в цифрах
покрытия — цифры по `src/storage/knowledge.ts` и `src/fs.ts` остались прежними.
