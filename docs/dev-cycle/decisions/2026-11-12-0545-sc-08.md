## Вопрос

`bench:scale` был ручным. Нужен ночной гейт на 100k с порогами и падением при регрессии >2×;
искусственное замедление `listTasks` должно валить порог.

## Решение

- `.github/workflows/scale-bench.yml`: weekly cron + `workflow_dispatch`; seed 100k (`--sharded`),
  `run-scale --only tasks_list,knowledge_list --reps 3`, gate и artifacts.
- `scripts/bench/gate-scale.mjs`: сравнение median с baseline; factor 2 и absolute caps
  (500 ms tasks/knowledge, 5000 ms cold start); exit 1 при нарушении, JSON в artifact.
- `docs/benchmarks/scale-baseline.json`: baseline из `sc02-runscale-100k-2026-11-08.json`
  (tasks 28 ms, knowledge 33 ms, cold start 967 ms).
- `tests/scale-gate.test.ts`: 3/3 — baseline pass, 57 ms tasks → RED, cap/missing/cold start.

## Почему

- Baseline и caps — данные, а не зашитые в workflow числа.
- `run-scale` уже даёт median/p95/responseBytes; gate только читает JSON, поэтому его можно
  прогнать локально и в CI без сервера.
- Ночной cron не блокирует PR; артефакты сохраняются даже при падении.

## Проверено

- `tests/scale-gate.test.ts` — **3/3**.
- CLI: baseline → exit 0; tasks 60 ms → exit 1, `median 60 ms > 2x baseline 28 ms`.
- `markdownlint` docs; `npm run build` не затрагивался; backlog:check **370/28**.
- **Мутация**: тест с 57 ms ловит регрессию; без factor-проверки он бы прошёл.

## Ограничения

- Workflow **не запускался** в этом окружении: GitHub Actions недоступен; зелёный nightly на
  master не подтверждён. Локально проверены только gate-логика и baseline.
- «Искусственное замедление `listTasks`» проверено подменой median в JSON, а не правкой
  `listTasks` + полным 100k прогоном; это дешёвая проверка гейта, не сервера.
- Baseline — один прогон на конкретной машине; CI runner может быть медленнее. Caps 500 ms
  выбраны с запасом, factor 2 остаётся основным сигналом.
- `knowledge_list` на 100k в baseline есть, но seed `--tasks-only` создаёт 0 документов;
  ночной job тоже сеет только задачи, поэтому knowledge-порог проверяется на пустом проекте.
