# 2026-11-11 11:00 — UI-39: метки «на критическом пути» и «блокирует N»

- **Пункт:** UI-39 (high); опирается на UI-38 и V-02
- **Ветка / sha:** `feat/ui-39-graph-metrics`, от `origin/master` `405ddd4` (PR #378 влит)
- **Основание:** BACKLOG UI-39; `tasks_list`/`tasks_get`, `getCriticalPath`, `getBlockedByTask`

## Вопрос

Как показать на карточке задачи две независимые метки — «на критическом пути» и «блокирует N
транзитивно» — не считая дорогой граф на каждом обычном `tasks_list` и не кодируя смысл только цветом?

## Решение

- **Сервер:** новый `src/register/graph-metrics.ts`:
  - `dependentsCount` — обратный BFS по `dependsOn` (прямые + все транзитивные, unique);
  - `onCriticalPath` — членство в `getCriticalPath(tasks)` (длиннейшая цепочка, существующее
    определение storage).
- `tasks_list` и `tasks_get` получили **opt-in** `includeGraphMetrics` (по умолчанию выключен, чтобы
  не удорожать обычный список); при включении поля добавляются в каждый item, включая batch-ветку
  `ids/codes`. Успешный wire-формат старых полей не менялся.
- **UI:** `TaskCard` показывает две текстовые метки с иконкой: `Critical path` и `Blocks N`
  (`Badge` + `IconDependencies`); тон `Blocks N` — `medium`, при N≥3 — `blocked` (семантические
  токены), но текст/иконка остаются, поэтому смысл не зависит от цвета. Метка приоритета —
  отдельная полоска `PriorityDot`, не смешивается.
- `TaskQuickView` и полная страница показывают те же метки; `tasks_get` вызывается с флагом, после
  сохранения метрики сохраняются в локальном состоянии.
- `api-client`: `Task.onCriticalPath?/dependentsCount?`, `tasks.get(...,{includeGraphMetrics})`,
  `tasks.list` запрашивает флаг.

## Почему

- Транзитивные зависимые — это обратный обход, а не `getBlockedByTask` (тот прямой); поэтому новый
  helper, а не изменение семантики существующего.
- Opt-in флаг сохраняет стоимость обычного списка; UI задач включает его, потому что карточки
  показывают метки.
- Текст+иконка удовлетворяют DESIGN.md §6 (не только цвет); тон — вторичный сигнал.

## Ограничения, записанные честно

- Метрики **не входят в обычный `tasks_list`** без флага; UI списка задач теперь всегда просит флаг,
  то есть платит O(граф) на страницу — для больших проектов это кандидат в SC-04.
- `getCriticalPath` — существующее определение длиннейшей цепочки; семантика «критичности» по
  времени/ресурсам не вводилась.
- **SQLite-профиль** не хранит `dependsOn`, поэтому на демо-SQLite обе метки пустые; файловый/CI
  зелёный (pre-existing Y-05 gap).
- Метки на карточке в list-view сортировку/фильтры не учитывают; это визуальный слой.

## Откат

Revert ветки: удаляются `graph-metrics.ts`, флаги `includeGraphMetrics` в `tasks_list/get`, поля
`Task.onCriticalPath/dependentsCount`, метки в карточке/диалоге/странице и тесты. Существующие
`dependsOn`/DAG-инструменты не меняются.
