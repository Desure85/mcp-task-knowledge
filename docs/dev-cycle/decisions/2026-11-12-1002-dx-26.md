## Вопрос

Оставались последние части DX-26: `ui` (HTTP + открыть браузер) и actionable-ошибки запуска
(занятый порт → `--port`, не writable `DATA_DIR` → hint).

## Решение

- `src/cli/ui.ts`:
  - `ui [--port N] [--host H] [--no-open]`, по умолчанию `MCP_PORT`/3001 и `127.0.0.1`;
  - запускает `AppContainer({ transportType: 'http' })`, печатает URL, открывает браузер
    (`cmd start` / `open` / `xdg-open`);
  - `EADDRINUSE` → hint про `--port`/`MCP_PORT`; wildcard-bind → browser-safe `127.0.0.1`.
- `src/index.ts`: `main().catch` для `EADDRINUSE`/`DATA_DIR must be set` печатает `startup: …` и
  `hint: …` вместо только fatal-лога; ServerLock-ветка сохранена.
- Тест `tests/ui-cli.test.ts` — парсинг, URL, hints; реальный HTTP-старт не спавнится.

## Почему

- `ui` — тонкая обёртка над существующим HTTP-транспортом, без второго сервера.
- Ошибки запуска должны говорить, что делать, а не только код.
- Browser-open не критичен для теста; URL/hints детерминированы и покрыты.

## Проверено

- `tests/ui-cli.test.ts` — **4/4**.
- `node dist/index.js ui --help` → usage, exit 0.
- `npm run build` — чисто; bundle пересобран.
- backlog:check **378 done / 20 pending / 22 blocked / 1 deferred**; DX-26 закрыт (подпункты a/b/c/d).
- Мутация не применима к CLI-парсингу; ветка `startupHint` покрыта прямыми кейсами.

## Ограничения

- `ui` открывает MCP HTTP endpoint, не Next.js web-ui; web-ui запускается отдельно.
- Реальный старт HTTP и открытие браузера не проверялись в CI (нет GUI/порта).
- `DATA_DIR`-hint срабатывает только если сообщение содержит `DATA_DIR must be set`.
- `ui` не демонизируется: процесс живёт до Ctrl+C.

## Откат

Удалить `src/cli/ui.ts`, ветку `ui` и hint-код в `src/index.ts`, тест; поведение обычного server
возвращается к прежнему fatal-логу.
