## Вопрос

Какая аддитивная модель задачи закрывает исполнителя, срок, поля проекта, комментарии и типы связей,
не ломая wire-формат и не требуя переписывания файлов?

## Решение

Принят `docs/adr/ADR-2026-11-12-task-model.md`:

- опциональные `assignee`, `dueDate`, `fields`, `relations`;
- `ProjectMetadata.fields` (string/number/boolean/date/enum/user, required/default/options);
- комментарии — append-only `comments/<project>/<taskId>.jsonl`, mentions `@user`;
- `dependsOn`/`parentId` остаются каноническими, `relations` — только relates/duplicates/blocks;
- schema 1→2 — no-op для файлов, новые поля опциональны; откат — вернуть CURRENT_SCHEMA=1.

## Почему

- Аддитивность сохраняет старые задачи и клиентов; индекс и запросы (TK-02) получают данные без миграции.
- Комментарии отдельно не раздувают task JSON и дают append-only аудит.
- Поля проекта — конфиг, а не свободный JSON: динамическая zod-валидация и понятные ошибки.
