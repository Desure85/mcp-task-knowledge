## Вопрос

Как реализовать Postgres-профиль для Store-коллекций, не сломав wire-формат, и как проверить его на
реальном PostgreSQL, если Docker-демона нет, а токен `gh` не даёт изменить CI-воркфлоу (scope
`workflow`), — то есть как не выдать «зелёные тесты на моках» за закрытый DoD?

## Решение

1. **Гейт среды снят локально:** npm-пакет `embedded-postgres` (в scratch-каталоге, не зависимость
   проекта) поднимает **настоящий PostgreSQL 18.6** отдельным процессом; `pg@8.23.1` +
   `@types/pg@8.15.6` добавлены точными версиями. Тесты запускаются с `POSTGRES_URL` против этой
   СУБД: `select version()`, DDL, транзакции, advisory-замки — реальный движок, не самописный мок.
2. **`db.ts`:** пул соединений, схема — JSONB-документы задач/документов, `doc_versions`,
   `projects`, `events`/`snapshots`, `locks`, `search_index` (generated `tsvector` + GIN — задел
   Y-06a2), `search_state`; `pg_trgm` ставится при наличии прав и репортится флагом; `TRUNCATE`
   таблиц в тестах даёт изоляцию.
3. **Профиль `createPostgresProfile({connectionString, blobsDir?})`** (async): `TaskStore`
   (list/page с курсорами и countOnly, CRUD, lifecycle, tree/children/subtree, cascade), `DocStore`
   (CRUD, archive/trash/restore, версии на create/update, `restoreVersion` через `patchDoc`),
   `ProjectStore` (create/list/detail со stats/read/update metadata/workflow/remove с force),
   `HistoryProvider` (документные версии; task history — `CAPABILITY_UNAVAILABLE`), `EventLogStore`
   (write-behind), `LockProvider` — `pg_advisory_xact_lock` на выделенном соединении (сериализация
   между процессами, освобождение на commit/rollback). Промпты/память/блобы переиспользуют файловые
   реализации (как SQLite-профиль, с тем же записанным ограничением).
4. **`profile-select.ts`/`setup.ts`:** `STORAGE_PROFILE=postgres` — валидный вид; синхронная фабрика
   `createStorageProfile` отказывает с указанием на async `createPostgresProfile`; `setup` читает
   `POSTGRES_URL`, при отсутствии — `CONFIG_MISMATCH` с подсказкой, ошибка открытия заворачивается в
   `CONFIG_MISMATCH`, а не теряется. Файловый профиль остаётся значением по умолчанию.
5. **Явные ограничения, записанные в коде и решении:** `SearchProvider` в контракте синхронный, а
   `pg` асинхронный — поиск вынесен в Y-06a2 (сейчас `fullText=false`, пустые кандидаты, честно);
   `EventLogStore` тоже синхронный — журнал работает write-behind кэшем с `flush()` (durable-вставка
   идёт следом, семантика фиксируется в решении, а не замалчивается); claims задач, как в SQLite
   Y-05a1, объявлены `CAPABILITY_UNAVAILABLE`; `pgvector` в окружении нет — векторы ждут Y-06b.

## Почему

- JSONB-документы сохраняют ровно те объекты, что отдают инструменты, поэтому wire-формат не зависит
  от профиля; контрактные данные (версии, проект, замки) вынесены в отдельные таблицы, где нужны
  запросы/транзакции.
- Advisory-lock — самый короткий честный способ получить межпроцессную сериализацию без отдельной
  таблицы lease-ов и фонового GC.
- Write-behind журнал и отложенный поиск лучше, чем синхронная ложь: оба ограничения видны в
  манифесте (`fullText=false`), в коде и в решении.

## Проверено

- `tests/storage-postgres.test.ts` — **12/12 против реального PostgreSQL 18.6** (запуск с
  `POSTGRES_URL`; без него набор документированно пропускается): манифест и честные недоступные
  возможности, task lifecycle/фильтры/пагинация/countOnly/tree/cascade, документы и версии/restore,
  история документов + отказ по task history, проекты/metadata/workflow/remove с force, события
  (append/since/snapshot/compact/перезагрузка из БД), сериализация замков и освобождение после
  исключения, делегирование prompts/memory/blobs, выбор профиля по env.
- Затронутые наборы: `storage-postgres`, `storage-sqlite` (ожидание `postgres` как известного вида),
  `storage-wiring`, `storage-contract`, `blob-provider` — **97/97 + 1 skip** (skip — MinIO без
  `BLOB_S3_*`); `tsc` test-проекта чистый, build зелёный.
- Revert-check: **6 мутаций RED** — tasks.list без фильтра project, page без cursor, doc update без
  повышения версии, task history отдаёт пустой список вместо `CAPABILITY_UNAVAILABLE`, `withLock` без
  advisory-lock, event id не монотонен.
- Среда: CI-сервис Postgres **не добавлен** — push workflow отклонён без scope `workflow`; это
  ограничение записано, проверка выполнена локально на настоящем PostgreSQL 18.6 (embedded), а не на
  моке. Для CI нужен один шаг `services: postgres` от владельца токена с `workflow` scope.

## Откат

Revert ветки: удаляются `src/storage/profiles/postgres/{db,index}.ts`, `tests/storage-postgres.test.ts`,
