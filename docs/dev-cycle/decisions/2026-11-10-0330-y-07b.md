# 2026-11-10 03:30 — Y-07b: S3/MinIO BlobProvider (закрывает Y-07)

- **Пункт:** Y-07b (закрывает Y-07 «BlobProvider: S3 и MinIO»)
- **Ветка / sha:** `feat/y07b-s3-blob-provider`, от `origin/master` `dc1d8be` (PR #342 влит)
- **Основание:** ADR-009 (абстракции за профилями), решение Y-07a (контракт `BlobProvider`),

## Вопрос

Как реализовать S3/MinIO-совместимый `BlobProvider` без новой зависимости, доказать, что он проходит
тот же контракт, что и файловый провайдер, и проверить подпись SigV4, если локальный Docker недоступен?

## Решение

1. **`src/storage/blobs/s3-blob-provider.ts`:** S3-адаптер на `fetch` + локально реализованный AWS
   Signature Version 4 (canonical request → string to sign → signing key → `Authorization`) без
   сторонних SDK. `put/get/size/delete/list` повторяют контракт `BlobProvider`; ключи валидируются
   тем же `assertValidBlobKey`, что и в файловом провайдере. Контрольная сумма — `sha256:<hex>`,
   кладётся и возвращается через `x-amz-meta-sha256` (заголовок входит в подписанные). `list(prefix)`
   использует S3 `list-type=2` и добирает метаданные HEAD-запросами. Bucket создаётся лениво
   (`HEAD bucket` → `PUT bucket`), если `createBucket !== false`; `pathStyle` по умолчанию true (MinIO).
   `capabilities.presign=false` — presigned URL не реализованы, и врать в capabilities нельзя.
2. **`s3BlobProviderConfigFromEnv()`** — конфигурация из `BLOB_S3_ENDPOINT/BUCKET/REGION/ACCESS_KEY/
   SECRET_KEY`; неполный набор → `undefined`, а не частично настроенный клиент.
3. **Один контрактный набор:** `tests/blob-provider.test.ts` уже экспортирует `runBlobProviderContract`;
   Y-07b прогоняет через него файловый провайдер, S3-адаптер против встроенного fake S3-сервера
   (локальная проверка протокола: SigV4-заголовки, checksum, bucket, prefix) и **против реального MinIO,
   когда заданы `BLOB_S3_*`**.
4. **MinIO-прогон (среда):** контрактный набор автоматически прогоняется против реального MinIO,
   когда заданы `BLOB_S3_*` — MinIO отвергает неверную подпись, поэтому это настоящая
   криптографическая проверка, которую fake сервер дать не может. **Попытка добавить сервис MinIO в CI
   (`bulk-smoke`) не удалась**: push отклонён GitHub («refusing to allow an OAuth App to create or update
   workflow … without `workflow` scope»), токен `gh` в этой среде не имеет scope `workflow`. Изменение
   воркфлоу не влито; это ограничение среды записано, а не выдано за проверку. План (гейт 3) допускает
   документированный ручной прогон: локально Docker-демон недоступен — набор с MinIO пропускается
   `describe.skip` с объяснением, fake-сервер и 6 мутаций остаются локальным гейтом, а MinIO-прогон
   выполняется там, где есть Docker или workflow-scope для CI-сервиса.
5. **Область применения не меняется:** MinIO/S3 используется только для вложений, экспортов и копий,
   не как основное хранилище задач/документов (ADR-009); потребителей в инструментах пока нет — это
   отдельный инкремент после миграции (Y-08).

## Почему

- SDK ради SigV4 утяжелил бы зависимости и спрятал бы проверку подписи; собственная реализация
  укладывается в один файл и тестируется на реальном MinIO в CI.
- Один `runBlobProviderContract` на оба бэкенда — единственное доказательство совместимости: разные
  наборы тестов разъехались бы и различия всплыли бы в продакшене.
- `presign=false` честнее, чем флаг, который нечем подтвердить.

## Проверено

- `tests/blob-provider.test.ts` — **18 passed, 1 skipped** локально (skip = MinIO без `BLOB_S3_*`,
  задокументирован): 7 кейсов общего контракта на файловом провайдере, 7 на S3-fake (тот же набор),
  SigV4-поля запроса (`Credential=…/us-east-1/s3/aws4_request`, подписанные `x-amz-content-sha256`
  и `x-amz-meta-sha256`, payload hash), NOT_FOUND/delete/list, prefix изоляция (URL содержит
  `/bucket/prefix/key`), конфигурация из env, maxBytes.
- Затронутые наборы: `blob-provider`, `storage-wiring`, `storage-contract` — **51/51** (+1 skip);
  `tsc` test-проекта чистый, build зелёный.
- Revert-check: **6 мутаций RED** — checksum не sha256, 404 на GET отдаёт пустые байты, delete
  отсутствующего ключа возвращает true, prefix не применяется к URL, bucket не создаётся, валидация
  ключа отключена.
- Ограничение среды: Docker-демона локально нет, CI-сервис MinIO не добавлен из-за отсутствия
  `workflow` scope у токена; MinIO-часть контракта запускается при заданных `BLOB_S3_*` (ручной прогон
  по `docs/features/blob-storage.md` или инфраструктура с workflow-scope), а не выдаётся за проверенную.

## Откат

Revert ветки: удаляются `s3-blob-provider.ts`, S3-часть тестов и CI-сервис MinIO с `BLOB_S3_*`;
контракт `BlobProvider` и файловый провайдер (Y-07a) остаются без изменений. Задачи, документы,
поиск и wire-формат не затрагиваются.
