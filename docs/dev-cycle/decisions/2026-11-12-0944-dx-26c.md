## Вопрос

DX-26 требует `uninstall` — вычистить клиентские конфиги, установленные `install-agent`.

## Решение

- `src/cli/uninstall-agent.ts`: читает `<home>/.mcp-task-knowledge/<client>-install-manifest.json`.
- Для каждой записи:
  - managed-файл: удаляется только если sha256 совпадает с манифестом (иначе `skipped`);
  - config-файл: удаляется ключ `mcp-task-knowledge` из `mcp` (opencode) или `mcpServers` (claude-code),
    JSON перезаписывается атомарно-подобно (temp не нужен: файл мал).
- `--dry-run` печатает план и ничего не меняет; manifest удаляется только в реальном прогоне.
- Пути ограничены `home`; выход за home — `skipped`, не удаляется.
- `uninstall` диспетчеризуется в `src/index.ts` до `AppContainer`.

## Почему

- Источник истины — манифест установки, а не эвристика «удали всё, что похоже на наше».
- Проверка sha защищает пользовательские правки: изменённый файл не удаляется молча.
- `--dry-run` даёт безопасный предпросмотр.

## Проверено

- `tests/uninstall-agent.test.ts` — **3/3**: удаление managed-файла + config-ключа, dry-run без
  изменений, отсутствие манифеста → 0.
- `npm run build` — чисто; bundle пересобран; backlog:check **377/21**.

## Ограничения

- Имя сервера в конфиге захардкожено `mcp-task-knowledge`; bundle с другим именем не вычистится.
- Backup-файлы `install-agent` не удаляются (это история).
- Нет e2e-спавна `dist/index.js uninstall`; проверена функция + build.
- `claude-code` config-путь `.claude.json`; `XDG_CONFIG_HOME` учитывается только для opencode.

## Откат

Удалить `src/cli/uninstall-agent.ts`, ветку `uninstall` в `src/index.ts` и тест; manifest-файлы
пользователей не затрагиваются.
