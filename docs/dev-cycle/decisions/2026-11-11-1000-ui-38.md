# 2026-11-11 10:00 — UI-38: зависимости в карточке и отдельный DAG-маршрут

- **Пункт:** UI-38 (high); опирается на UI-36/UI-37 и SC-01
- **Ветка / sha:** `feat/ui-38-dependencies`, от `origin/master` `a5a0e75` (PR #377 влит)
- **Основание:** BACKLOG UI-38; AC-02/AC-03; `tasks_get_deps`, `tasks_dag`

## Вопрос

Как показать зависимости задачи со статусами, отдельным признаком «заблокирована», редактированием
рёбер с серверным отказом на цикл — и убрать общую сводку с кнопки над доской в маршрут с настоящими
серверными фильтрами?

## Решение

- **Сервер:** цикл зависимости теперь бросает `WorkflowError('DEPENDENCY_CYCLE', …, { taskIds })`,
  поэтому `tasks_update` возвращает стабильный код, а не только текст (аддитивное изменение
  error-контракта; успешные ответы не менялись).
- **`api-client`:** `tasks.getDeps(project,id)` и `tasks.dag(project,{tag,limit,onlyWithDeps})`;
  `DagData` получил необязательные `truncated/returnedNodes`.
- **Полная страница `/tasks/<id>`:** блок зависимостей показывает:
  - `isBlocked` отдельно от статуса («Blocked by unmet dependencies»);
  - `dependsOn`/`dependedBy` со статусами и ссылками;
  - цепочку до корня (первый путь, ≤10, cycle-safe);
  - поиск задачи, Add/Remove ребра; после изменения оба конца видны через `tasks_get_deps`;
  - `DEPENDENCY_CYCLE` показывается кодом и сообщением, состояние не меняется.
- **Быстрый просмотр UI-36:** те же статусы блокеров/зависимых, `isBlocked` и цепочка до корня.
- **Отдельный маршрут `/tasks/dag`:** tag/limit/onlyWithDeps уходят аргументами в `tasks_dag`;
  кнопка над доской теперь ведёт туда, а не открывает клиентскую сводку.
- `tasks_get_deps` остаётся источником статусов/`isBlocked`; `tasks_dag` — рёбер/страницы/фильтров.

## Почему

- Один серверный код цикла позволяет UI отличать цикл от прочих ошибок, не парся текст.
- `tasks_get_deps` уже считает `isBlocked` по workflow (не по статусу), поэтому UI не дублирует
  правило «done = выполнено».
- Отдельный маршрут делает фильтры реальными серверными аргументами (AC-03), а не срезом одной
  страницы.

## Ограничения, записанные честно

- **SQLite-профиль** не сохраняет `dependsOn` через `tasks_update` и не отдаёт DAG-рёбра
  (`tasks_dag.edges=[]`), поэтому на демо-SQLite блок зависимостей пуст; файловый профиль/CI зелёный.
  Это тот же известный разрыв Y-05, не замаскирован.
- UI-31 (критический путь / «что заденем») не входит в UI-38; здесь только цепочка до корня и
  `isBlocked`.
- `tasks_dag` page-limited; рёбра за страницей не видны (SC-04).
- Поиск для добавления ребра — по загруженному `tasks_list`, без серверного поиска.

`DEPENDENCY_CYCLE`; кнопка возвращается к inline-сводке. UI-36/UI-37 не затрагиваются.
