# 2026-11-13 07:40 — DX-12: `agent_bootstrap`

- **Пункт:** DX-12 (medium, был `blocked` на design review)
- **Ветка:** `feat/dx-12-agent-bootstrap`, от `origin/master` `70128be`

## Вопрос

Агент видит ~207 инструментов и короткий `instructions`, но не знает конвенций: передавать
`project`, проверять `ok`, использовать CAS, подтверждать разрушающие действия. `briefing`
отдаёт данные, а не инструкцию по серверу. Нужен контракт `agent_bootstrap` до регистрации.

## Решение

ADR `docs/adr/ADR-2026-11-13-agent-bootstrap.md` + реализация `src/register/bootstrap.ts`:

- `agent_bootstrap({project?})` — read-only; отдаёт `server` (version/toolCount/
  registryVersion/capabilities), `project`, `instructions` (markdown ≤4096), `tools`
  (`total/recommended/disabled`), `envelope`;
- `recommended` фильтруется по фактическому registry; отсутствующие попадают в `disabled`;
- никаких задач/документов/памяти/секретов; project только отчётный;
- CAPS — тот же `SERVER_CAPS`, что в initialize; DX-15 остаётся отдельным манифестом
  env-флагов/лимитов.

## Почему

- Инструкция версионируется вместе с сервером и не копируется в вики.
- Фильтрация recommended по registry не врёт про выключенные профилем tools.
- Отдельно от `briefing`: данные и «как пользоваться» — разные контракты.

## Ограничения

- Текст статический: меняется только с кодом; локализации нет.
- `server_capabilities` (DX-15) не реализован — в bootstrap только MCP CAPS.
- Под requireAuth инструмент гейтится как обычный data-tool; pre-auth доступен только в
  открытом локальном режиме.
- Живой клиент (Claude/OpenCode) не проверялся — unit на моке registry.

## Откат

Удалить `bootstrap.ts`, регистрацию, тест, ADR; перегенерировать API reference (206/204);
вернуть DX-12 в `blocked`, сводку 415/12.
