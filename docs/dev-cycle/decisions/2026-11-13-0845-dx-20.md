- **Пункт:** DX-20 (low, был `blocked` на research)

## Вопрос

Реален ли `mcp-task-knowledge.exe` без Node ≥20? Прошлый PoC (2026-09-12) нашёл ограничения
better-sqlite3/ONNX, но отчёт не был оформлен и не перепроверялся на текущем коде.

## Решение

Проведён повторный PoC на Bun 1.3.13 (Windows x64, `master` `8f06ec5`):

- `bun build --compile src/index.ts` → 1003 модуля, bundle 6.4 с, compile 1.3 с, **117.8 MB**;
- бинарь запущен без Node, `initialize` по stdio отвечает `protocolVersion 2025-06-18`,
  capabilities logging/resources/tools/prompts, exit 0;
- отчёт `docs/benchmarks/dx-20-single-binary.md` с методикой, findings и reproduction.

Найденные ограничения:

1. `serverInfo.version = 0.0.0`: бинарь не читает `package.json` из `$bunfs`; нужна инъекция
   версии при сборке.
2. SQLite/ONNX не проверены: smoke на file profile + `EMBEDDINGS_MODE=none`; native
   better-sqlite3 по прошлому PoC падает, ONNX `.so/.dll` не инлайнится.
3. Только Windows x64; нет подписи, установщика, per-platform матрицы, checksums.

## Почему

- Для узкого профиля (file storage, без эмбеддингов) single-binary реально работает.
- Но выпускать его как официальную поставку нельзя: версия врёт, нативные пути не проверены.
- DX-21 (Homebrew/Scoop) остаётся blocked до реального release pipeline.
