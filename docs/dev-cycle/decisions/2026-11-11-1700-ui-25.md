## Вопрос

Где общий доступный TreeView, как показать вложенность задач в списке (с прогрессом, созданием
подзадачи и выбором родителя) и дерево документов с хлебными крошками, не добавляя новый серверный
формат?

## Решение

- **`components/ui/TreeView`** — настоящие `role=tree`/`group`, `aria-expanded` на ветках,
  раскрытие/сворачивание, кнопки-строки, selected/`aria-current`. Хелперы `lib/tree.ts`
  (`treeIds`, `descendantCount`, `visibleTree`) и компонентный тест.
- **Задачи (list view):**
  - каждая строка получила раскрытие; `tasks_get_children` подгружает детей по требованию,
    глубина показывается отступом;
  - у родителя — прогресс `done/total` по загруженным детям и статусному category/closeStatus;
  - «Add subtask» открывает создание с уже выбранным родителем; в форме создания появился
    `Parent task` (select из загруженных задач);
  - при создании `parentId` уходит в `tasks_create`; список перезагружается штатно.
- **Knowledge:**
  - переключатель `List/Tree`; дерево строится из `knowledge_tree` (id/title/type/children);
  - выбор узла открывает документ; в режиме чтения — `Breadcrumb` по `parentId`;
  - в редакторе появился `Parent document` (`null` для корня), сохранение через
    `knowledge_bulk_update.parentId`; при создании родитель применяется вторым update;
  - в карточках списка/поиска показывается путь предков, если они есть в загруженной странице.

## Почему

- `knowledge_tree` уже отдаёт иерархию, а `parentId` уже принимается bulk-update — новый wire-формат
  не нужен.
- Дети задач грузятся только при раскрытии, поэтому глубина не превращает страницу в полный обход
  дерева.
- Один общий TreeView исключает вторую реализацию для Z-03 (дерево файлов скилла).

## Ограничения

- Список задач остаётся page-limited (SC-04): дети, не попавшие в страницу, появляются после
  раскрытия через `tasks_get_children`; родитель, которого нет в текущей странице, показывается
  корнем.
- `Parent task`/`Parent document` предлагают только загруженные элементы, серверного поиска родителя
  нет.
- В Knowledge дерево `knowledge_tree` читает все документы (как и раньше); в режиме `Tree` на очень
  больших проектах это дороже, чем список.
- Путь в результатах поиска строится по загруженной странице; если предок за её пределами, путь
  неполный.
- Клавиатурная навигация TreeView — Tab + Enter/клик и отдельные expand-кнопки; roving tabindex и
  стрелки между строками не реализованы (DoD просил aria-expanded, не полный WAI-ARIA APG).

## Откат

Revert ветки: удаляются TreeView/`lib/tree.ts`/тесты, дерево задач и knowledge-переключатель,
parent select и breadcrumbs; UI возвращается к плоскому списку и карточкам. Серверный формат и
существующие инструменты не меняются.
