## Вопрос

Overview показывал задачи и просроченные документы, но не давал ответа «что не так со знаниями»:
устаревшие memory-факты, противоречия, документы без связей и самые связанные узлы. Нужен обзор с
действиями «открыть / проверить / связать», опираясь на существующие `memory_verify` и граф.

## Решение

Новый `web-ui/components/KnowledgeHealth.tsx` (над `OverviewAttention`), данные — только существующие
MCP-инструменты, без нового серверного формата:

- **Stale memory facts** — `memory_verify({project, limit:200})`; список `status==='stale'`, кнопка
  «Проверить» повторяет U-05 (без отдельного single-fact API) и показывает
  `memory_verify: проверено N, устаревших M`; при `REPO_INVALID` — `role=alert` с ошибкой, не
  пустой экран.
- **Possibly contradictory facts** — `memory_temporal_query({includeInvalidated:true,limit:200})`;
  показывает `valid===false`/`invalidationReason`/`supersededBy` с причиной. Это эвристика
  «инвалидировано», не семантическое доказательство противоречия.
- **Documents without links** — `knowledge_list`; документ без `parentId` и без детей (по
  `parentId` других документов). `memory_fact` исключены (они уже в stale-секции). Действие
  «Связать» ведёт в `/knowledge?doc=…`, где U-25 даёт parent select.
- **Most connected nodes** — `web-ui/lib/graph-model.buildGraph(facts,'entities')`, top-5
  `entity` по `degree`, ссылка `/graph?entity=…` (UI-30).
- API-клиент: `api.memory.verify` + `MemoryVerifyResult`.
- Ссылки: stale/unlinked → `/knowledge?doc=`, connected → `/graph?entity=`, пустые состояния на
  каждой карточке.

## Почему

- `memory_verify` — единственный источник истины о живых якорях; UI не переизобретает проверку.
- Единый `buildGraph` гарантирует те же узлы/степени, что и `/graph`, без второго алгоритма.
- «Противоречия» честно названы *possible*: temporal invalidation — это факт истории, а не
  семантический contradiction detector.
- Unlinked по parent/child — существующая модель связей UI-25; tags/mentions не считаются связью.

## Ограничения

- `memory_verify` использует `repo` по умолчанию = cwd MCP-сервера; при запуске не из git-checkout
  секция покажет `REPO_INVALID` (honest error).
- Проверка не per-fact: кнопка «Проверить» пересканирует до 200 фактов.
- «Contradictions» — только invalidated temporal facts; семантические противоречия между фактами
  не вычисляются.
- Unlinked учитывает только parent/child, не теги/упоминания/граф memory.
- Списки ограничены 5 элементами; `knowledge_list` в UI использует `callToolAll` и может быть
  дорогим на очень больших базах.
- Граф — до 200 temporal facts (как `/graph`), степени не транзитивные.
- «Связать» открывает редактор, а не отдельный диалог связывания.
