# 2026-11-11 16:59 — U-02: `changes_since` delta feed

- **Пункт:** U-02 (medium), мягкая зависимость MU-03
- **Ветка / sha:** `feat/u-02-changes-since`, от `origin/master` `ca00528`

## Вопрос

Агент, опрашивающий сервер, не мог спросить «что изменилось с момента T»: `dashboard_activity` — это
последние N событий без фильтра по времени, а у задач/документов нет общего delta-эндпоинта.

## Решение

Новый MCP-инструмент `changes_since({since, project?, types?, includeDeleted?, limit?})`:

- `since` — ISO, включительно; невалидный → `INVALID_SINCE`;
- источники:
  - задачи (`tasks.list`, включая archived/trashed) по `updatedAt`;
  - документы (`docs.list`) по `updatedAt`;
  - temporal-факты (`TemporalGraph.query({includeInvalidated:true,limit:1000})`) по `recordedAt`
    (и `validTo` для инвалидации);
- `change`: `created|updated|closed|archived|trashed` для задач; `created|updated|archived|trashed` для
  документов; `recorded|invalidated` для памяти;
- `includeDeleted` по умолчанию `false` скрывает archived/trashed задачи и документы;
- `limit` 1..500 (default 100), сортировка newest-first;
- ответ `{since, project, count, total, nextSince, items}`; `nextSince` — максимум `since` и самого
  свежего item, поэтому поллер может двигаться без пропусков/наложений.

## Почему

- `updatedAt` уже есть у task/doc; temporal-факты имеют `recordedAt`/`validTo`, поэтому U-02 можно
  закрыть до MU-03, не выдумывая новую модель версий.
- `nextSince` детерминирован и не зависит от числа `limit`.
- Отсутствие/порча temporal-файла не скрывает task/doc-дельту (try/catch только для памяти).
- Новый инструмент аддитивен; формат существующих ответов не менялся.

## Ограничения

- Нет tombstone-записей: удалённые из archived/trashed **без updatedAt** не видны; `includeDeleted` — это
  archived/trashed, не hard-delete.
- `updatedAt` на файловом профиле имеет mtime-точность; два изменения в одну мс могут слиться.
- temporal graph читается с `limit:1000` и без project-фильтра: при >1000 фактов хвост выпадает.
- `nextSince` — эвристика по времени, не курсор; при равных timestamp возможны повторы.
- Документы не разделены на `memory_fact` и обычные в `types:'knowledge'`; память идёт отдельным kind.
