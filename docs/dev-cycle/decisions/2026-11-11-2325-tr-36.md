## Вопрос

`github_*`, `jira_*`, `slack_*` бросали исключение из handler'а; MCP-клиент получал protocol
`isError`, тогда как gdrive/gmail/notion/onedrive/linear возвращали `{ok:false,error:{message}}`.
Одинаковые сбои API выглядели по-разному в зависимости от коннектора.

## Решение

- `src/connectors/errors.ts`: `ConnectorErrorEnvelope` и `connectorError(unknown)`.
- В каждом из трёх коннекторов регистрация обёрнута локальным `reg(...)`: вызывает исходный
  handler в `try/catch` и возвращает конверт при ошибке.
- Успешные ответы (`{ok:true,data}`) не менялись; имена инструментов и схемы не менялись.
- Docs `docs/features/connectors.md` фиксирует общий конверт.

## Почему

- Единый конверт позволяет агентам обрабатывать сбой коннектора без разбора protocol `isError`.
- Обёртка на границе регистрации не трогает бизнес-логику fetch/parse и не подавляет ошибки health:
  health по-прежнему возвращает `{healthy:false,message}`.
- Валидационные ошибки (например, отсутствующий Slack channel) теперь тоже видны как `ok:false`,
  а не как protocol error.
