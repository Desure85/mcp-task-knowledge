# 2026-11-11 21:04 — Z-06: происхождение, снимок и обновление по diff

- **Пункт:** Z-06 (medium), зависит от Z-05
- **Ветка / sha:** `feat/z-06-prompt-provenance`, от `origin/master` `a2a1a84`

## Вопрос

Z-05 умеет импортировать prompt/skill из marketplace/GitHub, но не запоминает происхождение и не
защищает локальные правки: обновление из источника могло перезаписать изменённый пакет, отката и
снимков не было.

## Решение

`src/prompts/provenance.ts` — `PromptProvenanceStore` с раскладкой
`<root>/<id>/{manifest.json,files/,snapshots/<snapshot>/files/}`:

- **manifest**: `source` (kind/id/url/version/commit/license/retrievedAt), `importedAt`,
  SHA-256 по отсортированным `path\0length\0content`, `snapshotId`, `history`.
- `import`: отказ на существующий id; `{overwrite:true}` архивирует старый state и сохраняет
  history.
- `status`: пересчитывает hash текущих файлов, `modified = hash !== importedHash`.
- `diff(current,next)`: path-level `added|changed|removed`.
- `update`: при отсутствии правок — no-op с пустым diff; при `modified` —
  `ProvenanceError('MODIFIED')` и **никакой записи**; только `{force:true}` перезаписывает.
  Перед обновлением сохраняется snapshot, затем новый; history пополняется.
- `rollback(id,snapshotId)`: архивирует текущее состояние и восстанавливает snapshot.
- Безопасность: `id` — только `[a-zA-Z0-9][a-zA-Z0-9._-]*`; пути — относительные, без `..`,
  absolute/drive, пустых сегментов, дублей; symlink/спецфайлы отвергаются.
- `docs/features/prompt-provenance.md`.

## Почему

- Хэш содержимого, а не mtime/размер, отличает настоящую локальную правку от touch.
- Отказ `update` при `modified` — главный DoD-инвариант: чужой пакет не затирается без
  явного `force`.
- Снимки полные, а не дельты: пакеты небольшие, а откат должен быть тривиально надёжным.
- Path-level diff достаточен для Z-06; трёхсторонний merge — Z-07.

## Ограничения

- Нет MCP-инструмента/UI; Z-07 будет потребителем.
- Diff только по путям, без 3-way/семантических конфликтов.
- `force` намеренно затирает локальные правки.
- Снимки — полные копии, не дельты.
- Файлы только UTF-8 строки; бинарные не поддерживаются.
- `rollback` не проверяет локальные изменения перед восстановлением.
- Запись не транзакционная: crash может оставить частичный `files/`.
- `requestedAt`/license не валидируются, только сохраняются.
