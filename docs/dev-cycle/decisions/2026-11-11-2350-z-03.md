# 2026-11-11 23:50 — Z-03: package browser и page плагина

- **Пункт:** Z-03 (high); зависит от Z-01, Z-02, UI-25, UI-10
- **Ветка / sha:** `feat/z-03-package-browser`, от `origin/master` `32a0af2`

## Вопрос

Как показать и редактировать skill-пакеты и включать/выключать компоненты плагина, если Z-01/Z-02
реализованы как библиотеки без MCP read/write API?

## Решение

- Добавлен MCP-слой `src/register/packages.ts` (5 инструментов):
  - `packages_list` — skill-пакеты из `DATA_DIR/skill-packages` и плагины из `DATA_DIR/plugins`;
  - `package_get` — дерево файлов и текстовое содержимое (файлы >256 KiB → `content:null`);
  - `package_create` — создание skill-пакета или плагина из относительных файлов (plugin.json
    генерируется с components);
  - `package_write_file` — правка одного skill-файла, путь через `resolveSkillPackagePath`;
  - `package_toggle_component` — `disabledComponents` в `plugin.json`, файлы не удаляются.
- UI `/packages`:
  - список пакетов/плагинов;
  - общий `TreeView` (все узлы раскрыты) для файлов;
  - редактор skill-файла с Save, read-only просмотр plugin-файлов;
  - для плагина — components (skills/commands/agents/hooks/mcp) с Enable/Disable и бейджем
    enabled/disabled/absent.
- Ссылка `Packages` в sidebar + page-meta; `docs/api-reference.md` перегенерирован (148 tools),
  строки добавлены в `docs/features/tools.md`.

## Почему

- Z-03 не может читать пакеты из браузера без серверного API; минимальный слой переиспользует
  готовые `SkillPackageStore`/`readPluginPackage`, не вводя новый формат.
- Компоненты плагина включаются через `disabledComponents` в существующем `plugin.json`: файлы
  остаются на диске, включение/выключение обратимо.
- `TreeView` из UI-25 исключает вторую реализацию дерева.

## Проверено

- `e2e/packages.spec.ts` — **1/1**: через MCP создаются skill и plugin; `/packages` открывает
  skill, читает `notes/readme.md`, сохраняет новый текст (проверено через `package_get`); открывает
  plugin, выключает `skills`, `package_get` подтверждает `disabledComponents`.
- `docs-tools-coverage` — все 5 инструментов задокументированы, header 148; build/tsc.
- API-reference: 148 (146 default + 2 dynamic).

## Ограничения

- Plugin-файлы в UI read-only; редактируются только skill-файлы.
- Нет ZIP-импорта/установки; `package_create` принимает только относительные файлы.
- Лимит редактора 256 KiB на файл; большие файлы показываются как read-only.
- `plugin_toggle` меняет `disabledComponents`, но не проверяет, что компонент действительно
  объявлен в manifest (UI не даёт включать absent-компоненты).
- `DATA_DIR/skill-packages` и `DATA_DIR/plugins` — фиксированные корни; настройки нет.

e2e; api-reference/tools.md возвращаются к 143. Z-01/Z-02 библиотеки не меняются.
