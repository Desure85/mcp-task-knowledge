# 2026-11-11 14:00 — имя задачи открывает полный редактор в новой вкладке

- **Тип:** прямой запрос владельца (не пункт BACKLOG), ветка `fix/task-open-editor-new-tab` от `master` `2b764d4`
- **Затронуто:** дашборд задач (доска и список), quick view, тесты

## Вопрос

Почему клик по имени задачи открывает встроенную панель редактирования прямо в дашборде, и как сделать
так, чтобы имя вело в полное редактирование в новой вкладке, а встроенное окно исчезло?

## Решение

- Удалена встроенная панель `editingTask` из `web-ui/app/tasks/page.tsx` вместе с `saveEdit` и её
  состоянием; дашборд больше не содержит формы редактирования существующей задачи.
- Имя задачи на доске и в списке вызывает `openTaskEditor(task)` →
  `window.open(`/tasks/${task.id}`, '_blank', 'noopener,noreferrer')`: полная страница задачи
  открывается в новой вкладке.
- Кнопка **Edit** в quick view делает то же самое (полный редактор в новой вкладке), затем диалог
  можно закрыть; read-only превью по клику на свободную область не изменилось.
- Создание задачи (`New task`) остаётся в дашборде: запрос касался окна редактирования, не создания.

## Почему

- Один канонический редактор — полная страница `/tasks/<id>`; дублировать его в дашборде значит
  поддерживать два набора полей/валидации и снова ловить расхождения.
- Новая вкладка сохраняет контекст доски (фильтры, скролл) и даёт прямую ссылку на задачу.
- `noopener,noreferrer` не даёт новой вкладке доступ к opener.

## Проверено

- `tasks-list.spec.ts` — **1/1**: пустая ячейка строки → превью, имя → новая вкладка `/tasks/<id>`.
