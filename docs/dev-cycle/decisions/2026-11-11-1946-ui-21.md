# 2026-11-11 19:46 — UI-21: Access «подключить агента»

- **Пункт:** UI-21 (medium), зависит от UI-10, UI-12, DX-29
- **Ветка / sha:** `feat/ui-21-connect-agent`, от `origin/master` `bfb89dc`

## Вопрос

`/access` умел создавать setup-link, но сценарий «подключить агента» не был пошаговым:
ссылка показывалась без готового конфига, пользователь вручную собирал URL/токен, не было
проверки подключения и человеческих подписей вроде «Link lifetime minutes».

## Решение

- **5 шагов** на странице (нумерованные заголовки/ol):
  1. создать одноразовую ссылку;
  2. открыть конфиг (ссылка redeeming one-time);
  3. скопировать сниппет;
  4. проверить подключение;
  5. передать конфиг агенту.
- **Server-side redeem**: `POST /api/setup/redeem` принимает ссылку, проверяет, что она ведёт
  на настроенный MCP-origin (`MCP_API_URL`, localhost/127.0.0.1 нормализуются), делает GET
  `/.well-known/mcp-setup/<otp>`, возвращает markdown. Браузер не зависит от CORS MCP-сервера,
  SSRF ограничен origin + путём.
- **Парсинг** `web-ui/lib/setup-flow.ts`: fenced JSON → `mcpServers`, URL, Bearer token,
  `configText`; ошибки «нет JSON/нет токена».
- **Проверка**: `POST /api/setup/check` отправляет настоящий MCP `initialize` с токеном на
  `${MCP_API_URL}/mcp`, затем DELETE сессии; 200 + `result` → «Подключение работает», HTTP/RPC
  ошибка → alert «Не удалось проверить подключение…».
- **UI**: после создания ссылки кнопка «2. Получить конфиг»; `<pre>` со сниппетом, Copy
  (clipboard), кнопка проверки, `role=status`/`role=alert`; использованная ссылка помечается,
  Copy link скрывается. Форма: «Ссылка действует (минут)» + hint про одноразовость.
- URL setup-link приходит с `localhost`, а `MCP_API_URL` — `127.0.0.1`: origin-сравнение
  нормализует эти хосты (без этого E2E падал «Ссылка не принадлежит этому серверу»).

## Почему

- Готовый сниппет с токеном — то, что реально нужно агенту; setup-link остаётся одноразовым
  носителем. UI сам redeeming'ит ссылку, поэтому токен не надо вставлять вручную.
- Server-side redeem/check убирает CORS и не заставляет браузер ходить на MCP-origin напрямую.
- Проверка — настоящий `initialize`, а не оптимистичный ping: ловит неверный/просроченный токен.
- 5 шагов и русские подписи — по DoD, вместо технического «Link lifetime».

## Ограничения

- Для работы redeem/check нужен `MCP_API_URL`, совпадающий с origin setup-link; при внешнем
  public URL за reverse-proxy origin должен быть тем же (или прокси тем же).
- Ссылка расходуется при получении конфига: после этого её нельзя передать как ссылку — только
  готовый сниппет.
- Проверка создаёт MCP-сессию; DELETE делается best-effort, при сбое сессия живёт до idle TTL.
- Clipboard зависит от разрешения браузера; fallback-копирование не реализовано.
- `role=status`/`role=alert` не автоматически фокусируются; скринридер объявит live-region.
- Сценарий проверен админом (создание setup-link требует admin); создание отдельного
  пользователя-агента в 5 шагов не входит.
- Не покрыто: просроченная ссылка, повторный redeem, неверный Bearer, реальный внешний
  reverse-proxy.

## Откат

карточку `/access`; серверный wire-формат не менялся.
