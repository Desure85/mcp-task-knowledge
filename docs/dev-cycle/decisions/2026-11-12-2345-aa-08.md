# 2026-11-12 23:45 — AA-08: профили инструментов и серверная инструкция

- **Пункт:** AA-08 (high, design)
- **Ветка:** `docs/aa-08-tool-profiles`, от `origin/master` `2a21b33`

## Вопрос

Как ограничить видимую поверхность ≤60 инструментов и что писать в `instructions`, чтобы агент понимал
порядок работы, а не выбирал из 206 tools?

## Решение

Принят ADR `docs/adr/ADR-2026-11-12-tool-profiles.md`:

- профили `core` (≤28), `agent` (≤60), `full` (206); `MCP_TOOL_PROFILE`, default `full` до следующего major;
- профиль — фильтр видимости + `TOOL_NOT_FOUND` для скрытого вызова, не security boundary;
- `instructions` ≤4 КиБ, 9 пунктов: проект → задачи → знания → память → промпты/скиллы → ошибки;
- режимы `auto|off|custom`, неизвестный профиль → `full` + WARN.

## Почему

- Явные allowlist-имена ловят удаление/переименование tools тестом.
- Инструкция короткая и не дублирует JSON Schema.
- Default `full` сохраняет совместимость; переход на `agent` — в следующем major.

## Проверено

- ADR фиксирует состав, лимиты, конфиг, реализацию AA-08b и тесты.
- `backlog:check` — **399/0/21/1**.
- Код не менялся: design gate; реализация — AA-08b.

## Ограничения

- Профиль не является границей безопасности.
- Текст инструкции английский; локализация позже.
- Allowlist ещё не создан — это следующий инкремент.

Удалить ADR и вернуть AA-08 в blocked.
