## Вопрос

Агент не может посмотреть, почему вызов упал: pino пишет только в stderr, а `journalctl` — инструмент
оператора. Нужен read-only способ прочитать хвост лога, при этом (а) не записывая секреты в
открытом виде, (б) не отдавая клиенту мегабайты, (в) не делая файловую запись обязательной для всех.

## Решение

1. **Файловый синк — опциональный (`LOG_FILE`).** По умолчанию сервер по-прежнему пишет только в
   stderr: строки лога содержат текст задач и документов, и превращать это в файл на диске без
   ведома владельца — решение о приватности, а не удобство отладки. При `LOG_FILE` запись идёт в
   **оба** места; относительный путь резолвится от `DATA_DIR`.
2. **Ротация: 10 МБ на файл, 3 файла (`.1`, `.2`), настраивается** `LOG_ROTATE_BYTES`/
   `LOG_ROTATE_KEEP`. Запись — синхронный append: между строками нет открытого дескриптора, поэтому
   переименование на Windows надёжно (открытый write-stream нельзя переименовать — первая версия
   на этом и спотыкалась, поймано тестом ротации). Активный файл всегда существует, даже сразу после
   ротации: `logs_tail` на него резолвится.
3. **Инструмент `logs_tail` — только чтение.** Открывает файл в режиме `r`, читает последние
   256 КБ, отдаёт не больше `lines` (по умолчанию 200) и `maxBytes` (по умолчанию 64 КБ), с фильтром
   по уровню. Не-JSON строки (стек-трейсы) не отфильтровываются: они несут контекст.
4. **Маскирование до отдачи.** JWT, `Bearer`, `ghp_`/`github_pat_`, `sk-…`, поля
   `password`/`token`/`secret`/`apiKey`. Специфичный маркер не затирается общим: `[REDACTED_JWT]`
   остаётся собой, а не превращается в `[REDACTED]`.
5. **Без `LOG_FILE` — внятный отказ**, а не пустой хвост: `LOG_FILE_DISABLED` с подсказкой, как
   включить.
6. **Счёт инструментов сдвинулся:** 129 по умолчанию, 131 с каталогом, 133 с записью каталога.
   Обновлены `docs/features/tools.md` (строка + заголовки), `README.md`, контракт в `AGENTS.md`,
   комментарий в `tests/docs-tools-coverage.test.ts`; `docs/api-reference.md` перегенерирован
   (131).

## Почему

- Опциональность сохраняет текущее поведение и приватность; те, кому нужен хвост, включают его
  одной переменной.
- Синхронный append выбран ради корректности ротации на Windows; строка лога — микросекунды.
- Маскирование в самом читателе (а не в формате записи) означает, что даже уже записанные строки
  безопасно отдаются клиенту.
