# 2026-11-13 21:30 — TK-06: worklog edit/delete + `spentMinutes`

- **Пункт:** TK-06 (low) — идея, записанная в BACKLOG по ходу TK-05

## Вопрос

После TK-05 work item можно было только добавить: ошибку в длительности или описании
нельзя исправить, а `tasks_get` не показывал сумму затраченного времени. Это реальный
пробел функциональности, а не косметика.

## Решение

- `tasks_worklog_update({ id, workItemId, durationMin?, startedAt?, description?, expectedVersion? })`
  меняет только выбранный item, сохраняя `id`/`createdAt`; пустой патч → `WORK_ITEM_EMPTY`.
- `tasks_worklog_delete({ id, workItemId, expectedVersion? })` удаляет один item; отсутствующий →
  `WORK_ITEM_NOT_FOUND`, остальные не трогаются.
- `tasks_get` возвращает вычисленный `spentMinutes` (сумма `durationMin`), не храня его вторым
  полем; `fields`/`compact` применяются как раньше.
- Оба метода идут через `store.update` и поддерживают `expectedVersion` (CAS).

## Почему

- Сумма — производная от массива; дублировать её в storage значит получить расхождение.
- Точечные update/delete по `workItemId` не требуют перечитывать/перезаписывать чужие items.
- Это универсальная функция, не привязанная к платформе; идея записана в BACKLOG как TK-06.

## Ограничения

- Нет UI и отчётов по времени; `spentMinutes` только в `tasks_get` (list его не суммирует).
- Нет ограничения «кто может править чужой work item»: авторизация — на уровне tool-gate.
- `expectedVersion` относится к версии задачи, не к версии отдельного item.
- Работает с любым storage-профилем, но SQLite/PG e2e для work items не запускался.
