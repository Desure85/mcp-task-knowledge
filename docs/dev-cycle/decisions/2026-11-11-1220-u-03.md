# 2026-11-11 12:20 — U-03: evidence при закрытии задачи

- **Пункт:** U-03 (medium), зависимостей нет
- **Ветка / sha:** `feat/u-03-task-evidence`, от `origin/master` `822f6c6`

## Вопрос

Как не давать закрывать задачу «голословно» и сохранять проверяемое доказательство (commit/CI/output),
не ломая существующих клиентов `tasks_close`?

## Решение

- `Task.evidence?: TaskEvidence` (аддитивно в wire): `commitSha?`, `ciUrl?`, `checkOutput?`, `note?`,
  серверные `at`, `bySessionId?`, `byUserId?`.
- `tasks_close` принимает необязательный `evidence`:
  - `commitSha` — `^[0-9a-f]{7,40}$`;
  - `ciUrl` — только `https://`;
  - `checkOutput`/`note` — ≤ 4096 символов;
  - нужен хотя бы один из `commitSha`/`ciUrl`/`checkOutput`;
  - ошибки → `{ok:false, code:'EVIDENCE_INVALID', hint:'pass commitSha, ciUrl or checkOutput'}`.
- Проектная настройка `requireEvidence` в `.project.json` (через `project_update`):
  - при `true` закрытие без evidence → `{ok:false, code:'EVIDENCE_REQUIRED', hint:...}`;
  - `false`/отсутствие — прежнее поведение.
- Evidence пишется в задачу **до** `closeWithCascade`; `tasks_get` возвращает её без изменений;
  cascade применяет evidence к корневой задаче, потомки закрываются как раньше.

## Почему

- Расширение `tasks_close` необязательным полем не ломает старых клиентов; `requireEvidence` —
  opt-in на проект, а не глобальный дефолт.
- Evidence хранится в самой задаче, поэтому доступна в `tasks_get` без нового инструмента; история
  (MU-03) — отдельный, уже заблокированный пункт.
- Валидация в handler, а не только в zod-схеме: тесты и `tools_run` с loose-схемой получают тот же
  стабильный `EVIDENCE_INVALID`.

## Проверено

- `tests/task-evidence.test.ts` — **3/3**:
  - `requireEvidence=true` без evidence → `EVIDENCE_REQUIRED`, задача не закрыта;
  - невалидный sha, `http://` ciUrl, `checkOutput` 4097 → `EVIDENCE_INVALID`;
  - валидный evidence закрывает задачу и виден в `tasks_get` (`commitSha`, `note`, `at`);
  - `requireEvidence=false` закрывает без evidence.
- build/tsc.
- **Мутация:** удаление проверки `requireEvidence` в `tasks_close` должно красить первый тест
  (revert-check выполнен, RED).

## Ограничения

- `checkOutput` ограничен 4096 **символов**, не байт; многобайтный текст может быть чуть больше 4 KiB.
- Evidence применяется только к корневой задаче cascade; закрытые потомки без evidence.
- `byUserId` в схеме поля есть, но handler его не заполняет (нет гарантированного пользователя в
  локальном stdio); `bySessionId` берётся из request scope, если он есть.
- История изменений evidence (кто/когда менял) не пишется — это MU-03.

## Откат

Revert ветки: убрать `evidence` из `Task` и `tasks_close`, `requireEvidence` из `ProjectMetadata`/
`project_update`; тест удаляется. Старые файлы задач с `evidence` останутся читаемыми (лишнее поле).
